# Terminal-Bench 2.1로 magi 벤치마킹하기

무엇을 재는지, 직접 돌리는 법, 그리고 나온 숫자.

[Terminal-Bench](https://www.tbench.ai)는 도커 컨테이너 안의 진짜 터미널과 과제를 에이전트에게 주고
해냈는지를 채점합니다. 에이전트 전체를 재는 벤치입니다 — 루프, 도구, 회복, 모델이 함께 시험대에 오르고,
한 번의 실행은 그중 무엇이 결과를 만들었는지 말해주지 않습니다. 아래 표가 판정 옆에 비용과 호출 수를
같이 싣는 이유가 그것입니다. 둘 다 통과했더라도 한쪽이 다섯 배를 썼다면 같은 결과가 아닙니다.

## 무엇이 시험대에 오르나

- **루프**: magi의 플래너, 도구, 카운슬, 회복. 고정된 바이너리에서.
- **백엔드**: `MAGI_BASE_URL`이 서빙하는 것. 여기 기록된 실행은 magi의 `claudecode` 심을 통해 Claude
  Code CLI를 백엔드로 씁니다. 달러 컬럼이 있는 이유가 그것입니다 — 평범한 OpenAI 호환 엔드포인트는
  비용을 보고하지 않고, 그 칸은 `?`로 남습니다.
- **데이터셋**: `terminal-bench/terminal-bench-2-1`, 89개 과제.

## 준비물

- **Docker**. 요청할 병렬도만큼의 여유와 함께 돌아가고 있어야 합니다. Terminal-Bench는 trial마다
  컨테이너를 띄우고 그것들이 VM이 가진 것을 나눠 씁니다. 무엇을 가졌는지는 `docker info`가 말해줍니다.
- **[Harbor](https://www.tbench.ai)**, Terminal-Bench 러너(`harbor run`).
- **컨테이너용 magi 바이너리** — `magi-arm64` 또는 `magi-amd64`를 한 디렉토리에. 어댑터가 컨테이너마다
  올려서 거기에 설치합니다. 안에서 빌드하는 것은 없습니다.
- **이 기계의 magi**. `SHIM=`을 쓴다면 필요합니다 — 풀이란 백엔드 심을 서빙하는 magi 데몬들입니다.
  `SHIM_BIN`이 그것을 가리키고, 기본값은 `PATH`의 `magi`입니다.
- **그 심이 감싸는 CLI가 이 기계에 설치되고 로그인되어 있어야 합니다.** `SHIM=claudecode`는 모델 턴마다
  `claude --print`를 한 번씩 실행하므로 호스트에 동작하는 `claude`가 필요합니다. `SHIM=codex`라면
  `codex`가 필요합니다. CLI는 **호스트에서** 돌지 과제 컨테이너 안에서 돌지 않습니다 — 컨테이너는 심에게
  HTTP만 말합니다 — 그래서 이미지에 무언가를 더 넣을 필요가 없습니다.

마지막 항목은 89개짜리 실행을 시작하기 전에 확인하십시오. 끝난 뒤가 아니라:

```sh
claude --version && claude --print 'reply with: ok' --model sonnet
```

## 돌리는 법

```sh
# 컨테이너가 실행할 magi 바이너리 (magi-arm64 / magi-amd64).
export BINARY=/tmp/magi-serve

# 89개 전부. 인자는 동시에 몇 개를 돌릴지입니다.
SHIM=claudecode bench/harbor/run.sh 1
```

`SHIM=<플러그인>`은 **trial마다 백엔드를 하나씩** 띄웁니다 — 그 플러그인의 loopback 심을 서빙하는 magi
데몬을, 각자 자기 디렉토리에서. 컨테이너를 거기로 향하게 하고, 지출 원장을 샘플링하고, 실행이 끝나면
전부 정리합니다. 병렬도가 얼마든 과제별 비용이 정확하게 남는 이유이고, 풀 크기를 설정이 아니라 인자에서
가져오는 이유입니다:

```sh
SHIM=claudecode bench/harbor/run.sh 4      # trial 4개, 백엔드 4개
```

OpenAI 호환 엔드포인트라면 무엇이든 됩니다. 대신 비용 컬럼이 없습니다 — 평범한 엔드포인트는 지출을
보고하지 않으니까요:

```sh
BASE_URL=http://host.docker.internal:11434/v1 MODEL=qwen3-coder:30b bench/harbor/run.sh 1
```

실행이 끝나면 표를 찍습니다. 언제든 다시 물어볼 수 있습니다:

```sh
python3 bench/harbor/report.py --jobs-glob 'jobs/*tb21*'
python3 bench/harbor/report.py --jobs-glob 'jobs/*tb21*' --markdown   # 문서에 붙일 때
```

## 표 읽는 법

| 컬럼 | 무엇인가 |
|---|---|
| `min` | trial의 벽시계. 컨테이너 셋업과 검증 포함 |
| `turns` | magi가 답한 사용자 프롬프트 수 — 과제 하나는 보통 **하나**입니다 |
| `calls` | 백엔드가 실제로 서빙한 LLM 요청 수. 규모를 따라 늘어나는 건 이 숫자입니다 |
| `in` / `cached` / `out` | magi 자신의 토큰 집계. trial의 `turn.finished`에서 |
| `usd` | 백엔드의 원장을 trial 시간창으로 차분한 값. `~`는 나눠 가진 값이라는 뜻 |
| `council` | 종료 게이트의 집계, `done 3-0`. `— none`은 완료 선언이 없었다는 뜻 |

`turns`와 `calls`는 자릿수가 다르고 둘 다 사실입니다 — 과제 하나, 프롬프트 하나, 그 안에서 모델 호출
마흔 번. 에이전트 타임아웃으로 잘린 trial은 `turn.finished`에 도달하지 못하므로 입력이 `0`이 아니라
`?`로 나옵니다. 0은 주장이니까요.

## 발등을 찍을 하나

**병렬은 점수를 움직일 수 있고, 아래쪽으로만 움직입니다.** trial들이 도커 VM의 CPU와 메모리를 나눠 씁니다.
7 CPU · 8GB VM에서 네 개를 돌리면 각자 1.75코어와 2GB를 받고, 컴파일하거나 학습시키는 과제는 에이전트와
아무 상관없는 이유로 타임아웃 납니다. 왜곡은 한 방향입니다 — 굶주림은 통과를 타임아웃으로 바꿀 수 있지
그 반대는 못 합니다. 올리기 전에 `docker info`를 확인하고, 점수는 같은 여유에서 돌린 점수하고만
비교하십시오.

반면 비용은 병렬을 견딥니다. 운이 아닙니다. 귀속은 백엔드 원장을 trial 시간창으로 차분해서 구하는데,
어느 호출이 어느 trial 것인지는 선 위에 적혀 있지 않습니다 — 과제 이름은 OpenAI 호환 엔드포인트를 넘지
않습니다. 그래서 `SHIM=`이 풀 크기를 병렬도 인자에서 가져오고, trial마다 백엔드를 하나씩 점유합니다.
원장 하나에 trial 하나, 시간창 하나에 원장 하나 — 병렬도가 얼마든 정확합니다. 나눠 갖기는 직접 준비한
백엔드 하나에 trial 여럿을 붙일 때만 나타나고, 그때는 `report.py`가 해당 행에 `~`를 붙입니다. 나눠 가진
값을 측정값인 척 넘기지 않습니다.

## 격리, 그리고 치팅이 없었음을 확인한 방법

과제가 GitHub에 공개된 벤치마크는 두 가지로 틀릴 수 있습니다. trial이 앞선 trial에게서 배우거나,
에이전트가 답을 찾아보거나. 어느 쪽도 바란다고 막히지 않습니다.

**trial 사이에 넘어가는 것이 없습니다.** 과제마다 자기 이미지에서 컨테이너를 새로 띄웁니다. 호스트에서
안으로 들어가는 것은 정확히 하나 — magi 바이너리이고, 업로드 후 `install`합니다. 네트워크를 쓰지 않으므로
컨테이너 안에서 curl/wget을 망가뜨려도 설치를 실패시킬 수 없습니다. 마운트된 호스트 디렉토리는 없습니다.
`MAGI_DATA_DIR`는 컨테이너 안을 가리키고, 어댑터는 경험·메모리·스킬 디렉토리를 **하나도 설정하지
않습니다.** magi의 스토어는 그 컨테이너와 함께 살고 죽습니다. 백엔드 심이 재개 앵커를 들고 있지만, 재개는
렌더된 히스토리가 이미 보낸 것의 **엄격한 접두 확장**이어야 성립합니다 — 서로 다른 과제는 결코 일치하지
않으므로 세션이 상속되는 일이 없습니다.

**컨테이너에는 네트워크가 있습니다.** 많은 과제가 그것을 필요로 합니다 — 패키지 설치, 소스 다운로드,
데이터셋 내려받기. 그러므로 정답 조회는 원리적으로 가능하고, 없다고 가정할 게 아니라 확인해야 합니다.
magi가 하는 모든 도구 호출은 웹 호출까지 이벤트 로그에 남으므로 검사는 기계적입니다:

```sh
set -- jobs/*tb21*/*__*/agent/magi-stdout.txt   # 감사할 실행으로 범위를 좁히십시오
grep -ohE '⚙ (websearch|webfetch)' "$@" | sort | uniq -c
grep -ohE '⚙ (websearch|webfetch) \{[^}]{0,200}' "$@"        # 하나하나 다 읽어보십시오
grep -ohE '⚙ bash \{"command": "[^"]{0,160}' "$@" | grep -iE 'curl|wget|git clone'
grep -oih 'terminal-bench' "$@" | wc -l
```

범위가 중요합니다. 범위를 안 좁힌 glob은 이 저장소가 수집한 모든 job을 훑고, 다른 실행의 호출을 세는
감사는 이 실행의 감사가 아닙니다.

아래 실행에 대한 감사는 아직 쓰지 않았습니다. 도중이 아니라 마지막 과제 뒤에 할 일이기 때문입니다 —
20개를 본 검사는 뒤따르는 69개에 대해 아무 말도 하지 않습니다. 실행이 끝나면 이 문단에 위 명령들이
돌려주는 숫자와, 하나하나 인용해 읽은 웹 호출과, 위임된 서브에이전트의 세션 스토어에 대한 같은 진술이
들어갑니다. 그 스토어는 부모 전사에 나오지 않으므로, 부모만 본 검사는 반쪽 검사입니다.

**하나는 의도적으로 상속되며, 그것은 과제별이 아닙니다.** Claude Code CLI가 운영자의
`~/.claude/settings.json`을 읽고, 아래 결과의 추론 에포트 HIGH가 거기서 옵니다 — 심은 `--effort`를 보내지
않고, 중립 작업 디렉토리는 *작업공간*을 격리하지 사용자 레벨 설정을 격리하지 않습니다. 모든 trial에
동일하게 적용되므로 과제 간 유출이 아니라 런의 성질이고, 결과와 함께 명시합니다. 사용자 레벨 스킬도 메모리도
`CLAUDE.md`도 모델에 도달하지 않습니다. 주장이 아니라 잴 수 있습니다 — 돌고 있는 백엔드에 최소 턴을
넣으면 입력이 **327 토큰**으로 청구되고, 그중 76 토큰쯤이 magi 자신의 래퍼입니다(배너,
`The conversation so far:`, 역할 표시). 아무것도 억제하지 않으면 CLI 스캐폴드만 37,659 토큰인데, 그런
크기의 무엇도 327 안에 없습니다.

같은 프로브가 나머지 절반에도 답합니다. 다른 과제의 콜을 이미 1,500번 넘게 서빙했고 살아 있는 세션을
들고 있던 심에 넣었을 때도 똑같이 327, `cached_tokens 0`이었습니다 — 바닥은 심의 이력을 따라 자라지
않고, 재개 앵커의 접두 검사가 그 심이 물고 있던 어떤 대화에도 이 프로브를 붙이기를 거부했습니다.
숫자를 믿지 말고 자기 백엔드에 직접 확인하십시오:

```sh
curl -s localhost:58411/v1/chat/completions -H 'Content-Type: application/json' \
  -d '{"model":"sonnet","stream":true,"messages":[{"role":"user","content":""}]}' \
  | grep usage
```

이 프로브는 **백엔드 경로에 대해서만** 말합니다 — magi를 통째로 건너뛰기 때문입니다. magi가 자기 메모리를
싣는지는 위 문단이 답합니다: 어댑터가 실을 스토어 자체를 설정하지 않습니다.

## 결과

magi + Claude Code CLI가 서빙하는 `claude-sonnet-5`, 에포트 HIGH(운영자의 `~/.claude/settings.json`에서
상속된 것이고 플래그로 고정한 게 아닙니다), `MAGI_COLLAPSE_REPEATS=0`.

**실행이 아직 진행 중이라, 이 절은 부분적으로 채우는 대신 일부러 비워둡니다.** 데이터셋 일부에 대한
패스율은 진짜 숫자의 작은 판본이 아닙니다. 다른 숫자이고, 그걸 실으면 감당할 수 없는 비교를 부릅니다.
89개 전부에 결과가 생기면 표가 여기 들어옵니다. 만드는 명령은:

```sh
python3 bench/harbor/report.py --jobs-glob 'jobs/*tb21*' --markdown
```
