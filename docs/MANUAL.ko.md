# magi 사용자 매뉴얼

[English](MANUAL.md) · [한국어](MANUAL.ko.md)

확장형 터미널 AI 코딩 에이전트 클라이언트. 공급자 무관(OpenAI 호환), 멀티에이전트,
Lua 플러그인, MCP, 공유 메모리를 지원한다.

---

## 1. 설치 & 요구사항

- **LLM 백엔드**: OpenAI 호환 엔드포인트([Ollama] 권장). 기본 모델은 **`gpt-oss:120b-cloud`** —
  Ollama **무료 클라우드 티어**라 GPU 없이 한 번만 로그인하면 된다.
  ```sh
  ollama signin                 # 무료 티어; 기본 gpt-oss:120b-cloud는 클라우드에서 실행
  # 완전 로컬로 돌리려면:
  ollama pull qwen3-coder:30b   # 가장 강한 로컬 코더 → ./magi --model qwen3-coder:30b
  ```
- **빌드**: `make build` 또는 `CGO_ENABLED=0 go build -o magi ./cmd/magi` (순수 Go 단일 바이너리)
- **프리빌트**: `curl -fsSL .../scripts/install.sh | bash` 또는 `brew install sayaya1090/tap/magi`

## 2. 실행

### 대화형 TUI
```sh
./magi                 # 다크/라이트 자동 감지
./magi --theme light   # 테마 강제(auto|dark|light)
```

### 헤드리스 (스크립트/CI)
```sh
./magi -p "list the go files and summarize"
./magi -p "create hello.txt with: hi" --output json   # JSONL 이벤트
echo "explain main.go" | ./magi -p -                   # stdin
```

헤드리스 출력 계약 (안정 — 스크립트·CI·벤치 어댑터가 의존):

- **종료코드**: `0` = 턴 정상 종료 · `1` = 에이전트 수준 에러로 종료(`loop_guard`,
  `stall_guard`, `max_steps`, 프로바이더 실패) · `2` = magi 자체가 프롬프트를 실행하지
  못함(셋업/제출 실패).
- **stdout** = 트랜스크립트: 모델 텍스트(최종 답), 툴 호출/결과, council·컴팩션 노트.
  `--output json`이면 fact 이벤트를 줄 단위 JSONL로 출력.
- **stderr** = 에러 전용. 에이전트 수준 에러는 grep 가능한 `error[<code>]: <message>` 형식.

**헤드리스 권한 거부는 가짜 사용자 결정이 아니라 정직하다.** 헤드리스에서 `--permission auto`/`ask`는 프롬프트에 답할 사람이 없으므로 `bash`/`webfetch`가 사용 불가다. 에이전트가 받는 툴 결과는 이를 **범주적으로** 말한다 — "이번 런에선 사용 불가(이 모드는 프롬프트 없이 승인 못 함), 재시도 말 것; 그 없이 진행하거나 왜 못 했는지 보고하라" — 인터랙티브 거부가 보낼 오해 소지 있는 `denied by user` 대신. 이 구분이 중요하다: `denied by user`는 "사람이 *이 호출*에 아니라고 했다"로 읽혀 에이전트가 변형을 재시도하며 헛돈다; 범주적 메시지는 그 능력이 런 전체에서 그냥 꺼졌다고 알려 한 번에 적응하게 한다. 그 툴이 필요하면 `--permission allow`(또는 인터랙티브 실행)를 쓰라. 기동 시 stderr에 이 불일치를 알리는 한 줄도 남는다.

### 켜둔 채로 두고, 다시 돌아오기

턴 하나가 20분 걸릴 수 있다. 예전엔 터미널을 닫으면 그걸로 끝이었다.

```sh
./magi --daemon        # UI 없이 엔진만 실행 — 아무도 안 보고 있어도 계속 일한다
./magi --attach        # 이 디렉터리에서 돌고 있는 데몬에 터미널 UI를 붙인다
./magi --agents        # 이 머신의 모든 magi 데몬과 각자 무엇을 하고 있는지
```

데몬이 있어야 컴패니언이 **주소를 갖는다**. 상주하는 것만이 일을 받고, 일정을 지키고, 다른 머신에
보인다. 나머지 표면 — `--join-cluster`·`--members`·`--relay`·`--mcp` — 는 §13.

- **워크스페이스당 데몬 하나.** 소켓 이름은 워크스페이스의 실제 경로에서 나온다
  (`<config>/daemon-<dir>-<hash>.sock`, 심링크 해소). 그래서 `--attach`는 그 디렉터리의 데몬만
  찾는다. 한 워크스페이스를 데몬 둘이 잡을 수는 없다 — 두 번째가 락에서 지고, 누가 갖고 있는지
  말해준다.
- **떼는 것은 멈추는 것이 아니다.** 붙어 있던 UI를 닫아도 실행은 계속되고, 그 백그라운드 명령과
  language server도 살아 있다 — 그건 시작한 프로세스의 몫이다. 멈추는 건 데몬 자신의 Ctrl-C다:
  취소하고, 실행이 풀리길 기다리고, 소켓을 내려놓는다.
- **뷰어 여럿, 실행 하나.** `--attach`를 여러 개 붙여 같은 데몬을 볼 수 있다.
- `--agents`는 데몬당 한 줄을 찍는다: 상태, 무엇을 하는 중인지, 얼마나 놀았는지, 무언가 답을
  기다리는 중인지. 소켓들을 짧은 데드라인으로 병렬로 두드리므로, 먹통 데몬 하나가 목록 전체를
  잡아먹지 않는다.

### 환경 점검
```sh
./magi --doctor
```
`--doctor`는 magi가 필요로 하는 모든 것을 한 번에 진단하고 종료한다 — 새 머신이 이상하면 먼저 돌려라. 각 항목에 `ok`/`warn`/`fail` 한 줄을 출력한다:

- **LLM 엔드포인트** — `--base-url` 도달성과 설정된 `--model`이 거기 존재하는지(Ollama의 경우 클라우드 모델 로그인 여부).
- **선택 외부 도구** — `gopls`, `rg`(ripgrep): 있으면 편집 후 진단·검색이 날카로워지고, 없어도 우아하게 degrade(warn일 뿐 fail 아님).
- **샌드박스 백엔드** — 사용 가능한 명령 격리(macOS `sandbox-exec`, Linux `bwrap` 등)와 bash가 격리 실행되는지.
- **Config** — **council 멤버 `provider`**가 정의된 `[llm.profiles.*]`를 가리키는지; 미정의면 warn(기본 백엔드로 폴백).
- **플러그인** — 각 플러그인(내장 + 플러그인 디렉터리별)이 실제 로드되는지와 로드된 이름 목록; 로드 실패한 디렉터리는 사유와 함께 warn. 로드된 플러그인이 플러그인 API로 등록한 자체 doctor 프로브도 여기서 실행·보고된다.

종료코드는 **하드 실패**(예: LLM 엔드포인트 도달 불가) 때만 0이 아니며, 경고는 advisory로 종료코드에 영향 없음.

### 버전 / 자동 업데이트
```sh
./magi --version
./magi --update            # 바이너리 + 관리형 플러그인 모두 업데이트 후 종료
./magi --update-core       # 바이너리만 업데이트(체크섬 검증)
./magi --update-plugins    # 관리형(git) 플러그인만 업데이트
./magi --plugin-install <git-url> [--plugin-pin <ref>]   # 플러그인을 사용자 플러그인 디렉터리로 clone
```

**관리형 플러그인** = git 체크아웃인 플러그인(`--plugin-install`로 설치했거나 직접 clone한 것).
`--update-plugins`는 각 플러그인에 fast-forward pull을 실행하며, 로컬 커밋/변경이 있어 ff 불가하거나
git remote가 없는 플러그인은 보고 후 **건너뜀 — 강제로 덮지 않음**. 직접 배치한 비-git 플러그인은
손대지 않음. 플러그인은 핫리로드되므로 `--update-plugins` 후 재시작 불필요.

**인터랙티브 기동 시 체크.** 터미널에서 TUI로 띄우면 최대 24시간에 한 번 새 릴리스를 확인함.
**패치** 릴리스는 한 줄 배너만 띄우고(`… magi --update 실행`), **마이너/메이저** 릴리스는 필수로 간주해
짧은 취소 가능 대기 후 자동 설치하고 재시작을 안내함. 이 체크는 **인터랙티브 TTY에서만** 발화 —
`-p`·파이프·CI·벤치마크에선 절대 안 됨 — 이라 비인터랙티브 실행은 네트워크 호출도, 갑작스러운 설치도
없음. `--no-update-check`(또는 `MAGI_NO_UPDATE_CHECK=1`)로 끔.

권한 모드: `ask`=매번 확인 · `auto`=**편집은 자동 승인, 명령(bash)/네트워크만 확인** · `allow`=전부 자동 · `deny`=차단. TUI에서 `Shift+Tab`(또는 `/permission`)으로 순환.

**데몬에서는 모드가 프롬프트의 대기 시간까지 정한다.** `--permission ask`나 `auto`로 띄운 상주
컴패니언은 붙는 UI에 프롬프트를 보내고(§13), 아무도 안 붙었을 때가 갈린다:

- **`ask`는 기다린다.** 무기한. 묻겠다고 골라놓고 타이머가 대신 답하는 것이야말로 이 모드가 막으려는
  것이라, 컴패니언은 누가 답할 때까지 플릿의 `waiting` 상태에 앉아 있는다 — 콘솔에 배지가 붙고 폰으로
  푸시된다.
- **`auto`는 3분 뒤 포기**하고 정책으로 해소하며, 그 결정이 누군가의 것이 아니라 기본값이었다는 사실을
  트랜스크립트에 남긴다. 여기서 남는 프롬프트는 잔여물이다 — 편집은 이미 승인됐고 남은 건 명령과
  네트워크라, "나 없이 계속해"가 방어 가능하고 몇 시간 멈춰 있는 건 아니다.
- **`allow`**는 스스로는 묻지 않는다. 데몬의 기본값인 이유가 그것이다: 아무도 안 보는 동안 도는 일 —
  일정(§14) 포함 — 이 거기 없는 사람 때문에 멈추면 안 된다. 다만 가드레일이 그 위로 프롬프트를 강제할
  수는 있고(위험한 명령, 외부 통신), 그건 `auto`와 같이 3분으로 묶인다 — 그 프롬프트는 모드가 아니라
  정책 때문에 존재하기 때문이다.

터미널은 어느 모드에서든 기다린다: 사람이 앞에 있고, 그가 읽는 동안 만료되는 프롬프트는 그의 손에서
빼앗은 결정이다.

가드레일 posture(`--profile`/`MAGI_PROFILE`)는 두 축(**권한 승인** × **OS 샌드박스**)을 한 번에 잡는 프리셋이다: `safe`=`ask`+`read-only`, `standard`(권장)=`auto`+`workspace-write`(편집 자동승인·명령/네트워크 확인·쓰기는 워크스페이스로 제한), `yolo`=`allow`+`full`. `--permission`/`sandbox`를 따로 주면 프리셋보다 우선한다. profile 미지정 시 샌드박스는 opt-in(무제한)으로 남고 권한만 기본 적용된다 — 기존 사용자의 네트워크/트리 밖 쓰기를 조용히 끊지 않기 위함. 샌드박스 축(`sandbox = "read-only"|"workspace-write"|"full"`)은 `config.toml`에서 직접 지정할 수도 있다.

**세밀 규칙(`config.toml`).** 모드 외에 세 리스트 키로 정책을 좁힌다: `allow`/`deny`는 툴 호출에 대한 글롭 규칙(예: `Bash(git push:*)`는 그 명령 자동승인, `Read(**/.env)`는 시크릿 읽기 차단)으로 — `p` 권한 선택(§4)이 영속하는 것이 바로 이것 — `deny`가 `allow`보다 우선한다. `allow_domains`는 **WebFetch/bash 네트워크 egress를 호스트 허용목록으로 제한**한다(예: `["api.github.com"]`); 비우면 호스트 제한 없음. 셋 다 전역·프로젝트 config에서 덮어쓰지 않고 **누적(append)**되며, 플러그인의 `set_config_key`가 절대 건드릴 수 없는 고정 deny-list에 있다(EXTENDING §플러그인).

> **카운슬(MAGI: Melchior·Balthasar·Casper · 기본 on)**: 에이전트가 `council` 툴로 부르는 3인이다. `question`은 확신이 안 서는 것에 대한 읽기를 받아오고 아무것도 끝내지 않으며, `complete: true`는 **작업 종료를 선언**하고 답을 받는다 — 수락(턴 종료)이거나, 무엇이 아직 안 됐는지와 함께 반려(§6). 그들이 읽는 것은 magi 자신의 기록이다: 허가한 모든 명령과 그것이 진짜로 어떻게 끝났는지(실패가 exit 0 뒤에 숨은 파이프라인은 failed로 기록), 툴이 쓴 경로, **이번 턴 에이전트 자신의 편집**을 파일별 before→after diff로(write/edit 호출에서 재구성 — git 독립이라 사람이나 외부가 만든 변경이 에이전트 공으로 잡히지 않는다), 그리고 선언 시엔 **워크스페이스 새로 읽기**: 작업 시작 이후 수정된 파일, 아직 살아있는 백그라운드 명령, 기록은 썼다는데 디스크에 없는 경로. 멤버는 자기 렌즈가 **구체적 결함**을 짚을 때만 반대하고, 만족하면 수락하며, 판단할 증거가 없으면 **기권**한다. `rule`이 합의 방식. 각 `[[council.member]]`에 `provider`(= `[llm.profiles.*]` 백엔드)와 `model`을 주면 **멤버마다 다른 모델로 심의**(싼 것+강한 것 혼합)할 수 있고, 미지정이면 세션 모델을 쓴다. TUI에선 심의가 **헤더 칩**(`⚖ council rN: <member>`)과 트랜스크립트 라인(소집 · 멤버별 한 줄: 멤버 색 `●` + 이름 + 판정 아이콘 · 집계)으로 라이브 표시된다. **멤버 라인을 클릭하면 상세 모달**(렌즈·근거·피드백·확신도)이 열린다. 멤버별 색은 테마로 변경 가능(`[theme.dark] melchior/balthasar/casper`). 워크플로우 모드에선 비활성(파이프라인이 자체 verify 게이트를 씀).
> 컬러 테마는 `[theme.dark]`/`[theme.light]`에서 role별로 외부 정의 가능(기본=NERV/MAGI). `--theme`로 모드(auto/dark/light) 선택.
> 첫 실행 시 주석 달린 기본 `config.toml`이 자동 생성된다(있으면 안 건드림).
> **잘못된 config는 절대 조용히 무시되지 않는다**: 전역 `config.toml` 파싱이 실패하면(예: 최상위 키 중복) magi는 파스 에러를 출력하고 시작을 거부한다 — 모델·플러그인·기타 모든 설정을 떨굴 빈 config로 폴백하지 않는다. 잘못된 **프로젝트** `.magi/config.toml`은 warn 후 건너뜀(유효한 전역 config는 여전히 적용). 알 수 없는 *키*(오타)는 warn일 뿐 시작을 막지 않는다.

> **루프 & 실행 안전 가드(결정론적, 항상 켜짐)**: council 외에도 약한 모델이 혼자 빠지는 실패 모드를 잡는 값싼 결정론 가드가 있다. **자기회귀 검사** — 턴 내 각 파일 상태를 추적, 편집이 이번 턴에 이미 있던 상태로 되돌아가면("고쳤다가 슬쩍 되돌리는" 함정) 중립 노트를 붙여 재확인(권고, 차단 안 함, 파일당 1회). **터부(tabu) 리스트** — 더 정밀한 보완: 산출물을 *실행하는* 명령(테스트/프로그램 실행, 인스펙트 전용 빌트인 제외)이 실패하면 그때 편집된 파일 전체의 내용 서명을 "이미 해봤고 안 됨"으로 기록한다; 이후 편집이 모든 파일을 그 실패 상태로 되돌리면 직전 실패 사유와 함께 표시해 같은 실패 루프를 다시 돌리는 대신 다른 수정을 시도하게 한다(권고, 상태당 1회). **비대화형 명령 실행** — 모든 `bash`는 제어 터미널 없이 stdin 닫고 실행 → 프롬프트를 띄우려는 명령(git 자격증명·ssh 호스트키·apt·pager)이 타임아웃까지 멈추지 않고 **즉시 실패**. **루프 가드** — 진전 없는 동일 툴 호출이 소량 상한을 넘으면 거부(직전 결과 되돌려줌); 계속 헛돌면 먼저 **교정 재-그라운딩 1회**(원 과제 재독·접근 변경) — 이 넛지에는 **완료 탈출구**가 있다: 작업이 정말 끝났으면 **툴 호출 없이** 답만 하고 턴을 끝내라(그것이 검증을 트리거한다; 확인 명령 하나 더는 진전이 아니다), 그리고 **활동을 보여주려고 완성된 작업물을 삭제·재빌드하지 마라**. 그래도 지속되면 예산을 다 태우지 않고 우아하게 중단. **스톨 강제중단** — 교정 넛지 후에도 여러 스텝 진전이 없으면 계속 갈지 않고 우아하게 중단(`stall_guard`); `bash` 쓰기는 진전으로 인정해 느린 빌드를 스톨로 오인하지 않는다. **빈-종료 넛지** — 답변 텍스트 **없이** 끝나는 턴은 사용자가 읽을 게 아무것도 없다. harmony 약한 모델이 analysis 채널만 뱉고 멈추거나("reasoning-only stop"), 툴을 쓴 뒤 마지막 스텝에서 침묵할 때 생기는데 — 후자는 council 게이트가 그 툴 작업을 보고 "done"으로 표결해 딜리버러블도 UNVERIFIED 플래그도 없이 끝날 수 있다. 이 턴은 툴 사용 여부와 무관하게 **1회** 넛지해 실제 결과를 쓰게 한다; 그래도 빈 재시도면 정상 종료하므로 루프가 되지 않는다. **마스킹된 실패 주석** — **exit 0**인데 출력에 진짜 크래시 시그니처(Python traceback, JVM 스레드 예외, goroutine 덤프 동반 Go panic)가 있거나 명령이 순수 종료코드-무마 꼬리(`|| true`, `|| echo …`)로 끝나는 `bash` 결과에는 상태줄 바로 뒤에 한 줄 경고를 단다: 그 exit 0은 성공의 증거가 아니다. 주석만 달 뿐 — ok/error 분류와 제어 흐름은 불변(`MAGI_EXITCODE_BODYSCAN=0`으로 비활성).

> **압박하 반-fabrication.** 이 가드들이 겨냥하는 실패 모드는, 줄어드는 스텝/시간 예산이나 막다른 길에 몰린 약한 모델이 막혔다고 인정하는 대신 그럴듯한 결과(파일 내용·테스트 결과·집계값)를 **지어내는** 것이다. 시스템 프롬프트는 스톡/예산 압박하에서 결과나 증거를 지어내는 것을 명시적으로 금지하고 정직한 부분 상태를 보고하게 한다; 카운슬은 모델이 끝냈다는 주장이 아니라 **magi가 관측한 것과 워크스페이스가 실제로 담고 있는 것**(§6)으로 판정한다 — 그래서 자신만만하지만 뒷받침 없는 "done"은 잡히고, 정직한 "Y 때문에 X를 못 했다"는 받아들여진다. 정직한 실패는 올바른 결과이고, 지어낸 성공이 버그다.

### 시간 예산

**스텝 천장은 없다.** 턴은 모델이 툴 호출을 멈출 때, 에이전트가 종료를 선언하고 카운슬이 수락할 때, 컨텍스트가 취소될 때, 또는 magi를 띄운 쪽이 그만 기다릴 때 끝난다. 상한은 다섯 번째 종료였고, 무슨 일이 벌어져서가 아니라 magi 자신의 산수로 런을 끝내는 유일한 것이었다 — 벤치 실측으로 벽시계에 도달한 런은 396건 중 76건 통과, 천장이 멈춘 런은 28건 중 0건이었다. (**워크플로우 페이즈**는 예외다: 자기 예산을 파이프라인 모양의 일부로 선언한다.)

매 스텝 에이전트에게 붙는 것은 **휘발성 라인**이다(캐시되는 시스템 프롬프트가 아니라 — 접두사 캐시 안정):

- **자기측정 경과** — 턴이 1분을 넘기면 *"You have been working for 11m of wall-clock time so far"*. 턴 시작부터 잰 magi 자신의 **스톱워치**이고 외부 정보는 하나도 안 들어 있으며, 느린 반복(컴파일 10회 재시도)을 알아채고 접근을 바꾸게 한다.
- **`--time-budget`(기본 꺼짐)** — 사용자가 지정한 소프트 마감(예: `--time-budget 20m`). 예산과 남은 시간을 표시하고, 경과가 넘어가면 *"budget EXCEEDED — 가장 작은 정직한 결과를 즉시 내라"*로 바뀐다. **권고이지 하드 정지 아님**이며, 결과를 apples-to-apples로 유지하려 리더보드/비교 런에선 끈다.
- **런의 상태** — magi의 기록을 매 스텝 다시 렌더한다: 허가한 명령과 그것이 어떻게 끝났는지, 쓴 경로, 아직 살아있는 백그라운드 명령. 화면 기반 에이전트가 결정마다 터미널을 다시 읽듯, magi가 실제로 갖고 있는 저장소에 대해 같은 갱신을 한다 — 에이전트가 기억에만 기대 일하지 않도록.

### 하네스 (기본 켜짐)

설정 없이도 "이해→계획→구현→검증→요약" 절차가 자연히 적용된다. 두 층으로 구성:

1. **운영 가이드 프롬프트(항상)** — 다단계 작업이면 `todowrite`로 계획 후 하나씩, 편집 후 빌드/테스트로 검증, 깨진 상태로 끝내지 않고, 마지막에 변경 요약. 사용법을 몰라도 그냥 대화만 하면 적용됨.
2. **내장 훅(항상, `--no-harness`로 끔)** — 파일 편집 직후 자동 포맷(gofmt) + 언어 진단(gofmt -e / go vet / py_compile)을 돌려 에러를 모델에 되먹임 → 자가 수정.

**팀 공유**: 프로젝트 루트의 `.magi/config.toml`을 커밋하면 워크플로가 레포와 함께 이동한다. 전역(`<config>/config.toml`)과 병합되며 `[[hooks]]`는 누적된다.

훅 이벤트:
| event | 시점 | 종료코드 ≠ 0 효과 |
|---|---|---|
| `PreToolUse` | 툴 실행 전 | 툴 **차단**(stderr가 모델에 전달; 경로 보호 등) |
| `PostToolUse` | 파일 편집 후 | 출력을 피드백으로 전달 |
| `Stop` | 턴 종료 직전 | 종료 막고 계속 작업 강제(예: 테스트 통과 요구) |

훅 명령은 셸로 실행되며 `MAGI_TOOL`/`MAGI_PATH` 환경변수 + JSON stdin을 받는다. `match`로 툴 이름 필터(`"*"`=전체).

타이핑 키는 입력창으로만 가고 스크롤은 위 전용 키로만 — 그래서 본문 타이핑(띄어쓰기 포함)이 화면을 스크롤하지 않는다. 위로 스크롤해 읽는 중이면 스트리밍이 화면을 끌어내리지 않는다(바닥에 있을 때만 자동 추적). 트랜스크립트가 넘치면 **헤더 칩**이 스크롤 위치를 보여준다(`⇅ 42% (120/300)`, 위에 있는 동안 새 출력이 오면 `↓ new` — End로 복귀). 그리는 스크롤바는 제거됐다(칩이 대체 — 윈도우 ambiguous-width 정렬 버그 클래스가 함께 소멸).

작업한 턴이 끝나면 **영수증 한 줄**(`▣ turn: 14 steps · 3 file(s) · council r2 · 3m49s`)이 남아 스크롤 없이 턴 비용을 볼 수 있다. 에이전트가 진짜 선택지를 물어야 할 땐 **선택 모달**(`ask_user` 툴)이 뜬다: ↑/↓ 또는 1-9로 고르고 enter, esc는 건너뛰기(모델에겐 "무응답 — 알아서 판단"으로 전달). 질문이 여러 개면 모달이 순서대로 하나씩 뜬다.

**권한 영속(`p` = 프로젝트):** `p`를 고르면 `.magi/config.toml`에 allow 규칙을 써 재시작해도 유지된다. 규칙은 **툴이 허용하는 만큼 좁게** 스코프된다: 대부분 툴은 `tool(**)`로 영속되지만, `bash`는 승인한 **프로그램 이름**만 영속한다 — `curl https://x`를 허용하면 `bash(**)`가 아니라 `bash(curl:*)`로 기록 — 그래서 한 번 허용이 이후 모든 명령을 몰래 사전승인하지 않는다. 셸 메타문자(파이프·리다이렉트)로 시작하는 명령은 고정할 프로그램이 없어 과도승인 대신 세션 한정으로 남는다. 허용된 프로그램이라도 파괴/egress 스캐너는 위험한 호출에 여전히 재확인한다.

**Ambiguous-width 문자(주로 윈도우 관련):** 기동 시 magi가 터미널을 한 번 프로브해 셀-폭 측정을 자동으로 맞춘다(윈도우는 Console-API 커서 델타, 그 외는 커서 위치 질의). 프로브를 못 돌리거나(예: 리다이렉트된 stdio) 잘못 추정하면 `MAGI_AMBIGUOUS_WIDTH=wide`(또는 `narrow`)로 강제하고, `MAGI_WIDTH_PROBE=0`은 프로브를 끈다. 표준 `RUNEWIDTH_EASTASIAN=1`도 존중된다.

### 마우스 / 텍스트 복사 (모드 없음)
휠 스크롤·드래그 선택·클릭 포커스가 **모드 전환 없이** 모두 된다 — 선택/복사를 앱이 직접 처리하기 때문이다. **드래그하면 그 범위가 하이라이트되고(문자/셀 단위, 줄 부분 선택 가능), 떼는 순간 클립보드로 복사**된다(OS 클립보드 `pbcopy`/`wl-copy`/`xclip` + OSC52 둘 다 시도). 드래그 중 휠 스크롤도 된다(선택은 콘텐츠 위치에 고정되어 스크롤해도 유지). 선택 경계는 **글자(grapheme) 경계로 스냅**되므로 한글·이모지 같은 2칸 문자를 반쪽만 잡는 일이 없다.

**블록 통째 복사(⧉)**: 각 대화 블록(사용자/어시스턴트)의 라벨 줄 오른쪽에 ⧉ 칩이 있다 — 클릭하면 그 블록의 **원문 텍스트**(렌더 전 마크다운 그대로)가 클립보드로 복사된다.

**IDE 내장 터미널 호환**: JetBrains(IntelliJ 등) 내장 터미널과 Apple Terminal은 와이드 문자(한글 등)를 화면엔 2칸으로 그리면서 **마우스 좌표는 글자당 1칸으로 보고**하는 특성이 있어, 보정 없이는 드래그가 포인터보다 왼쪽에 잡힌다. magi가 이 두 터미널을 자동 감지해 보정한다(`TERMINAL_EMULATOR`/`TERM_PROGRAM`). 다른 터미널에서 같은 증상이 보이면 `MAGI_MOUSE_COMPAT=chars`로 강제, 오탐이면 `off`로 해제할 수 있고, `MAGI_MOUSE_DEBUG=1`로 실행하면 클릭마다 좌표→글자 매핑이 토스트로 떠서 진단할 수 있다. 참고: JetBrains 내장 터미널은 **한글 IME 조합이 낱자모로 깨지는 자체 한계**가 있다(앱에서 보정 불가) — 한글 입력이 잦으면 외부 터미널(iTerm2 등) 사용을 권한다.

### 트랜스크립트 렌더링
- **edit/write는 색칠된 diff**로 보인다 — 구문 강조(파일 확장자로 언어 감지) + 줄번호 거터, 추가/삭제는 `+`/`-`로.
- **bash·read·grep·glob·list·webfetch·websearch 결과는 접힌 블록**으로 본문에 표시(read는 줄번호+구문 강조). 길면 `… +N more` 푸터가 붙고 **블록을 클릭하면 펼침**.
- **카운슬 거부 사유**는 한 줄 판정 아래에 줄바꿈되어 표시(전체 사유는 위원 클릭으로 상세 모달).
- **카운슬 판정 대기 표시**: 라운드가 열려 심의가 진행되는 동안 하단 상태줄이 스피너와 함께 무엇을 기다리는지 한 줄로 고정 표시한다 — 플랜 감사면 `⚖ 플랜 감사 판정 대기 중…`, 심의/합의면 `⚖ 카운슬 심의 판정 대기 중…`. 침묵처럼 보이던 대기 구간이 진행 중임을 알려준다.
- **검수 전 보고서 접기**: "검수해줘"류 요청은 보고서 → council 리뷰 → 개정 보고서 순으로 흐르는데, 리뷰 라운드가 continue로 판정하면 **개정본이 실제로 도착하는 순간** 원래(검수 전) 보고서를 한 줄 스텁(`≡ (검수 전 보고서 — 접힘, 아래 최종본 참고)`)으로 접어 최종본만 남긴다. 접기는 개정본 도착 시점으로 미뤄지므로 리뷰가 중단·오류로 끝나면 원본이 그대로 보존되고, 개정본이 원본과 사실상 동일하면 원본을 건드리지 않는다(깜빡였다 다시 뜨는 현상 방지).

### 상태 패널 (포스트잇)
계획(todos)·백그라운드 잡·컨텍스트가 있을 때 **우상단에 둥근 윤곽선 박스(포스트잇)**로 떠서 보인다(없으면 숨김). 트랜스크립트는 전체 폭을 쓰고 박스는 그 위에 겹쳐 그려지며(하단 정렬이라 보통 빈 공간에 뜸), **박스 왼쪽 모서리를 드래그하면 폭이 조절**된다. 잡 줄을 클릭하면 그 잡으로 줌인. 박스 테두리는 터미널이 실제로 그리는 셀 폭 기준으로 조립되므로, todo·잡 줄에 🚀 같은 이모지가 있어도(터미널이 1칸으로 그리든 2칸으로 그리든) 우변 `│`가 어긋나지 않는다 — 기동 시 이모지 폭을 한 번 프로브해 보정하며, `MAGI_EMOJI_WIDTH`로 강제하거나 `MAGI_WIDTH_PROBE=0`으로 끌 수 있다.

### 테마
시작 시 터미널 배경색으로 다크/라이트를 감지하고, **실행 중 OS 테마를 바꾸면 몇 초 안에 따라 전환**된다(배경색을 주기적으로 재질의). `--theme`(또는 `MAGI_THEME`)로 `auto`/`dark`/`light` 강제.

### 작업 중 끼어들기 (steering)
작업(턴)이 도는 동안에도 입력은 살아 있다 — 계속 타이핑할 수 있고(한글 IME 포함 인라인 조합), Enter를 누르면 메시지가 **진행 중인 턴에 즉시 주입**된다. 메인 에이전트는 **다음 스텝**에서 그 메시지를 보고 반영한다 — 큐에 쌓였다가 턴이 다 끝나야 나오는 게 아니라, 실행 중인 에이전트를 그 자리에서 조종(steer)하는 것. 메시지는 트랜스크립트에 바로 표시된다.
에이전트가 **긴 백그라운드 명령을 기다리는 것 말고 할 일이 없는 동안**에도, 보낸 메시지는 그 자리에서 처리된다 — 명령이 끝날 때까지 묵히지 않는다. 잡담엔 짧게 답하고, steer는 진행 중 작업을 실제로 바꾼다: "`docs/` 아래만 봐"는 방향을 전환하고, "그거 다음에 README도 써줘"는 추가 스텝을 접어 넣고, 모호한 steer는 먼저 짧게 되물어 구체화한 뒤 반영한다. steer가 실제로 반영되면 트랜스크립트에 "Steer applied …" 감사 줄이 남아 방향 전환이 실행됐음을 확인할 수 있다 — 말로만 수긍하고 넘어가지 않는다.
현재 작업이 끝나야 답할 수 있는 질의를 넣으면, 그 질의는 큐에 들어가 **입력한 자리에 그대로 보이다가**, 답변이 준비되면 **답변 바로 위로 재배열**되어 질의–답변이 한 쌍으로 붙는다(세션을 다시 열어도 중복 없이 짝이 유지된다).
작업 중 슬래시 커맨드: 읽기/UI 전용(`/help`·`/route`(=`/model`)·`/tools`·`/subagents`·`/sessions`·`/diff`·`/permission`·`/loop`·`/loopdiff`·`/context`)은 실행되고, 세션을 바꾸는 것(`/resume`·`/rewind`·`/fork`·`/replay`·`/clear`·`/init`·`/ultra`·`/compact`)은 작업 중 거부된다.

### 백그라운드 잡 라이브 뷰 (split-pane)

스트립에는 생산자가 둘이다. **백그라운드 명령**(`bash background=true`)은 그냥 두면 "프로세스가 시작됐다"는 한 줄이 전부고 그 뒤로는 아무것도 없다 — 정작 에이전트는 `bash_output`으로 폴링하며 읽은 것에 따라 행동하는데. **스폰된 자식**(플러그인이 등록한 서브에이전트, `/subagents`)은 툴 호출 하나 안에서 몇 분씩 도는데 메인 화면이 따라가지 않는 세션에서 돈다. 어느 쪽이든 살아있는 동안 메인 트랜스크립트 아래에 **라이브 패널**이 타일로 뜨고, 각각 **고유 색상**(M3 톤 팔레트)이 보더·헤더 배지에 적용된다.

자식의 패널은 **자기 트랜스크립트**를 보여준다 — 받은 프롬프트, 추론, 툴 호출마다의 인자와 결과, 마지막에 한 말 — 메인 트랜스크립트가 그리는 것과 같은 방식으로. 백그라운드 잡의 패널은 로그 꼬리를 보여준다.

- `Tab`(또는 패널 클릭)으로 포커스 이동 → 포커스된 패널에 그 색의 **포커스 링**.
- `Ctrl+O`(또는 포커스 패널 재클릭)로 **줌인** → 그 잡의 전체 출력. 줌 진입 시 맨 아래(최신)로 이동. 상단 breadcrumb 클릭(또는 `Esc`)으로 복귀.
- 페인은 **tail**을 보여주며 초당 몇 번 파일 끝에서 다시 읽는다. **보는 것은 아무것도 소비하지 않는다**: 이 읽기는 `bash_output`이 쓰는 오프셋을 전혀 전진시키지 않으므로, 에이전트가 읽는 내용은 안 보고 있었을 때와 정확히 같다.
- **생명주기**: 도는 동안은 큰 타일, 잡이 종료되면 done으로 표시되고 페이드되어 스트립에서 패널 기록으로 넘어간다. 다음 메시지를 보내면 사라진다.

### 우측 상태 패널
계획·진행 상황이 있을 때 화면 우측에 **상태 패널**이 뜬다(없으면 숨김). **좌측 경계를 마우스로 드래그**해 폭을 조절할 수 있다(기본 44칸). 섹션:
- **Plan** — 현재 todo 체크리스트 + 진행도(`done/total`): 완료 ✓, 진행 중 ◐, 대기 ☐, **취소 ✗**(턴이 중단/정지돼 못 끝낸 단계). 진행 표시는 결정론적 신호로도 구동되어 모델이 `todowrite`를 안 불러도 갱신된다. 실시간 갱신.
- **Jobs** — 지금 도는 백그라운드 명령(색상·상태·경과). **항목 클릭 → 그 잡 출력 상세(zoom) 진입**(페인 클릭과 동일).
- **Context** — 컨텍스트 토큰 사용 막대.

### 붙여넣기 접기
여러 줄(또는 200자 초과) 붙여넣기는 **입력창에서만** `[#N pasted L lines]` 칩으로 접힌다(입력창이 좁으므로). 전송하면 **트랜스크립트(메인)에는 전체 내용이 그대로** 표시되고, 에이전트에도 전체가 전달된다. (↑ 히스토리 recall은 칩 형태로 불러와 입력창을 어지럽히지 않는다.)

### `@` 파일 멘션
메시지에 `@경로/파일`을 넣으면 해당 파일 내용이 에이전트 컨텍스트에 첨부된다.

### 헤더 표시
`model <id> · ctx <%>` + **퍼미션 칩(색상 구분)**, 그리고 아직 도는 백그라운드 잡을 알리는 배지.
- 퍼미션 칩 색: `ask`=amber(안전) · `auto`=cyan(편집 자동) · `allow`=yellow(주의) · `deny`=red(차단).
- todo 체크리스트를 진행 중이면 헤더가 **활성 스텝**도 표시해, 지금 에이전트가 무엇을 하는지 상태 패널을 열지 않고도 보인다.

### 세션 재개 (`/resume`)
`/resume`(인자 없이) → **인터랙티브 피커**: 각 세션의 시간 + 첫 메시지 요약을 보여주고 `↑/↓`로 선택, `Enter`로 재개, `Esc`로 취소. `/resume N`으로 바로 전환도 가능.
- 목록에는 **사용자 세션만** 나온다.

### TUI 동작 체크리스트 (스크린샷)
검증 중인 인터랙션 동작 모음 — 각 항목 아래에 스크린샷을 붙이기 좋게 정리.

1. **작업 중 입력 + 한글 IME** — 턴이 도는 동안에도 입력창에 인라인으로 타이핑/조합됨(커서가 입력 위치에).
2. **Steering(작업 중 끼어들기)** — 작업 중 Enter로 보낸 메시지가 진행 중 턴에 즉시 주입, 다음 스텝에서 반영.
3. **백그라운드 잡 split-pane** — 도는 백그라운드 명령마다 라이브 패널이 타일로, **잡마다 고유 색상**.
4. **포커스 / 줌** — `Tab`(또는 패널 클릭, 마우스 ON일 때)으로 포커스 이동(색상 포커스 링), `Ctrl+O`로 전체화면 상세(브레드크럼·구분선·좌측 바가 그 색), `Esc` 복귀.
5. **붙여넣기 접기** — 멀티라인 붙여넣기 → 입력창엔 `[#N pasted L lines]` 칩, 전송 시 메인엔 전체 내용.
6. **스크롤 위치 유지** — 바닥에 있으면 스트리밍/패널 추가·제거·**터미널 리사이즈** 후에도 바닥 유지, 위로 스크롤해 읽는 중이면 안 끌려감.
7. **입력 히스토리** — `↑/↓`로 이전 프롬프트 불러오기(세션 재개 시 이전 턴도 포함), `Tab`으로 접두사 자동완성.
8. **마우스/복사 (모드 없음)** — 휠 스크롤·드래그 선택+복사·클릭 포커스가 모드 전환 없이 모두 됨(앱이 선택을 직접 처리). 드래그 중 휠 스크롤도 됨.
9. **시작 시 화면 정리** — 실행 시 터미널을 한 번 clear하고 깨끗한 화면에서 시작.

- 파일 수정 후 **진단 피드백**(Go: gofmt/`go vet`, Python: `py_compile`, 그 외는 각 언어서버) → 에이전트 자가수정(하네스, §3).

### 의도적으로 없는 것

`task` 툴이 없고, **magi는 자기 에이전트를 하나도 싣지 않는다** — 내장 플래너도, 리뷰어도, 워커도 없고, 그런 플러그인을 직접 설치하지 않는 한 위임하는 것도 없다.

있는 것은 심(seam)이다. 플러그인이 서브에이전트를 선언할 수 있고 사용자가 `/subagents`에서 켠다. 그런 플러그인이 없으면 닿을 방법 자체가 없다. 이건 이 절이 예전에 하던 주장("서브에이전트는 전혀 없다")과 다른 말이고, 그 차이는 의도적이다: 걷어낸 기계는 작업을 어떻게 쪼개고 무엇을 넘길지 **대신 판단**했고, 기록이 단죄한 것은 그 판단이지 능력이 아니다. §서브에이전트 참조.

집계 툴(`countlines`·`countmatches`·`groupby`·`tabulate`)도, `findcontext`도, `astgrep`도, LSP 내비게이션 툴도, `replan`도 없다. 기록된 모든 벤치 런을 세어보니 앞의 여섯은 **0회**, `astgrep`은 2회 호출됐고, 그동안 bash 호출의 59%는 파이프를 담고 있었다. 모델은 `wc -l`과 `grep`으로 손이 가지, 그걸 재구현한 툴로 가지 않는다. 안 불리는 툴은 공짜가 아니라 **매 요청·매 스텝의 무게**다.

언어서버 자체는 그대로 돈다. **편집 후 진단**(gofmt / `go vet` / `py_compile` / LSP)은 모델이 부르지 않아도 발화하며, 기록상 실제로 착지하는 쪽은 그 절반이다.

## 6. 턴을 끝내는 법

턴은 조용해져서 끝나지 않는다. 조용해지는 건 결정이 아니다 — 생각하다 만 턴과 정말로 끝난 턴이 예전엔 똑같이 끝났고, 둘 중 어느 쪽이냐고 물어본 적이 없었다.

그래서 종료는 행위다. 에이전트가 `council{complete: true}`를 호출하면, 멤버들이 **기록을 읽은 뒤에야** 턴이 닫힌다:

- **magi가 관측한 것** — 허가한 모든 명령, 그것이 뭔가를 구동했는지 들여다보기만 했는지, 그리고 어떻게 끝났는지. 진짜 실패가 exit 0 뒤에 숨은 파이프라인은 clean이 아니라 failed로 기록된다.
- **지금 이 순간의 워크스페이스** — 기억이 아니라 선언 시점에 새로 읽는다: 작업 시작 이후 수정된 파일(파일 많은 디렉터리는 개수로 접힘), 아직 살아있는 백그라운드 명령, 그리고 **기록은 썼다는데 디스크에 없는 경로**.
- **에이전트가 말한 것** — 자기 작업에 대한 진술을, 위 둘에 비추어.

수락하면 턴이 끝나고, 아니면 무엇이 아직 안 됐는지를 짚어 돌려보낸다. 묻는 건 별개다 — `council{question}`은 읽기만 받아오고 아무것도 끝내지 않는다.

에이전트가 끝내 선언하지 않으면 magi가 상기시킨다 — 최대 3회 — 그다음엔 작업물을 있는 그대로 착지시키되 "완료"가 아니라 **선언 없이 끝남**으로 기록한다. `MAGI_DECLARE_FINISH=0`이면 예전의 수동적 종료(모델이 툴 호출을 멈추면 끝)로 A/B 복귀.

`[council] enabled = false`면 툴 자체가 사라진다. 선언할 상대가 없으니 요구도 성립하지 않고, 루프는 수동적으로 끝난다.

### 에이전트는 하나다

magi는 한때 서브에이전트를 띄우고, 작업을 스텝으로 계획하고, 스텝마다 실행 가능한 체크를 저술하고, 카운슬이 그 체크가 충족됐다고 투표할 때까지 턴을 붙들었다. 전부 걷어냈고, 기본 상태에서는 여전히 에이전트가 정확히 하나다 — **magi는 자기 에이전트를 싣지 않는다.**

이유는 로그에 있다. 그 단계들은 **작업이 존재하기 전에** 무언가를 결정했고, 가장 비쌌던 결함은 정확히 한 종류였다 — magi가 실제로 벌어진 일의 기록보다 미리 내린 자기 판단을 믿은 것. 서버가 죽었을 때만 통과하는 포트 프로브, 생성기는 언더스코어를 쓰는데 하이픈을 요구하는 grep, 채점 식별자가 사라질 때까지 패러프레이즈된 브리프. 미리 작성된 체크는 작업에 대해 틀릴 수 있지만, magi가 허가한 것의 기록은 허가한 것에 대해 틀릴 수 없고, 불완전한 부분은 불완전하다고 말한다.

남은 것은 루프, 툴, 기록, 그리고 에이전트가 원할 때 부르는 카운슬이다. 오래 걸리는 일은 `bash background=true`로 보내 `bash_output`/`wait_for`로 지켜본다 — 자기 페인(§4)에 보이고, 착지하면 진짜 exit이 읽힌다.

### 서브에이전트가 필요하면

플러그인이 등록한다(EXTENDING §3.9). magi는 심만 제공하고 정책은 두지 않는다:

- **부르지 않으면 없다.** 서브에이전트는 `/subagents`에 뜨고 거기서 켠다. 플러그인이 꺼진 채로 실을 수도 있다. 꺼진 서브에이전트는 모델에게 **광고되지 않으므로** 요청당 비용이 0이다.
- **요약하지 않는다.** 자식은 플러그인의 프롬프트와 툴 자신의 인자를 **원문 그대로** 받고, 거기에 AGENTS.md·실행 환경·작업 트리를 받는다. 부모 대화의 큐레이션된 일부는 절대 받지 않는다. 필터는 툴 인자이고, 그 선택은 전체 컨텍스트를 가진 쪽이 한다 — 패러프레이즈된 브리프가 이 저장소에서 채점 식별자를 6/6으로 잃게 만든 그것이기 때문이다.
- **묶여 있고, 재귀할 수 없다.** 자식에겐 스텝 수와 시계가 주어지고, 툴 호출 전체에도 누적 예산이 걸리며, 자식에겐 스폰할 수단 자체가 주어지지 않는다.
- **보인다.** 자기 페인에서 자기 트랜스크립트로 돈다(§4).
- **무엇을 했는지 읽고, 되돌릴 수 있다.** `magi.child_steps`는 자식이 부른 호출들을 실패한 것의 출력 원문과 함께 돌려주고, `magi.restore_child`는 파일 변경을 되돌리고 **못 되돌린 것을 이름으로 말한다.** 둘 다 자동이 아니다.

magi는 예시 하나를 번들한다 — **제레(Seele)**. 읽고 분석해 단계 목록만 돌려주는 플래너이고, 허용목록에 쓰기 툴이 아예 없다. **꺼진 채로** 실린다.

## 7. 메모리 & 컨텍스트

- **AGENTS.md**: 작업 디렉터리(+`.magi/AGENTS.md`, 전역 `<config>/AGENTS.md`)의 내용이
  시스템 프롬프트에 주입되어 **압축돼도 보존**된다. `/init`로 자동 생성.
- **자동 압축(재수화 가능)**: 실제 토큰 수가 모델 윈도우 80% 초과 시 오래된 턴 요약(최근 보존). 압축된 구간은 **topic shard로 결정론적 인덱싱**되어 원문이 사라지지 않는다 — `recall_context("<topic>")`(파일 경로가 잘 맞음)로 **원문 그대로** 재수화(토픽당 1회·턴 예산·크기 캡). 여기에 매 스텝, 현재 작업(최근 사용자 프롬프트 + 마지막 어시스턴트 메시지)과 어휘적으로 맞는 압축-이탈 토픽 최대 3개가 **힌트로 자동 주입**되어(“관련 과거 컨텍스트 — recall_context로”) 모델이 recall을 떠올리지 못해도 잃은 걸 가리켜 준다. 매칭은 **BM25-lite IDF**로 순위를 매긴다: 여러 shard에 흔한 토큰(`the`, `handler`)보다 한 구역을 콕 집는 희귀 토큰(`dehydration`, `heap.go`)이 앞선다 — 그래서 현재 스텝이 실제로 필요한 구역을 가리킨다. 순수 어휘/결정론(임베딩 의존 없음)이며 힌트는 *가리키기*만 하고 원문은 여전히 `recall_context`로 당겨온다. 윈도우는 **모델별**(에이전트마다 다른 모델→다른 윈도우)로, 시드에 없으면 백엔드에 **질의**(vLLM `max_model_len`·LiteLLM `/model/info`·Ollama `/api/show`) — 초기 모델은 시작 시, 그 외 모델은 **처음 쓰일 때 지연 조회**(`/route` 런타임 전환 등). Claude/Gemini는 해당 엔드포인트가 없어 시드 테이블에 의존. 윈도우를 못 구하면 **무제한**(게이지·비율압축 비활성)으로 간주하고, `/context <model> <tokens>`로 수동 지정 가능.
- **공유 두뇌(D13)**: `<config>/experience`(또는 `experience_dir`)의 `memories/`·`skills/`를
  세션 시작 시 회수·주입한다. 스토어는 **세 층**이다: `<workspace>/.magi/experience`(그 워크스페이스와
  그 repo만), `<config>/teams/<name>/experience`(이 기계에서 그 팀을 선언한 컴패니언들),
  `<config>/experience`(이 사람의 모든 magi). `remember` 툴은 **바로** 그 안에 쓴다 —
  리뷰 큐는 없다(EXTENDING §2.4의 정정). 디렉터리를 git repo로 두고 commit/pull하면 팀 공유.
  단계별 부트스트랩/파일형식/리뷰 절차: [`EXTENDING.md`](EXTENDING.md) §2.

## 8. 스킬

`<config>/skills/*.md` 또는 `<workdir>/.magi/skills/*.md` (첫 줄=설명, 이하=본문), 그리고 **skill-creator 규격** `<workdir>/.claude/skills/<slug>/SKILL.md`(frontmatter `description`=트리거) — 표준 skill-creator 규격으로, Claude Code 도구와 번들 engram 플러그인이 만드는 형식을 변환 없이 읽는다. 스킬 목록은 소스 디렉토리 변경(mtime) 시 갱신되므로, engram이 세션 중 저장한 스킬도 재시작 없이 다음 턴부터 쓸 수 있다.
시스템 프롬프트에 목록이 노출되고, 모델이 `skill` 툴로 본문을 로드해 따른다.

## 9. 플러그인 (Lua)

`<config>/plugins/<name>/` 또는 `<workdir>/.magi/plugins/<name>/`에
`plugin.toml` + `init.lua`. capability: `tool`·`command`(`/login` 같은 슬래시 커맨드)·`context-provider`·`mcp`·`llm-headers`·`analyze`·`experience`(magi.propose_experience — 플러그인이 학습한 교훈/스킬을 D13 공유 스토어 리뷰 큐로 제안)·`notify`(magi.notify — 세션 트랜스크립트에 시스템 ⟳ 노트 추가, 능동 알림 채널; 모델도 다음 턴에 봄). `magi.remove_file`은 fs:write 권한으로 워크디렉토리 파일/디렉토리 삭제 — 산출물 쓰는 플러그인의 undo 반쪽. 파일 변경 시 **핫리로드**.
샌드박스(위험 stdlib 차단) + 매니페스트 권한(`fs:read`, `net`, `exec`) 집행.
예제: `plugins/examples/wordcount`.

**관찰자(observer) 플러그인.** 라이프사이클 이벤트(`startup`/`shutdown`/`session_start`) 외에 `magi.on`은 페이로드 테이블을 받는 **관찰 이벤트** 2종을 지원한다: `user_message`(`{session, text}` — 진짜 사용자 프롬프트 제출)와 `turn_finished`(`{session, text, outcome, reason, skills}` — 톱레벨 턴 종료, text는 최종 어시스턴트 답변; `skills`는 이번 턴에 로드된 스킬명 콤마 목록 — 사용 실적 계측용). `outcome`은 턴의 **구조적 판정**이라 관찰자가 성패를 문구에서 추측할 필요가 없다: `verified`(카운슬이 직접 done 합의) · `unverified`(승인 없이 착지 — 딜록/비용캡/라운드캡) · `guard`(루프/스톨 가드 강제정지) · `error` · `ungated`(툴을 쓴 턴인데 카운슬이 아예 안 돎 — 카운슬 비활성·워크플로·하위깊이 종료 — 완료가 미검증이므로 사용자 확인 없이 성공으로 기록하면 안 됨) · `done`(툴을 안 쓴 평이한 대화 종료); `reason`은 사유. 둘 다 **턴 경로 밖에서 비동기로**(바운드 큐 + 워커 1개) 발화되므로 느린 핸들러가 대화를 지연시키지 않고, 큐가 넘치면 이벤트를 버린다(관찰은 best-effort). 여기에 **`magi.analyze{system=, text=, model=?}`** — 도구 없는 **원샷 사이드카 LLM 호출**(토큰을 쓰므로 capability `analyze` 필요; 시간 제한; model 생략 시 세션 모델) — 과 **`magi.json_decode(s)`**를 조합하면, 플러그인이 대화를 관찰해 구조화 지식(교훈·요약)을 추출하고 `magi.write_file`로 축적한 뒤 `magi.register_context_provider`로 되먹일 수 있다. 번들된 **`plugins/engram`** 자기개선 플러그인(구조적 outcome을 게이트로 교훈/스킬 자동 추출)이 이 3종 조합의 레퍼런스다 — 해당 README 참고.

```toml
# plugin.toml
name = "wordcount"
capabilities = ["tool"]
permissions = ["fs:read:."]
```

**내장(embedded) 플러그인.** 바이너리에는 **engram** 자기개선 플러그인(교훈/스킬 자동 캡처 — `plugins/engram/README.md`)이 실려 있다. **기본 켜짐**이며, 사이드카 LLM 토큰 소비·워크스페이스 지식 파일 생성이 부담이면 끈다:

```toml
[plugins.engram]
enabled = false
```

`MAGI_EMBEDDED_PLUGINS=off`는 설정과 무관하게 내장 플러그인 전부를 끈다 — 측정 행동이 흔들리면 안 되는 자동화/벤치 런용.

종료 시 magi는 큐에 남은 관찰 이벤트를 잠깐 드레인해 관찰자의 사이드카 분석(예: engram의 교훈 추출)이 프로세스 종료 전에 착지하도록 한다 — 안 그러면 분석 도중에 죽는 헤드리스 원샷 런에 특히 중요하다. 이 대기는 상한이 있어(기본 `30s`) *느린* 사이드카 모델이 종료를 막지 못한다. `MAGI_DRAIN_TIMEOUT`(Go duration, 예: `5s`, `2m`)로 조정한다. 내장 플러그인을 끄면 드레인할 것이 없다.

켜진 내장 플러그인은 매 시작 시 `<config>/plugins-embedded/`에 풀리므로 항상 바이너리 버전을 따른다 — 업데이트는 `magi --update`에 실려 오고 별도 플러그인 업데이트가 필요 없다. 일반 플러그인 디렉토리에 같은 이름이 있으면 그쪽이 우선한다(커스터마이즈는 그리로 포크). **포크가 자체 플러그인을 번들**하려면 `plugins/embedded.go` 한 파일만 수정하면 된다(플러그인 디렉토리 추가 + `//go:embed all:<name>` 변수 + `Embedded` 맵 등록 — 하위 디렉토리도 함께 실린다).

**설치 / 업데이트.** git repo로 배포된 플러그인(repo 루트에 `plugin.toml`)은
`magi --plugin-install <git-url> [--plugin-pin <태그/브랜치>]`로 설치하며, `<config>/plugins/`로
clone된다. `magi --update-plugins`(또는 바이너리까지 갱신하는 `--update`)는 git 체크아웃 플러그인마다
fast-forward하며, 로컬 변경이나 remote 없음은 보고 후 건너뜀(덮지 않음). §버전/자동 업데이트 참고.

## 11. 모델 권장

- **gpt-oss:120b-cloud** — **기본**. Ollama 무료 클라우드 티어(`ollama signin`), GPU 불필요. 강력한 범용+코딩.
  무료는 "light usage"(동시 1개·GPU시간 쿼터)라 더 무거운 `qwen3-coder:480b-cloud`는 쿼터를 빨리 먹는다.
- **qwen3-coder:30b** — 가장 강한 **로컬** 코더(24GB GPU). `--model qwen3-coder:30b`로 완전 로컬 실행.
- **gpt-oss:20b** — 가벼운 로컬 대안(추론 표시).
- 작은 모델(llama3.1:8b 등)은 툴 활성 시 함수콜 누설 경향 → 비권장.

**프로바이더 복원력(불안정한 백엔드가 턴을 거의 잃지 않는 이유).** magi는 OpenAI 호환 계층을 best-effort로 다루며, 안전하게 가능한 곳에선 어보트 대신 복구한다:
- **tool-call 파싱** — 로컬/클라우드 모델의 tool-call 변종(JSON/XML/네이티브)을 모두 파싱하고, 백엔드가 `cache_control`을 거부(400/422)하면 투명하게 캐싱 없이 1회 재시도하고 세션 동안 기억한다.
- **일시 장애** — 연결 오류와 429/5xx는 상한 있는 백오프로 재시도(`Retry-After` 준수); 재시도 소진 시 **상태 + 본문**을 표면화해 실패가 진단 가능하며, 맨숭한 "request failed"로 끝나지 않는다.
- **harmony tool-call 오파싱** — Ollama의 gpt-oss harmony 파서는 **모델이 최종 답을 prose로 뱉을 때** 그걸 tool call로 읽으려다 종종 **500**을 낸다(`error parsing tool call: raw=…`). 재시도 사이 요청이 동일해 이 500은 결정론적이므로, magi는 **tools 배열을 벗기고 1회 재시도**한다: tools를 광고하지 않으면 서버가 tool-call 파싱을 건너뛰고 같은 prose를 일반 content로 돌려줘 — 모델이 실제로 낸 답이 턴 하드-어보트 대신 복구된다. 이 정확한 시그니처에만 스코프되어 진짜 장애(genuine outage)는 그대로 에러로 표면화된다.

## 12. 콘솔 (`magi-web`)

> 화면 구성·디자인 규칙·근거: [`UI.ko.md`](UI.ko.md).
> 눌러볼 수 있는 데모(목업 데이터, 서버 없음): <https://sayaya1090.github.io/magi/>.

이 머신의 모든 magi를 — 그리고 가리키면 다른 머신의 것까지 — 보는 웹 화면. 별도의 서비스가 아니라
**같은 데몬 위의 두 번째 표면**이다: 보여주는 것은 디스크에 이미 있는 이벤트 로그에서 유도하고,
*하는* 것은 전부 `--attach`가 쓰는 그 소켓으로 나간다. 콘솔을 꺼도 아무 일도 멈추지 않는다.

### 12.1 띄우기

```sh
./magi-web                                   # http://127.0.0.1:7777
./magi-web -addr 127.0.0.1:7788
./magi-web -config-dir /path/to/config       # 어떤 데몬들이 보이는지
./magi-web -workdir /path/to/repo            # 기본 워크스페이스
./magi-web -peer laptop=http://10.0.0.4:7777 -peer ci=http://10.0.0.9:7777
./magi-web -emit-demo ./out                  # 페이지를 정적 파일로 쓰고 종료
```

- **기본은 루프백이고, 자체 로그인은 없다.** 조직이 허용하는 방식으로 접근한다 — `ssh -L` 터널,
  또는 회사의 SSO를 앞에 세운 프록시. 계정을 우리가 만들면 회사 문 옆에 문을 하나 더 다는 것이고,
  두 번째 문은 언제나 더 약하다.
- **모든 라우트가 same-site 전용이다.** 핸들러마다 감싸져 있어 다른 오리진의 페이지가 POST할 수
  없다 — 콘솔엔 훔칠 토큰이 없지만, 그 버튼들은 데몬을 멈춘다.
- **`-peer name=url`은 다른 콘솔을 합친다.** 피어의 컴패니언이 그 이름을 달고 목록에 섞이고, 그들에
  대한 액션은 소유한 콘솔로 전달된다 — 그 머신의 소켓은 이쪽이 열 것이 아니기 때문이다. 응답 없는
  피어는 **그렇게 적힌 행**이 된다. 피어 URL은 오직 운영자에게서만 온다 — 페이지나 다른 피어의
  응답에서 오지 않는다.
- **`-peer`와 클러스터(§13.8)는 다른 것이다.** 피어는 운영자가 적어 준 콘솔이고 **사람이 보기 위한**
  것이다. 클러스터는 컴패니언들이 서로에게 누가 있는지 알리는 것이고 **일이 건너가기 위한** 것이다.
  둘은 서로의 목록을 읽지 않는다.

### 12.2 화면

왼쪽 레일에 목적지가 둘 있고, 컴패니언 상세는 첫 번째 안에 있다.

| 목적지 | 무엇이 있나 |
|---|---|
| **컴패니언** | 이 콘솔이 볼 수 있는 모든 데몬: 상태, 지금 하는 일, 호스트와 IP, 유휴 시간, 자기 계획의 진척(`3/7`), 그리고 **다른 컴패니언을 위해 지고 있는 일**. 위쪽 타일이 상태로 거르고 사람을 기다리는 수를 배지로 단다. 행을 누르면 그 컴패니언이 열린다 |
| **공유** | 경험 저장소와 MCP 서버가 일이 일어나는 순서대로 함께 있다: 자주 말해져 규칙이 된 것, 그 규칙들, 그리고 컴패니언들이 닿을 수 있는 곳. 경험 행마다 도달 범위("모든 컴패니언"/"frontend 팀"/"api만"), 무엇을 하다 배웠는지, 본문이 적히고 잘못된 건 잊게 할 수 있다. MCP 서버는 추가·변경·삭제할 수 있고 그 컴패니언의 설정에 쓰여 다음 기동 때 붙는다 |
| **보드** | 작업을 카드로, 컴패니언마다 한 칼럼, 옮길 수 있는 날짜. 칼럼이 상태가 아니라 누가 했나인 이유는 지난 화요일에 그 컴패니언이 어떤 상태였는지 같은 것은 존재하지 않기 때문이다. 카드는 에이전트가 붙인 `label`로 묶인다 |

### 12.3 컴패니언 상세

행에서 열리고 주소는 `/?d=<소켓 경로>`. 여기서 하는 일은 둘 — 지켜보는 것과 말하는 것 — 이라
페이지는 대화가 본체이고 나머지가 그 옆에 선다.

**대화.** 이벤트 스트림(`/events`)으로 트랜스크립트가 실시간으로 흐르고, TUI와 같은 방식으로
그려진다: 펼쳐지는 툴 호출 접기, 사고 블록, 멤버별 판정이 붙은 카운슬 라운드, diff, 그리고 아직
도는 호출 아래의 진행 막대. 툴 호출은 어떻게 끝났는지를 글리프로 말하고, 접기 하나를 펴면 같은
종류가 함께 펴진다.

**입력창.** 보내는 것은 새 턴이 아니라 **steer**로 들어간다 — 데몬이 이미 일하는 중일 수 있고,
어느 쪽인지 정하는 건 엔진이다. `중단`은 턴을 끊는다. 컴패니언이 권한이나 질문에 막혀 있으면 그
프롬프트가 여기 버튼과 함께 뜨고, 페이지에서 답하면 붙은 터미널이 답했을 그 호출이 풀린다.

**오른쪽 사실 패널.** 손잡이는 패널 오른쪽 위 아이콘이고, 열어 뒀는지 여부를 기억한다. 위에서부터:

| 카드 | 무엇인가 |
|---|---|
| 이건 뭔가 | 상태·워크스페이스·역할·팀(팀을 대표하는지까지)·호스트·IP·pid·스텝·마지막 활동·세션 id — 볼 때까지 한 줄로 접혀 있다 |
| 계획 | 에이전트가 마지막으로 기록한 투두와 진행 막대. **로그에서 읽으므로** 멈춘 컴패니언, 다른 데서 재개한 세션, 안 보고 있는 동안 진행된 것도 맞다 |
| 넘긴 일 | 다른 컴패니언에게 준 것과 돌아온 답 |
| 예정 | 무인 작업(§14): 스케줄 줄, 다음 발화 시각, 켜짐 여부 |
| 당신이 해야 했던 말 | 사람이 끼어든 기록, 기본 최근 일주일 — 어디서 손이 필요했는지의 기록 |
| 지금까지 한 일 | 지난 세션들, 단어로 검색(`/search?q=`), 열면 그 트랜스크립트 |

840px 아래로는 두 판이 들어갈 자리가 없어 탭 둘이 되고, 착지하는 쪽은 대화다.

### 12.4 라우트 (자동화용)

표시 없으면 `GET`. 컴패니언은 `?socket=`(또는 `?d=`)로, 연합된 콘솔은 `?peer=`로 지정한다.

| 라우트 | 하는 일 |
|---|---|
| `/fleet` | 목록 전체를 JSON으로 — 표가 그리는 그 행들 |
| `/events` | 한 컴패니언의 이벤트 스트림(SSE) |
| `/plan` · `/handoffs` · `/context` · `/history` · `/interventions` · `/cron` | 위 카드들의 JSON |
| `/search?q=` | 그 워크스페이스의 지난 세션 검색 |
| `/skills` · `/remember`(POST) · `/forget`(POST) | 경험 저장소 |
| `/mcp`(GET/POST) | 한 컴패니언의 MCP 서버 |
| `/submit`(POST) | 도는 세션에 텍스트를 steer |
| `/interrupt`(POST) · `/compact`(POST) | 턴 중단 · 지금 요약 |
| `/answer`(POST) | 막혀 있는 권한/질문을 호출 id로 해소 |
| `/shell`(POST) | 그 워크스페이스에서 명령 실행 |
| `/dispatch`(POST) | 이름·역할·팀으로 일을 보냄, §13의 규칙으로 해소 |
| `/console` | 이 콘솔이 무엇인지: 설정 디렉터리, 호스트, 임베딩 모델 |
| `/push`(POST) | 이 브라우저를 알림에 구독(키를 주고 띄운 경우) |

**용어.** 워크스페이스 하나에 묶인 magi 하나가 **컴패니언(companion)**이다. 여러 컴패니언을 보는
사람은 각각의 운영자가 아니라 **감독자(supervisor)**다 — 근거와 함의는
[`proposals/companions-and-supervision-2026-08-07.md`](proposals/companions-and-supervision-2026-08-07.md).

## 13. 컴패니언 · 팀 · 클러스터

magi 여럿이 서로에게 일을 넘기는 구조. **레지스트리도, 게이트웨이도, 브로커도 없다** — 데몬마다
소켓 옆에 작은 레코드를 발행하고 그 디렉터리가 곧 멤버십이다. 머신을 건너서는 같은 레코드가
컴패니언들이 서로 본 것을 알려 주며 옮겨 다닌다.

### 13.1 자기가 누구인지 선언한다

워크스페이스의 `.magi/config.toml`에:

```toml
[companion]
name = "design"                              # 남들이 부르는 이름
role = "디자인 시스템: 컴포넌트 스펙과 리뷰"   # 한 줄: 무엇을 위한 것인가
team = "frontend"                            # 선택: 관련된 일을 하는 컴패니언들
hub  = false                                 # 선택: 주장이 아니라 선호 (13.7)
mcp_peers = false                            # 선택: 귓구멍 (13.5)
```

데몬 레코드에 실려서 `magi --agents`·콘솔·툴이 전부 한 출처를 읽는다. 아무것도 선언하지 않은
컴패니언은 예전의 컴패니언 그대로 — 그냥 워크스페이스다.

### 13.2 서로를 본다

`companions`는 읽기 전용이고 각자의 이름·역할·팀·상태·사람에게 막혔는지, 그리고 **그 워크스페이스가
무엇을 배웠는지**(자기 경험 층에서 최대 3개, 많이 관측된 순)를 준다. `matching`으로 좁힐 수 있고,
좁힌 답은 **몇 개를 뺐는지 항상 말한다** — 안 그러면 그게 팀 전부로 읽힌다.

> 마지막 항목이 전문가를 만든다. 디자인 일을 계속 받는 쪽에 디자인 교훈이 쌓이고, 고르는 쪽이 그
> 기록을 보고 또 고른다. **magi는 순위를 매기지 않는다** — 증거를 보여주고 고르는 건 호출자다.

`companion_can`은 그중 하나에게 실제로 뭘 할 수 있는지 묻고, 답은 **그 컴패니언**이 한다: 역할,
스킬, 닿을 수 있는 MCP 서버. 그래서 안 돌고 있는 컴패니언은 설명할 수 없다 — 어차피 일을 맡길 수도
없으니 그게 맞는 방향이다.

### 13.3 조각을 넘긴다 — `hand_off`

```
hand_off(to, request, so_that, answer_as)
```

**즉시 영수증을 들고 돌아온다.** 요청자는 계속 일하고, 상대가 끝내면 그 답이 요청자의 대화에 도착해
거기서 합쳐진다. 기다리지 않고, 두 번 묻지 않는다.

넷 다 필수이고, 뒤의 둘이 차이를 만든다:

| 필드 | 무엇을 위한 것인가 |
|---|---|
| `to` | 툴 설명에 실린 명단에서 고른 이름 — 그 명단은 매 스텝 다시 만들어져 **지금** 돌고 있는 이들을 부른다 |
| `request` | 혼자 서는 지시 전체. 상대는 당신의 대화도, 파일도, 추론도 못 본다 |
| `so_that` | 그 답이 무엇에 쓰이는지, 한 절. 예상 못 한 것을 만났을 때 스스로 조정하게 해 주는 게 이것이고 — **되물을 수가 없다**. 이 비대칭이 이 필드의 값어치다 |
| `answer_as` | 답이 돌아올 **양식**: 당신이 읽을 순서대로 쓴 칸 이름들. 상대가 채운다 |

`answer_as`는 완료 조건 문장이 아니라 양식이다. "토큰 이름이 다 적히면 완료"는 나중에 꼼꼼히 읽어야
확인되지만, 양식은 **보면** 확인된다. 못 한 부분의 모양도 바뀐다 — 못 한 부분이 **그 칸으로**, 그렇게
적혀서 온다. 전체가 왜 어려웠는지에 대한 문단이 아니라. magi는 한 단어짜리 양식을 거절하고(실측:
모델이 `"text"` 한 단어로 채웠다) 거기서 멈춘다. 양식이 *좋은지*는 그 작업에 대한 판단이기 때문이다.

**연쇄 금지.** 넘겨받은 일은 다시 넘길 수 없다. 규칙은 트랜스크립트에 남은 라벨에서 읽으므로 재시작·
다른 데서의 어태치·재개된 세션을 견딘다.

### 13.4 돌아온 것, 그리고 그 값어치

답은 요청했던 양식과 그것을 지목하는 영수증과 함께 인용되어 도착한다 — 한 컴패니언에게 두 조각을
줄 수 있고, 두 답을 구별하는 유일한 수단이 어느 요청에 대한 답인가이기 때문이다.

그 뒤 요청자에게 `rate_handoff(who, verdict, why, asked)`를 묻고, `<워크스페이스>/.magi/handoffs.jsonl`에
덧붙는다. **점수가 아니라 기록이다**: 무엇도 이걸로 정렬·필터·순위를 매기지 않는다. 다음 `hand_off`
설명에 그냥 분모 표시("3건 중 2건 유용")로, 이름순으로, **후보가 둘 이상일 때만** 실린다 — 하나뿐이면
고를 게 없고 매 프롬프트의 순수 무게다.

### 13.5 귓구멍 — 둘 다 일하는 중에 말 걸기

`hand_off`는 조각을 준다. 귓구멍은 이미 둘 다 일하는 중에 오가는 대화를 위한 것이다: 계속하려면
답이 필요한 질문, 혹은 상대가 물은 것에 대한 답.

`mcp_peers = true`로 두면 여기서 돌고 있는 컴패니언이 전부 MCP 서버로 붙고, 각자 이름이 붙은 툴이
하나씩 생긴다: `ask`. **수신자가 툴 이름이다** — 일부러 그렇다. 필드에 담긴 이름은 모델이 지어낼 수
있는 이름이고, 이 트리에는 정확히 그 실패 기록이 있다("ssh"라는 존재하지 않는 컴패니언에게 보낸 요청).

기본은 꺼짐이고 그건 실수가 아니다: 피어당 툴 둘이 매 프롬프트의 툴 목록에 들어가고, 피어당 서브
프로세스가 데몬 수명 내내 떠 있다. 붙고 떨어지는 건 **턴 경계**에서만 일어난다 — 툴 집합이 바뀔 수
있는 유일한 순간 — 그래서 늦게 뜬 컴패니언은 다음 재시작이 아니라 다음 턴에 들린다.

### 13.6 한 번에 하나, 큐, 그리고 얼마나 바쁜지

컴패니언의 **대화는 격리되지만 일은 아니다**. 요청자마다 곁세션이 따로 생겨서 남의 요청이 사람이
하고 있는 대화에 끼지 않고 두 요청자가 이력을 공유하지도 않는다 — 하지만 한 워크스페이스에서 도는
턴은 사람 것까지 포함해 언제나 하나다. 한 트리에서 두 턴은 조율 없이 같은 파일을 고치는 두 에이전트다.

그래서 바쁜 컴패니언은 거절이 아니라 **큐에 쌓는다**. 일은 즉시 접수되고(영수증이 그래서 있다),
시작 전에 물어보면 그렇게 답한다 — "아직 시작 안 함, 3개 중 2번째 대기". 큐는 넷까지. 그 뒤로는
다른 데 물어보라는 문장과 함께 거절한다. 그보다 긴 큐는 나중에 오는 답이 아니기 때문이다.

발행 레코드에 숫자 둘이 실려 함께 이동하므로, 고르는 쪽이 각자가 얼마나 바쁜지 볼 수 있다:

```
worker (짧은 파일을 씀) · can: 3 · 1 in hand, 2 waiting
```

둘 다 옆의 상태에서 유도할 수 없다: **상태는 사람이 어태치한 세션에서 읽고**, 넘겨받은 일은 자기
대화에서 돈다 — 그래서 세 사람의 요청으로 바쁜 컴패니언이 `idle`로 읽히는 것이 맞고, 그렇지 않다고
말해 주는 게 이 숫자들이다. 사이팅에서 읽으면 그 사이팅만큼 오래됐다. 권위는 여전히 거절이고, 그건
낡지 않는다.

**그리고 남는다.** 도착은 전부 `<소켓>.load`에 적힌다 — 접수(앞에 몇 개 있었는지 포함)인지, 자리가
없어 돌려보냈는지. `magi --agents`가 최근 일주일을 표 아래에 합산한다:

```
Handed-over work over the last 7 days:
  worker  31 taken, up to 4 already waiting, 12 turned away
  Turned away means the queue was full when somebody asked. Repeatedly, and one copy of
  that companion is not enough for what is being asked of it.
```

적어 두는 이유가 그것이다: 지금 얼마나 바쁜지는 **한 순간**이고, 하나로 충분한지는 **패턴**이다.
파일은 한 달 뒤 감쇠하고, 데몬이 멈춰도 **지우지 않는다** — 과부하였는지 묻는 건 컴패니언이 죽고
난 다음 주다. 위의 위임 기록과 일부러 같이 두지 않았다: 판정은 컴패니언의 일에 대한 판단이라
저장소에 속하고, 이건 운영값이라 소켓 옆에 속한다.

### 13.7 팀과 허브

`team`은 관련된 일을 하는 컴패니언을 묶는다. 팀을 부르면 **가장 짐이 가벼운 멤버**에게 가고, 동점은
선출된 허브가 가른다 — 그래서 놀고 있는 팀은 안정된 주소 하나를 갖고, 바쁜 팀은 분산된다. 예전엔
항상 허브로 갔고, 그래서 **셋짜리 팀이 큐 하나처럼 동작했다**: 넘겨받은 일은 아무도 다시 넘길 수
없으므로(13.3) 전부 선출된 하나 뒤에 쌓였다. 두 번째 카피를 띄운 사람이 사려던 것의 정반대다.

허브는 **선언이 아니라 선출**된다. `hub = true`는 선호다. 실제로 거기 있는 컴패니언 중 가장 많이 할
수 있는 쪽이 팀을 대표하고, 동점은 결정적으로 갈라 모든 머신이 같은 하나를 뽑는다. 멤버가 전부
조용해진 팀은 아무도 뽑지 않고 그룹으로 주소가 되지 않는다 — 멤버 전원으로 풀리고, 호출자에게
고르라고 한다.

### 13.8 머신을 건너

다른 머신의 컴패니언은 **ssh**로 닿고, 건너가는 것은 데몬 자신의 프로토콜뿐이다:

```sh
ssh buildbox magi --relay /path/to/their/daemon-....sock
```

이걸 사람이 치지는 않는다. 부르려는 컴패니언이 여기 없을 때 magi가 친다. `--relay`는 stdin/stdout을
그 소켓에 잇는다. 그래서 일을 맡기는 것, 어떻게 됐는지 묻는 것, 무엇을 할 수 있는지 묻는 것이 세
개의 서브커맨드가 아니라 한 프로토콜의 세 **메서드**다 — 서브커맨드였다면 새 프로세스가 데몬이 이미
아는 것을 파일에서 다시 유도했을 것이다. 답은 폴링이 아니라 같은 파이프로 **푸시**된다.

여기인지 저기인지는 호스트명 비교가 아니라 **소켓 옆에 발행된 레코드**로 정한다: 설정 디렉터리는
공유될 수 있고(마운트를 공유하는 컨테이너 둘, 네트워크 홈을 쓰는 워크스테이션 둘), 다른 머신을
가리키는 레코드는 남의 경로다 — 그걸 열면 실패가 아니라 **엉뚱한 워크스페이스**가 열리고 일은 배달된
것처럼 보인다.

**클러스터 합류:**

```sh
magi --join-cluster buildbox      # 그 머신과 멤버 목록을 ssh로 교환
```

한 번의 교환이 전송이자 합류 전부다: 이쪽이 아는 것을 보내고, 저쪽이 병합해서 자기가 아는 것으로
답하고, 둘 다 결과를 쓴다. 그 뒤로는 데몬들이 알아서 갱신한다 — 매 분(지터를 줘서) 각자 호스트 둘을
골라 다시 교환하므로, 세 번째 머신 얘기가 아무도 두 번 말하지 않아도 첫 번째에게 닿는다.

쓰이는 파일은 `<config>/cluster.json`이고, **감쇠한다**: **5분** 동안 아무도 못 본 컴패니언은 보이되
일을 받지 않고, **1시간** 동안 못 본 컴패니언은 지워진다. 그래서 설정이 아니라 런타임 파일이다 —
설정은 저절로 낡지 않는다. 이 머신 자신의 컴패니언은 절대 여기 쓰이지 않는다: 매번 발행 레코드에서
읽고, 사본은 데몬이 멈추는 순간 낡는 두 번째 답일 뿐이다.

필요한 것: 키 인증이 되는 `ssh`(magi는 `BatchMode=yes`로 부른다 — 물어보지 않는다), 그리고 원격
`PATH`에 있는 `magi`. 원격 바이너리는 이 머신의 경로가 아니라 그냥 이름으로 부른다.

### 13.9 클러스터, 처음부터 끝까지

머신 둘, 컴패니언 셋. `mac`이 디자인, `buildbox`가 빌더와 리뷰어.

**워크스페이스마다 자기가 누구인지:**

```toml
# mac:~/work/design/.magi/config.toml
[companion]
name = "design"
role = "디자인 시스템: 컴포넌트 스펙·토큰·리뷰"
team = "frontend"
```

```toml
# buildbox:~/work/api/.magi/config.toml
[companion]
name = "api"
role = "Go 서비스: 핸들러·저장소·테스트"
team = "backend"
hub  = true
```

**각각 데몬을 띄운다**(워크스페이스당 하나 — 소켓 이름이 워크스페이스 실제 경로에서 나오므로 관례가
아니라 락으로 강제된다):

```sh
cd ~/work/design && magi --daemon &
```

**한 번, 어느 쪽에서든 합류:**

```sh
mac$ magi --join-cluster buildbox
```

**각 머신이 무엇을 믿는지 확인:**

```sh
$ magi --agents
STATE  AGENT                                       IDLE  STEPS  WORKSPACE
idle   design  — 디자인 시스템: …                   12s   -      /Users/me/work/design
idle   api *  — Go 서비스: …               [backend*]  4s   -    /home/me/work/api
```

여기서부터는 모델이 한다: `hand_off` 설명에 누가 있는지, 각자 어느 호스트에 있고 무엇을 할 수 있고
지금 무엇을 지고 있는지가 이미 실려 있다. 더 설정할 것은 없다.

**보기:** `magi-web`은 그 머신의 컴패니언을 보여주고, `-peer`로 다른 콘솔의 행을 같은 표에 넣는다(§12.1).

**하나가 계속 거절하면** 카피를 하나 더 띄운다 — 같은 `team`을 가진 두 번째 워크스페이스 — 그러면 팀
주소가 둘 사이로 일을 퍼뜨리기 시작한다(13.7). 그렇게 할 근거는 `magi --agents`에 있다(13.6).

### 13.10 "합류"라는 말을 쓰는 다른 것 둘

`magi --join <name>`은 `--join-cluster`가 **아니다**. 한 컴패니언의 프로젝트 설정을 읽어
`.magi/joined-<name>.toml`을 내 것 옆에 쓴다 — **적용되지 않는 제안서**다. 담기는 것: 그들의 팀,
`experience_dir`(신참이 뭔가를 알고 시작하게 만드는 그 한 줄), 쓰는 MCP 서버, `AGENTS.md` 포인터.
담기지 않는 것: 모델·권한 자세·샌드박스 — 그건 팀이 아니라 그 워크스페이스의 선택이다.

내용은 전부 주석 처리돼 있고, 일부러 그렇다. `[mcp]` 항목은 **이 프로세스가 실행할 명령과 인자**이고
훅은 셸 한 줄이다. "합류한 컴패니언이 그러라고 했다"는 문장이 사고 보고서에 있어선 안 된다. 환경변수는
이름만 적히고 값은 절대 안 적힌다 — 두 번째 워크스페이스에 복사된 토큰은 두 곳에 있는 토큰이다.

`POST /dispatch`는 `to=`(이름·역할의 단어들·팀)를 받아 같은 규칙으로, 그 컴패니언 페이지에 사람이
타이핑한 것과 같은 경로로 해소한다 — 둘이 정확히 한 경로로 데몬에 닿는다. 둘이 매칭되면 선택이 아니라
에러다.

### 13.11 일부러 하지 않는 것

- **스케줄러.** 무엇도 함대를 밸런싱하거나 누가 무엇을 해야 하는지 정하지 않는다. 모델이 누가 있고
  각자 뭘 할 수 있고 얼마나 실렸는지 적힌 목록에서 고르고, 모든 거절은 행동으로 옮길 수 있는 문장이다.
- **메시지 버스.** 띄워 둘 브로커도, 살려 둘 것도, 데몬보다 오래 사는 상태도 없다. 전부 끄면 클러스터는
  한 시간 안에 만료되는 파일 몇 개다.
- **인증.** 유닉스 소켓은 소유자 전용이고, 머신을 건널 때의 경계는 ssh다 — 그 호스트에 그 사용자로
  `ssh`할 수 있는 사람은 이미 magi가 할 수 있는 모든 것을 할 수 있다.
- **합의(consensus).** 멤버십은 가십이고 감쇠한다. 두 머신이 세 번째에 대해 잠시 다를 수 있다. 아래의
  모든 것은 사이팅을 참고로, 거절을 권위로 취급하도록 쓰여 있다.

### 13.12 무엇이 암호화되고 무엇이 아닌가

"에이전트끼리 통신"이라고 하면 네트워크 프로토콜처럼 들리는데 그렇지 않으므로, 분명히 적어 둔다.

| 경로 | 전송 | 암호화 |
|---|---|---|
| 컴패니언 → 컴패니언, 같은 머신 | 유닉스 도메인 소켓, `0600` | **아니오. 그리고 커널 밖으로 나가지 않는다.** 파일이 소유자 전용이라 누가 데몬에게 말할 수 있는지는 연결 시점에 OS가 답한다 |
| 컴패니언 → 컴패니언, 머신 간 | `ssh <host> magi --relay <socket>` | **예 — ssh.** magi는 머신 간에 자기 포트를 열지 않고 선 위에서 자기 프로토콜을 말하지 않는다 |
| 가십(`--join-cluster`, 1분 루프) | `ssh <host> magi --members` | **예 — ssh**, 같은 방식 |
| 귓구멍(`mcp_peers`) | 로컬 서브프로세스 stdio | **아니오. 그리고 머신 밖으로 나가지 않는다** |
| 사람 → 콘솔 | 루프백 평문 HTTP | **아니오.** 자기 터널이나 프록시 뒤에 두라 — 그게 문서화된 접근 방법이다(§12.1) |
| 콘솔 → 콘솔(`-peer`) | 준 URL로 평문 HTTP | **`https://`나 터널을 준 경우에만.** 이것이 유일하게 평문으로 네트워크를 건널 수 있는 홉이고, 트랜스크립트를 실어 나른다 |

즉 magi는 **자기 키도 자기 인증서도 없다**. 일부러 그렇다: 머신을 건널 때의 보안 경계는 ssh이고, 그
호스트에 그 사용자로 `ssh`할 수 있는 사람은 이미 거기서 magi가 할 수 있는 모든 것을 할 수 있다. 그
옆에 두 번째 자격증명 체계를 두면 교체하고, 유출되고, 틀릴 것이 하나 더 늘 뿐 — 첫 번째를 가진
공격자가 할 수 있는 일을 좁히지는 못한다.

조심할 곳은 `-peer` 하나다: ssh가 아닌 유일한 magi-대-magi 링크이고, 에이전트끼리가 아니라
콘솔끼리이며, 사람이 읽는 것을 실어 나른다. 루프백이 아닌 곳에는 터널이나 `https://` URL을 주라.

## 14. 무인 작업 (`schedule`, `[cron]`)

이미 상주 중인 데몬은 타이머로 일할 수 있다. 작업은 설정에 살고, 이름으로 편집할 수 있도록 명명
테이블이다:

```toml
[cron.nightly-audit]
schedule = "0 3 * * *"        # 5필드, 로컬 시각; 또는 @hourly @daily @weekly @monthly
prompt   = "어제 커밋을 훑고 회귀 위험으로 보이는 것을 보고해."
enabled  = true               # 선택; 없으면 켜짐
```

- **데몬 전용.** 대화형 `magi`는 아무것도 스케줄하지 않는다 — 안 그러면 한 저장소에 열린 터미널마다
  같은 작업이 발화한다.
- **발화 1회 = 새 세션 1개.** 살아있는 대화에 끼워 넣는 게 아니라 새 대화로 제출되고, `/resume`과
  콘솔 히스토리에 다른 것과 똑같이 뜬다.
- **밀린 것을 몰아 돌리지 않는다.** 정오에 뜬 데몬은 새벽 3시 작업을 발화하지 않는다. 일주일 자리를
  비웠다고 폭풍이 불면 안 된다.
- **자기 자신과 겹치지 않는다.** 이전 실행이 안 끝난 발화는 사유를 기록하고 건너뛴다.
- **로컬 시각**이고, 서머타임의 결과를 그대로 진다: 반복되는 시각은 두 번 발화할 수 있고 건너뛴 시각은
  발화하지 않는다. 안 그런 척하지 않고 적어 둔다.
- 설정은 매 틱 다시 읽으므로 파일 수정이 재시작 없이 반영된다.

에이전트는 `schedule` 툴로 자기 일정을 보고 바꿀 수 있고, TUI에는 `/cron`이 있고, 콘솔은 컴패니언
상세에 같은 작업을 보여준다(§12.3).

## 15. 상태 & 범위

**루프 엔지니어링 트랙은 계획이 아니라 출하됐다** — 이 툴의 시그니처이며 이 매뉴얼 전반에 기술돼 있다: 에이전트가 종료를 선언하는 상대인 **카운슬**(Melchior·Balthasar·Casper, §3·§6), **Loop map**(`/loop`), 라이브 심의 패널, **rewind/fork/세션-diff**(`/rewind`·`/fork`·`/loopdiff`, §4), **재수화 가능 컴팩션**(§4). 마찬가지로 이미 구현됨: **OS 샌드박스**(`--profile`/`sandbox`, §3), **편집 후 LSP 진단**(§5), **웹 검색**(`websearch`), **프롬프트 캐싱**(`cache_control`, 기본 켜짐 + 자동 폴백). 테스트 예시가 있는 기능/마일스톤 스펙은 [`SPEC.md`](SPEC.md), 내부 구조는 [`ARCHITECTURE.md`](ARCHITECTURE.md)에 있다.

**진짜로 범위 밖(현재).** magi 자체의 계정·세션·권한은 없다: 콘솔은 루프백에 바인딩하고 조직이 이미 쓰는 수단을 통해 접근한다. 회사마다 그 답이 다르고, 그들 문 옆의 두 번째 문은 언제나 더 약하기 때문이다(§12). 자동 컨텍스트 *랭킹*은 임베딩이 아니라 의도적으로 어휘적/결정론적(BM25-lite, §4)이라 벡터-DB 의존이 없다. 이는 채워야 할 갭이 아니라 범위 선택이다.

> 클라이언트다"라고 적고 있었다. `magi-web`(§12)은 데몬이 생긴 이래로 존재했고 머신을 넘어

> 서버도 제공하지 않는다.
