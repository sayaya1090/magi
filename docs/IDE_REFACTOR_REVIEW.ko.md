# IDE UI 작업 이후 구조 검토와 남은 리팩터링

2026-09-15 검토. 범위는 #200 화면 검토 시점인 `d2324213` 이후 변경 파일과 그 연결 경로입니다. 이번 구간의 변경은 VS Code와 Go idebridge에 집중됐고 JetBrains 구현 변경은 없었습니다. JetBrains 전체 구현을 재감사한 결과로 읽지 않습니다. 코드 구조 검토이며 신규 실물 테스트를 실행하지 않았습니다.

답변 상태의 독립 TypeScript 추출, 리터럴 치환, 플랫폼 경로 해석, 파일 이동 추출부의 순환 의존성 해소는 완료된 기반으로 유지합니다. 아래는 그 이후에도 남은 구조 작업입니다. 단순히 파일 길이를 줄이기 위한 분할은 하지 않습니다.

## A. 현재 파일 이동 보완과 함께 처리

### A1. 완료된 기반

`d24b3207`의 출처 검증 공통화와 `9fd43685`의 diff boolean 결과·Ask 타입 보완을 확인했습니다. 이 항목의 추가 구현 요청은 없습니다.

### A2. 요약과 원문을 데이터에서 분리

`askedFor()`의 clip된 문자열은 행 요약용입니다. 상세 자료로 재사용하면 정보가 이미 사라진 뒤입니다. 짧은 표시 문자열과 원문 조회 대상을 분리하고, 상세 열기는 호스트가 보관한 원문을 사용합니다. 도구 인자·결과·승인 자료에 같은 구분을 적용합니다.

본문에 큰 원문을 매 스트림 갱신마다 반복 전송하지 않도록 합니다. 그렇다고 별도 저장 DB를 만들 필요는 없습니다. 현재 이벤트에서 조회하거나 필요한 기간의 스냅샷을 보관하면 됩니다. 긴 인자의 끝부분과 여러 줄 원문 접근을 검증합니다.

## B. 다음 기능 추가 전 별도 커밋

### B1. 완료된 기반: 웹뷰 스크립트를 타입 검사되는 실행 소스로 추출

`HostToWebviewMessage`를 `PaintedRow`, `PanelNoteInfo`, `Activity`, `info` 스키마를 포함하는 판별 유니온으로 엄격히 정의하고 `chat.ts`의 `post(msg: HostToWebviewMessage)`에 연결했습니다. 웹뷰 액션 및 입력 DOM 어댑터(`createWebviewActionAdapter`, `createWebviewInputAdapter`, `dispatchHostMessage`)를 브라우저 TypeScript 소스 `src/web/chat_adapter.ts`로 추출해 완전한 정적 타입 검사를 수행합니다. `tools/build-webview-assets.mjs`를 통해 브라우저 전역 및 Node.js 양방향 번들링 자산으로 연결되어 확장 호스트와 웹뷰 스크립트 간 메시지 계약 정합성을 보장합니다. 단위 테스트 346개와 E2E 하네스 23개 시나리오가 전수 통과했습니다.

### B2. 자동완성 요청 수명 분리

`suggestReqId`, `typing`, `suggestion`, `mentions`, 입력 대상 비교와 초기화가 웹뷰에 남아 있습니다. 입력 수정·모드 전환·제출·세션 변경을 하나의 무효화 경로로 모읍니다. 타이머와 결과 수락 판정만 작은 컨트롤러로 추출합니다.

답변 상태 모듈에 자동완성 네트워크를 넣지 않습니다. 입력 대상과 입력 버전을 전달하고 유효한 결과만 화면에 반영합니다. 일반 입력의 세션 변경도 별도 문맥 변경으로 다룹니다. 늦은 결과, 연속 입력, 모드 전환, 제출 후 Tab을 기존 하네스로 검증합니다.

## C. 테스트 구조를 실제 경로에 맞춤

`transcript-test.mjs`는 약 900줄의 연속 시나리오이며 `chat.ts`의 문자열 일부를 잘라 `new Function`으로 HTML을 얻습니다. 파일 구조 변경에 취약하고, 여러 사례가 앞선 입력 상태를 이어받습니다. B1과 함께 배포용 HTML 생성 함수 또는 실제 생성 자산을 하네스가 읽도록 바꿉니다.

테스트는 요청 상태·파일 이동·diff·레이아웃 묶음으로 나누고 필요한 시작 상태를 각 묶음에서 만듭니다. 브라우저 실행까지 매번 복제할 필요는 없습니다. 기존 사용자 동작 단언을 유지합니다.

캐시 순수 테스트와 provider/IDE 연결 테스트를 구분합니다. 임의 isPinned 콜백을 바꾼 테스트는 실제 탭 종료 구독을 검증하지 않습니다. provider 등록·두 면 열기·실패 finally·문서 종료·dispose는 호스트 어댑터 수준에서 확인합니다. 실제 VS Code 실행은 별도 증거로 보고합니다.

Go `FileNav` 필드 선언과 필드명 검사만으로 TypeScript와 출력 동등성이 검증됐다고 하지 않습니다. 실제 Go 생산 경로를 연결할 필요가 있는지 먼저 결정하고, 연결한다면 공통 이벤트 fixture에서 값을 비교합니다. 쓰이지 않는 선언을 동등성의 근거로 유지하지 않습니다.

## D. 당장 기능을 막지는 않지만 정리할 수명 규칙

`answer_state.ts`의 `failedDrafts`·`draftVersions`·질문별 초안에는 종료 요청 정리 정책이 명확하지 않습니다. 실패 초안을 사용자가 다시 볼 수 있는 경로와 보관 기간을 정한 뒤 정리합니다. 오래됐다는 이유만으로 미전송 답변을 조용히 삭제하지 않습니다. 이 부분은 동작 결정이 필요하므로 단순 추출 커밋과 분리합니다.

`getInFlight()`는 내부 객체를 반환하고 `getState()`의 중첩 객체는 얕게 복사합니다. 외부에서 상태를 수정할 필요가 없다면 readonly 반환 계약 또는 방어적 복사로 상태 소유권을 지킵니다. 실제 호출자가 필요한 조회만 남기고 테스트 편의용 공개 API를 늘리지 않습니다.

캐시의 항목 수 제한과 메모리 바이트 제한은 다릅니다. 큰 승인 자료를 장시간 보관하는 운영 문제가 확인되면 바이트 예산을 도입합니다. 열린 자료와 미전송 초안의 보호 요구를 먼저 정의하며, 이번 단계에 범용 캐시 프레임워크를 추가하지 않습니다.
