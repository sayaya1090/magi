# 연결 복구

일시적인 연결 단절 때문에 개발자가 작업을 다시 보내지 않아야 합니다. 복구는 저장된 진행 상태를 유지합니다. 영구적인 장애 중에도 완료를 보장하는 것은 아닙니다.

| 중단 상황 | 동작 |
|---|---|
| 출력 전 재시도 가능한 API 오류 | 코어가 지터를 적용한 대기 후 요청을 재시도하고 `Retry-After`를 따릅니다. 기본 한도는 단계마다 재시도 6회, 누적 대기 3분입니다. 서버가 요구한 대기가 남은 예산보다 길면 조기에 재요청하지 않고 중단합니다. |
| 부분 출력 후 연결 단절 | 코어가 받은 내용을 저장하고 이어 쓰기 안내를 추가해 다음 응답을 요청합니다. 출력 이후의 일시적인 네트워크·타임아웃·과부하 오류도 이 경로를 사용합니다. |
| 완료된 도구 호출 없이 부분 응답 중단 반복 | 최대 6회 이어서 요청합니다. 일곱 번째 응답도 중단되면 명시적인 오류로 끝내고 저장된 진행 상태를 유지합니다. |
| 연결 단절 전 완성된 도구 호출 수신 | 일반 실행 경로에서 호출을 처리하고 결과를 저장합니다. 복구가 원래 요청을 재실행하지 않습니다. 미완성 도구 호출을 완성된 호출로 취급해서는 안 됩니다. |
| IDE 전사 연결 종료 | 데몬 작업은 연결과 별도의 수명을 가집니다. JetBrains는 백오프 후 마지막 영속 이벤트 순번으로 재접속하고, 데몬은 이후 이벤트를 재생합니다. 재접속은 작업을 다시 제출하지 않습니다. |
| 종료 또는 업데이트 대기 | 새 `Submit`·`Steer` 요청은 메시지를 저장하기 전에 거절합니다. 종료는 이미 접수된 메시지 저장을 종료 기한 안에서 기다립니다. 그 저장 중에는 업데이트가 유휴 상태를 확보할 수 없습니다. |

인증 실패, 권한 실패, 할당량 소진과 사용자 취소는 자동 재시도로 바꾸지 않습니다. 외부 작업이 실행됐을 가능성이 있지만 결과를 모르면 영향을 확인한 뒤 반복해야 합니다. 임의의 외부 서비스나 프로세스 충돌까지 포함하는 정확히 한 번 실행을 보장하지는 않습니다.

## 검증

`internal/adapter/daemon/connection_recovery_test.go`는 실제 HTTP 어댑터와 데몬 소켓을 사용합니다. HTTP 응답을 잘라 다음 요청에 저장된 부분 응답이 포함되는지 확인하고, 그 요청이 진행되는 동안 IDE 소켓을 끊은 뒤 영속 커서로 재접속합니다. 최종 답변 수신, 사용자 요청 1개, 모델 요청 2회, 영속 이벤트 중복 없음이 통과 조건입니다.

`internal/app/cut_by_lost_stream_test.go`는 부분 출력 후 복구, 반복 단절 한도, 완성된 쓰기 호출의 1회 실행을 검증합니다. `prompt_admission_test.go`는 종료·업데이트 중 접수 거절과 이미 접수한 저장의 종료 대기를 검증합니다. JetBrains `TranscriptTest`는 커서 직렬화와 통신 실패·명시적인 닫기 구분을 검증하며, UI 재접속 루프는 `MagiToolWindow.reattach`에 있습니다.

통제된 장애 주입 검사입니다. 모든 프록시·원격 모델 서비스·IDE 설치 환경의 복구를 입증한 것은 아닙니다.
