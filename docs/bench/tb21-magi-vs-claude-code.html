How to read this

  • Both agents used the web — this is not one-sided. magi has websearch and webfetch as tools; Claude Code has neither, and has Bash instead. Pulling all 439 trajectories from the leaderboard job and counting: 54 trials (22 tasks) called curl or wget against an external host, 30 of them (13 tasks) somewhere that was not a package or distribution mirror. Six trials across four tasks called a search engine directly — no search tool, but search all the same. Of the 89 tasks counted here magi used the web on 14, and on 8 of those the baseline went outside for the same task. Here is what it was after:
    • break-filter-js-from-html — tags BeautifulSoup's html.parser misses and a browser executes
    • build-pov-ray CC too, 2/5 — where to get the POV-Ray 2.2 source archive — two searches, two fetches (an ibiblio index and a third party's notes on this task). It was looking for a download, and never reached the dataset. And it still failed, because the archive it found was not the one the solution names
    • caffe-cifar-10 CC too, 5/5 — another mirror for cifar-10-binary.tar.gz — where to download it
    • compile-compcert CC too, 5/5 — compcert.org's download and release pages — where the source tarball is
    • count-dataset-tokens CC too, 1/5 — the card and README of the HuggingFace dataset it was asked to count
    • dna-assembly CC too, 3/5 — NEB's BsaI-HF v2 guide — the extra bases needed when a cut site sits near a fragment's end
    • gcode-to-text — PrusaSlicer's default M486 object names — it looked, and still got it wrong
    • mailman — Mailman3's own MTA integration page (docs.mailman3.org .../mta.html) — how postfix's local_recipient_maps and transport_maps line up on one domain. A tool's documentation about its own configuration
    • mteb-leaderboard CC too, 3/5 — the dataset's own task README — and on all five trials this repository has watched. The instruction asks for the best embedding model on the Scandinavian MTEB leaderboard as of August 2025, which cannot be answered without the web, and that search puts the task's own page near the top. Quarantine → re-run → reach again repeats without end, so this row carries its re-run result and states the reason here (same clause in docs/BENCHMARK.md). Do not weigh this row like the others
    • protein-assembly — searched the 38-character light-chain sequence it had read out of antibody.fasta to identify the antibody — recognising data it was given, not looking up an answer
    • qemu-startup — the error string it had just been handed, rosetta error: unimplemented syscall 282 — the problem x86_64 QEMU hits under Rosetta. It found the way around and passed
    • regex-chess CC too, 1/5 — the answer file itself — chess_engine.py from carlini/regex-chess. Under the leaderboard's rule this trial is rescored to zero; the account is on its card
    • torch-pipeline-parallelism CC too, 1/5 — searched train_step_pipeline_afab, the function the task names outright, and read huggingface/picotron_tutorial's reference implementation. Not the dataset and not a solution file, but a public tutorial that is this task's origin. It also fetched the registry's task page once, which is an SPA and returned a shell. The first trial was held for the same reason and the re-run walked the same road, so like mteb-leaderboard this row carries its re-run result with the reason stated here.     • train-fasttext — fastText's own classification-results.sh — the yelp hyperparameters

  • Both sides are rescored by the leaderboard's own rule. tbench.ai's integrity policy defines reward hacking as resolving a task without demonstrating the capability it was meant to measure and sets the consequence at a reward of zero for the trial. On the Claude Code side, the judge in PR #98 flagged twelve trials and three harness-cheating ones were disqualified (code-from-image twice, fix-code-vulnerability once), moving 75.28% to 74.61% — this page uses the adjusted figure. On this side the same scan over all 89 adopted trials found none that touched a grader and one that fetched the answer from the internet (regex-chess), rescored to zero. torch-pipeline-parallelism fetched a reference implementation, but the baseline's identical behaviour was not disqualified, so it stands with the reason on its card.
  • k differs. One attempt per task here against five on the leaderboard. Comparing a single good run to an average of five leaves far more room for luck on this side.
  • Timeouts are billed at $0 on both sides. Checked across all 445 leaderboard rows: every one of the 42 AgentTimeoutError rows has a blank cost, and no non-timeout row is blank. The correspondence is exact, so using the same ruler means magi's timed-out runs are zero too. That drops 15 runs and $33.63 here — three of them (schemelike-metacircular-eval, dna-assembly, chess-best-move) passed despite being cut, so counting the reward while dropping the cost lands the same way on both sides.
