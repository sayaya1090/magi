# 컨텍스트 조립 구조 검토와 리팩토링 설계

상태: 1~4단계 구현 및 자동 검증 완료. 검토 기준: `d6cfed8f` (2026-09-28). [English](CONTEXT_ASSEMBLY_DESIGN.md)

## 1. 결론과 범위

공통 인터페이스는 이미 있습니다. `port.ContextProvider`는 검색 결과를 주입하는 확장 지점입니다. 툴·스킬·메모리 전체를 통합하는 추상클래스를 새로 만드는 것은 기존 구조와 중복됩니다. Go 인터페이스와 값 타입으로 **조립되는 항목의 계약**을 명시하고 기존 확장 지점을 연결합니다.

이번 설계의 대상은 모델 요청을 만드는 앱 계층입니다. 도구 실행·권한 검사, 메모리 저장소, 스킬 파일 형식, 모델 어댑터의 메시지 역할은 유지합니다. 일반적인 프레임워크나 플러그인 API 교체는 포함하지 않습니다.

먼저 동작을 보존하며 구조를 분리합니다. 다음 단계에서 실제 도구 목록에 따른 안내 생성과 출처 추적을 추가합니다. 토큰 예산 최적화·자동 중복 제거·신뢰 수준에 따른 역할 재배치는 별도 변경으로 남깁니다.

## 2. 이미 구현된 구조

| 구성 | 코드 근거 | 현재 계약 |
|---|---|---|
| 검색형 컨텍스트 확장 | `internal/port/port.go`: ContextProvider, ContextQuery, ContextChunk | Provide(ctx, query), Source/Text 반환 |
| 등록·수집 | `internal/app/app_plugin_api.go`: RegisterContextProvider, gatherContext | 등록 순서로 수집, 공급자별 5초 context timeout, 실패 건너뜀, 출력 길이 제한 |

따라서 조립 진입점과 캐시는 이미 존재합니다. 부족한 부분은 항목별 식별·출처·배치 계약과 실제 요청 도구 목록에 대한 안내의 의존성을 한곳에서 검토할 수 있는 구조입니다.

## 3. 확인된 주의점

1. `ContextProvider`는 검색용입니다. 프로젝트 지침, 도구 스키마, 대화 이벤트까지 그 인터페이스로 밀어 넣지 않습니다.
2. `gatherContext`의 8000 제한은 주석의 문자 수 표현과 달리 Go 문자열의 **바이트 수**입니다. 문자열 슬라이싱은 UTF-8 중간을 자를 수 있습니다. 수정은 구조 변경과 분리해 시험합니다.
3. 5초 timeout은 공급자가 context 취소에 협조해야 작동합니다. 비협조 공급자를 확실히 종료한다고 문서화하지 않습니다. 공급자는 현재 순차 호출되므로 전체 지연은 공급자 수에 따라 늘 수 있습니다.
4. `volatileContext` 주석의 RAG 최상위 전용 설명과 달리 함수 내부에는 해당 분기가 보이지 않습니다. 호출 범위와 테스트로 실제 동작을 고정한 후 주석을 바로잡습니다. 리팩토링 중 임의로 필터를 추가하지 않습니다.
5. 회상 안내 일부는 `agent.allows`를 확인하지만 실제 요청의 고정된 도구 배열을 확인하지 않습니다. 스킬 도착 알림도 별도 경로입니다. 권한 허용과 실제 등록은 구분해야 합니다.
6. Office 기본 지침과 번들 스킬도 컨텍스트의 입력입니다. `SeedInstructions`는 기존 비어 있지 않은 지침을 덮어쓰지 않습니다. 코드 변경만으로 기존 설치의 오래된 지침까지 사라지지는 않습니다.

## 4. 설계 결정

### 4.1 앱 내부 값 타입

새 파일 `internal/app/context_fragment.go`에 비공개 타입을 둡니다. 첫 단계에서는 외부 포트를 변경하지 않습니다.

```go
type contextFragment struct {
    id       string // 앱이 부여하는 안정적 식별자
    source   string // 생성 경로; 모델 본문에 자동 노출하지 않음
    text     string // 기존 헤더와 공백까지 포함한 본문
    lane     contextLane
    requires []string // 생성 안내가 요구하는 실제 도구 이름
}
```

`contextLane`은 `turnSystem`, `volatileStable`, `volatileRun`, `volatileClock` 네 값입니다. 세션 고정 스킬 목록은 기존 `skillBlockFor`가 관리하고 그 결과를 turnSystem에 넣습니다. 기록으로 남기는 도착 알림은 조립기에서 생성하지 않습니다.

식별자는 `system/project-memory`, `system/agent`, `tail/plan`, `tail/retrieved/<등록순번>/<청크순번>`처럼 앱에서 부여합니다. 플러그인의 Source는 표시 출처이며 고유키나 권한 근거가 아닙니다. 같은 출처의 다른 청크를 자동 제거하지 않습니다.

### 4.2 순수 조립 함수와 기존 제공자

`internal/app/context_assembly.go`에 항목을 순서대로 결합하는 순수 함수를 둡니다. 파일 읽기·검색·이벤트 기록·도구 실행·캐시 갱신은 하지 않습니다. 초기 버전은 우선순위 정렬 없이 전달받은 순서를 보존합니다.

기존 `systemFor`와 `volatileContext`는 자료 수집을 담당하고 항목을 조립기로 넘깁니다. 작은 공급자마다 클래스를 만들지 않습니다. `gatherContext`의 기존 ContextChunk를 앱 내부 항목으로 변환하는 어댑터만 추가합니다. 기존 Provide 시그니처와 Lua 등록 API는 유지합니다.

```text
기존 자료 읽기·검색 ──> contextFragment[] ──> 순수 조립 ──> 기존 고정/변동 경로
기존 sessionToolSpecs ────────────────────────────────> ChatRequest.Tools
기존 이벤트 재구성·압축 ──────────────────────────────> ChatRequest.Messages
```

도구는 문자열 항목으로 바꾸지 않습니다. 실행 가능 판단에는 요청에 실리는 `[]port.ToolSpec`의 정확한 Name 집합을 사용합니다. 별도 목록을 재검색하거나 설정의 enabled 값만으로 판단하지 않습니다.

### 4.3 고정 수명과 부작용 보존

- `stepSystemFor`와 `sessionToolSpecs`를 고정 상태의 유일한 진입점으로 유지합니다.
- 사용량 조회는 고정을 시작하지 않습니다. `context_state.go`의 조회가 도구 연결 전에 빈 목록을 고정하지 않도록 기존 테스트를 유지합니다.
- 턴 안에서 프로젝트 지침·언어·스킬 수정 때문에 접두부가 달라지지 않게 합니다.
- 도구 목록은 세션·에이전트별 기존 키와 수명을 유지합니다. 새 도구는 다음 세션에 반영한다는 현재 계약을 변경하지 않습니다.
- 도착 알림과 메모리 도착 큐 소비는 `buildStepRequest`에 남깁니다. 압축으로 조립을 다시 실행해도 이벤트가 두 번 기록되지 않아야 합니다.
- 일시적 컨텍스트는 기존 마지막 user-role 메시지에 남고 이벤트 로그에는 저장하지 않습니다. 역할과 신뢰 정책을 이번 리팩토링에 섞지 않습니다.

### 4.4 실제 도구 목록과 안내의 일치

구조 분리 이후 `buildStepRequest`에서 기존 `sessionToolSpecs`를 한 번 확보하고 동일한 스냅샷을 안내 생성과 최종 요청에 사용합니다. 이 호출을 앞당기는 변경은 초기 연결·고정 시점 회귀 검증을 별도로 수행합니다. 호출 순서가 안전하지 않으면 먼저 읽기 전용 수집을 추가하는 대신 단계 전체를 보류하고 연결 순서를 조사합니다.

앱이 생성하는 스킬 로딩 안내는 `skill`, 메모리 안내는 `recall_memory`, 압축 문맥 안내는 `recall_context`가 실제 목록에 있을 때만 넣습니다. 도착 알림에도 같은 조건을 적용하며, 빠진 안내는 진단 사유로만 남깁니다. 사용자 작성 지침이나 검색 결과를 정규식으로 삭제하지 않습니다.

완료 안내는 정확한 도구 이름과 계약을 알고 있는 생성 경로에서만 만듭니다. 해당 목록에 `council`이 없으면 호출을 요구하지 않습니다. `land`도 실제 목록에 있을 때만 안내하고 둘 다 없으면 일반 결과 보고를 안내합니다. 임의의 MCP 이름을 접미사만 보고 완료 도구로 취급하지 않습니다.

이 조립기는 자연어 지침의 모든 모순을 자동으로 해결하지 못합니다. Office의 오래된 사용자 지침은 별도 마이그레이션 또는 사용자가 검토할 갱신 안내가 필요하며, 자동 덮어쓰기는 범위 밖입니다.

### 4.5 예산·진단·출처

첫 단계는 기존 각 경로의 제한과 순서를 그대로 보존합니다. UTF-8 안전 절단은 후속 수정에서 8000 **바이트** 상한을 유지하며 마지막 완전한 코드포인트까지만 반환합니다. 생략 표시를 넣는다면 그 바이트도 상한에 포함합니다.

진단에는 id, lane, 바이트 수, included/skipped/truncated 상태와 `missing_tool` 등 사유만 담습니다. 본문·파일 절대 경로·검색 질의를 기본 로그에 남기지 않습니다. 기존 PromptShape 이벤트 스키마와 UI 집계를 변경하지 않습니다. 출처 메타데이터는 진단용이며 system 권한이나 신뢰를 부여하지 않습니다.

## 5. 순차 구현 지시

| 단계 | 수정 범위 | 완료 조건 |
|---|---|---|
| 1. 기준 고정 | 앱 테스트만 | 고정/변동 본문, 도구 명세, 메시지 역할·순서를 캡처. 시계·검색을 고정한 재현 입력 사용 |
| 2. 구조 분리 | context_fragment.go, context_assembly.go, prompt.go, 필요 시 app_plugin_api.go | 기존 결과와 바이트 단위 동일. 기존 캐시·포트·이벤트·압축 동작 유지 |
| 3. 실행 가능 안내 | loop.go, prompt.go, 안내 관련 테스트 | 하나의 고정 도구 스냅샷으로 안내와 Tools 구성. 제한 에이전트·세션별 소유권·완료 도구 없음 검증 |
| 4. 제한·진단 | app_plugin_api.go 및 조립 테스트 | 한글·이모지 경계에서 유효 UTF-8, 상한 유지, 출처별 누락 사유 확인 |

단계별 커밋으로 나눕니다. 2단계까지는 동작 보존 리팩토링, 3~4단계는 명시적인 동작 수정입니다. 구현자는 토큰 정책·신뢰 정책·플러그인 API를 추가 설계하지 않습니다. 예상과 다른 경로를 발견하면 해당 근거와 영향을 먼저 기록합니다.

## 6. 검증과 인수 기준

기존 `prompt_one_door_test.go`, `skill_head_frozen_test.go`, `retrieval_cache_test.go`, `context_provider_test.go`, `allowlist_advert_test.go`, 메모리·압축 테스트를 유지합니다. 테스트를 지우거나 기대값을 일괄 갱신해 동등성을 통과시키지 않습니다.

추가 시나리오는 다음과 같습니다.

- 같은 턴 2개 요청의 시스템·도구 배열 동일, 변동 꼬리만 변경.
- 다음 턴에 프로젝트 지침 변경 반영, 도구 스냅샷은 기존 세션 계약 유지.
- 서로 다른 에이전트·소유 세션 간 도구와 회상 안내 누출 없음.
- 설정은 켜졌지만 요청 목록에 완료 도구가 없는 경우에도 호출 안내 없음.
- 압축 전후 일회성 알림 소비·이벤트 기록 중복 없음.
- RAG 실패·빈 결과 캐시·등록 후 무효화·공급자 순서 보존.
- 제한 경계의 한글·이모지·중복 Source, 취소 협조 공급자 확인.
- 언어 선택과 사용자 지침 본문을 항목 분리가 임의로 수정하지 않음.

구현 단계마다 영향받은 테스트를 실행하고 최종으로 `go test ./internal/app ./internal/adapter/plugin/lua ./internal/arch`, `go test -race ./internal/app`, `go test ./clients/office/helper/...`를 실행합니다. Playwright는 `node clients/vscode/tools/transcript-test.mjs`를 항상 실행하고 결과를 기록합니다. 구현 후 앱·Lua·계층·Office 테스트, 앱 race 검사, Playwright 7개 실행이 통과했습니다. 서브에이전트 리뷰에서 발견한 진단 누락과 정체 안내 반복 문제를 보완하고 관련 테스트를 재실행했습니다. 실물 Office·IDE 검증과 자동 테스트 결과를 구분합니다.

## 7. 구현 결과와 남은 범위

기준 테스트는 `34497294`, 조립 분리는 `19db9858`에 분리했습니다. 실제 요청의 고정 도구 목록을 스킬·회상·완료 안내에 연결하고 UTF-8 안전 절단을 적용했습니다. `contextDiagnostics`는 앱 내부 조회용이며 별도 공개 API나 UI는 추가하지 않았습니다. 시스템 항목·변동 항목·RAG와 도착 안내 제외 사유를 본문 없이 반환합니다.

기존 사용자 지침 마이그레이션, 자연어 모순 자동 해결, 토큰 정책 변경, 플러그인 API 교체는 하지 않았습니다. 실물 Office·IDE 인수는 이번 코어 리팩토링의 자동 검증 결과에 포함하지 않습니다.
