# 카운슬 증거 준비와 최종 보고

카운슬은 매번 입력 전체를 새로 구성하지 않으면서 최신 증거를 검토해야 합니다. 승인 뒤 주 모델이 최종 보고를 반복하는 경로도 정리합니다. 이 변경은 캐시 적중을 보장하거나 패널의 후속 최종 판단 호출을 없애지는 않습니다.

## 최종 보고 계약

사용자에게 전달할 보고를 먼저 작성한 뒤 `council{complete:true}`를 호출합니다. `report_ready` 기본값은 true입니다. 승인하면 기존 종료 검사를 거쳐 `turn.finished`를 기록하고 주 모델을 다시 호출하지 않습니다. 보고 길이는 판정 기준이 아닙니다. 이번 턴에 assistant 보고가 전혀 없으면 승인 뒤 마무리 답변을 한 번 생성합니다. 기존 내용이 최종 답변이 아니라면 `report_ready:false`를 명시합니다. 거부되면 추가 작업을 진행합니다. 종료 훅·새로 도착한 하위 작업 결과·기존 종료 검사는 승인 뒤에도 작업을 다시 열 수 있습니다.

## 공통 증거 접두부

`councilPrefix`는 이번 턴의 저장된 이벤트로 시간순 기록을 구성합니다. 사용자 요청, 인자가 연결된 도구 결과, assistant 주장, 계획 변경, 이전 카운슬 판단을 포함합니다. 새 이벤트는 기존 항목 뒤에 붙습니다. 이전 판단은 실행 증거와 구분해서 표시합니다. 기록 뒤에는 현재 검토 자료를 붙이며, 최신 워크스페이스 관측·미해결 지적·최종 보고도 계속 전달합니다. 현재 관측은 과거 상태보다 우선합니다.

기록 상한은 64 KiB이며 항목마다 최대 4,000바이트를 보존합니다. 상한을 넘으면 가장 오래된 항목을 제거하므로 캐시 접두부도 변경됩니다. 새 턴에서는 기록을 새로 시작합니다. 모든 위원은 같은 최소 시스템 지침을 사용하고, 상세 판단 지침은 현재 검토 자료 뒤에 붙입니다. 패널의 후속 최종 판단 호출도 최초 대화를 유지합니다. 모델이 다르면 KV 상태를 공유할 수 없고, 다음 호출까지 접두부가 남는지는 백엔드 보존 정책에 달려 있습니다.

## 백그라운드 준비

명시적 캐시 경계를 지원하는 게이트웨이에는 판단 요청의 증거 접두부 끝에 `cache_control`을 지정합니다. 뒤에 붙는 최신 검토 자료는 이 경계 밖에 두며, 캐시를 끄면 원래 문자열 메시지를 그대로 전달합니다.

최상위 턴마다 작업자 하나가 이벤트 저장 뒤 알림을 받습니다. 워크플로 턴에는 생성하지 않습니다. 알림을 100ms 동안 묶어 최신 접두부를 준비하며, 요청 제한 시간은 30초입니다. 모델이 빌드·테스트 도구를 실행하면 모델이 쉬는 동안 이전 증거를 준비할 수 있습니다. 해당 빌드 결과는 결과가 나온 뒤에만 준비할 수 있습니다. 준비 작업은 답변을 생성하거나 판단을 기록하지 않으며, 완료를 가로막지도 않습니다. 지원하지 않는 제공자는 `ErrCapabilityAbsent`를 반환하고 일반 생성 요청으로 대체하지 않습니다.

`MAGI_COUNCIL_PREFILL` 기본값은 `auto`입니다. 읽기 전용 `/props` 요청으로 전용 서버 속성(`total_slots`, `chat_template`, `default_generation_settings`)을 확인합니다. 지원하지 않는 게이트웨이에는 예열용 completion 요청을 보내지 않습니다. 탐지 결과는 엔드포인트별로 재사용합니다. `off` 또는 `0`이면 예열 API 요청을 끄고, `llama.cpp`면 탐지 없이 전용 API를 지정합니다. `-no-cache`도 전용 예열을 끕니다. 명시적 전용 모드는 영향을 받는 모든 제공자가 호환 llama-server이고 채팅 엔드포인트와 같은 템플릿을 사용할 때만 사용합니다. 전용 API가 없는 Ollama와 호스팅 OpenAI 호환 게이트웨이는 건너뜁니다.

전용 경로는 `/apply-template`과 `/completion`을 사용합니다. 서버의 채팅 템플릿으로 입력을 구성하되, 증거 메시지 뒤의 역할 종료 표식 전에 접두부를 끊습니다. 요청은 `n_predict:0`, `cache_prompt:true`, `stream:false`를 사용합니다. 생성된 내용이 응답에 있으면 오류로 처리합니다.

`MAGI_COUNCIL_PREFILL_PREEMPT` 기본값은 `0`입니다. 진행 중인 예열은 끝까지 유지하되 새 예열은 전경 요청이 끝날 때까지 기다립니다. 공유 자원 때문에 남은 예열이 주 모델을 지연시킨다면 `1`로 지정합니다. 이때는 같은 클라이언트의 전경 요청이 예열을 취소합니다. 이미 처리한 계산 비용은 되돌아오지 않으며 부분 KV 상태 보존은 서버에 달려 있습니다. 어느 정책도 다른 클라이언트·프로세스·서버 스케줄링·캐시 축출까지 제어하지는 못합니다. 같은 접두부의 반복 준비는 생략하고, 사용 중인 제공자는 250ms 뒤 다시 시도합니다. 턴을 취소하면 작업자도 종료합니다.

## 검증과 측정

HTTP 계약 테스트는 생성 없는 요청, 템플릿 접미부 제거, 전경 요청의 취소 동작을 검사합니다. 카운슬 어댑터 테스트는 준비한 접두부를 실제 판단 요청과 후속 최종 판단 호출에 대조합니다. 코어 테스트는 시간순 판단 기록, 턴 격리, 짧은 최종 보고의 추가 모델 호출 없는 종료를 검사합니다. 이 테스트가 실제 모델의 캐시 적중이나 속도 향상을 입증하는 것은 아닙니다.

카운슬 스트림 로그에는 첫 토큰 대기, 전체 소요 시간, 제공자가 보고한 캐시 토큰 수를 남깁니다. 첫 토큰 대기에는 네트워크와 큐 대기도 포함되므로 순수 프리필 시간과 같지 않습니다. 지연 개선을 주장하기 전에 실제 백엔드에서 이 수치를 비교합니다. 이 경로를 수정할 때는 Go 검사와 함께 Playwright 전체 전사 하네스를 실행합니다.
