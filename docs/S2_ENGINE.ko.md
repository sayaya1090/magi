# S² Engine: 로컬 실험과 기억 전달

[English](S2_ENGINE.md) · [한국어](S2_ENGINE.ko.md) · [문서 지도](README.ko.md)

상태: 고정 검증·반복 실험·제어된 재사용을 구현했습니다. 결정적 테스트로 실제 플러그인, 호스트 스냅샷과 기억 전달을 검증합니다. 모델의 작업 성능 향상을 입증하는 결과는 아닙니다.

## 설치와 실행

`plugins/s2-engine`은 선택적으로 설치하는 Lua 플러그인입니다. 바이너리에 번들하거나 자동 설치하지 않습니다. `go build -o /tmp/magi-s2-engine ./cmd/magi`로 갱신된 코어를 빌드합니다. 플러그인 디렉터리를 사용자 플러그인 경로에 복사하거나, 이 플러그인만 포함한 부모 디렉터리를 `--plugins <directory>`에 지정합니다. 저장소의 `plugins` 전체를 지정하면 다른 플러그인도 함께 로드됩니다.

`/subagents`에서 `s2_compare`를 활성화하고 새 대화를 시작해 고정 도구 목록에 반영합니다. 로컬 코딩 작업의 비교 실험을 명시적으로 요청합니다. 인자 예시는 다음과 같습니다.

```json
{"task":"파서의 빈 필드 처리를 수정하고 테스트를 실행합니다","guidance":"파서를 수정하기 전에 기존 파서 테스트를 읽습니다","max_steps":20,"timeout":300}
```

기존 `harness-lab` 설정은 대응하는 `s2_*` 도구의 호환 별칭으로 읽으며 새 저장은 S² Engine 이름만 사용합니다.

두 실행은 같은 작업, 도구, 스텝 수와 제한 시간을 받습니다. `guidance`를 생략하면 기준 실행의 근거로 수정안을 제안합니다. `proposal_attempts`로 제안 보정을 1~3회로 제한하며 중복·무효 제안은 버리고 실행할 제안과 시도를 보고서에 기록합니다. 이는 제한된 보정 루프이며 성공 점수를 생성하지 않습니다. 서로 다른 제안이 여러 개 나오고 고정 검증기가 있으면 순서대로 실행해 처음 통과한 후보에서 멈추며 모든 후보 실행과 `selection_rule=first independent verifier pass; no generated score`를 보고서에 남깁니다. 검증기가 없으면 첫 후보만 실행하고 정성 검토를 참고로 유지합니다. 제안이 `null`이면 기준안을 유지하고 `unchanged`를 기록합니다. 선택 항목 `hypothesis`에는 예상하는 행동 차이를 씁니다. `prior_report`에는 같은 작업공간의 이전 비교 보고서 ID를 지정할 수 있습니다. 해당 기록은 확정되지 않은 근거로 제안 단계에 전달됩니다.

## 실행과 책임

```mermaid
flowchart LR
    A[명시적 요청] --> B[호스트가 초기 트리 고정]
    B --> C[기준안 체크아웃]
    C --> D[후보 지침]
    D --> E[같은 트리에서 후보 체크아웃]
    E --> F[기록된 근거 비교]
    F --> G[로컬 보고서 저장]
```

플러그인은 제안·비교 정책을 담당합니다. 체크포인트 분기 없는 기존 `magi.spawn{trial=true}`는 도구 호출 하나에 공통 소스 스냅샷, 별도 Git 클론과 전용 임시공간을 제공합니다. 소스 트리 해시와 실행 모델·프로바이더를 반환합니다. 도구가 반환하면 공통 소스를 정리하고 실험 체크아웃은 검사할 수 있도록 남깁니다. 실험 결과는 `merge_child`로 병합할 수 없습니다.

실험마다 지침 블록 하나를 바꿉니다. 도구 목록 변경, 생성된 플러그인 설치와 여러 후보의 재귀 탐색은 하지 않습니다. 실험 도구는 `read`, `grep`, `glob`, `list`, `write`, `edit`, `multiedit`, `bash`로 제한합니다. 실행 중인 플러그인의 문맥 제공과 공유 기억 조회는 제외합니다. 전역·프로젝트 AGENTS 지침은 한 번 확보합니다. 명시적 백그라운드 bash 요청은 거절하고, 지원하는 OS 샌드박스에서는 네트워크 허용을 끕니다. 기존 거부 규칙과 승인 정책은 유지합니다. 실험 셸에는 강제 가능한 OS 샌드박스가 필요하며 공유 캐시 쓰기와 Git 메타데이터 변경을 허용하지 않습니다. 지원되지 않는 플랫폼에서는 비격리 실행으로 넘어가지 않고 셸 실행을 거절합니다. 수명주기 훅은 아직 분기 제한을 상속하지 않으므로 훅이 설정된 환경에서는 실험을 거절합니다.

체크아웃 입력을 격리하며 운영체제 전체를 복제하는 기능은 아닙니다. 강제 샌드박스가 없는 플랫폼에서는 셸 명령의 외부 효과가 남을 수 있습니다. 배포·계정 조작·실제 Office나 브라우저 작업을 반복하는 용도로 사용하지 않습니다. 의존성과 Git이 무시하는 빌드 결과는 복사하지 않으므로 각 체크아웃에서 준비가 필요할 수 있습니다. 외부 서비스나 사용자의 동시 편집을 원자적으로 복제하는 실험은 아닙니다.

## 근거와 결과

보고서에는 작업 원문, 지침 변경, 가설, 스냅샷, 모델·프로바이더, 커밋 범위, 도구 근거, 스텝 수, 제한과 시작·종료 시각을 남깁니다. 보고서 ID는 난수입니다. `s2_report{"id":"<보고서 ID>"}`로 현재 작업공간의 보고서를 읽습니다. 기존 로컬 플러그인 저장소에 보관하며 다른 작업공간의 보고서는 읽지 않습니다. 공유 기억으로 자동 게시하지 않습니다. 실행·분석의 프로바이더 보고 입력·출력·캐시 토큰, 호출 수와 경과 밀리초를 기록합니다. 사용량 누락 시 `tokens_known=false`로 표시하고 부분 합계는 보존합니다. 금전 비용은 `unknown`입니다.

비교는 `baseline`, `candidate`, `inconclusive`와 관측 효과의 주장을 반환합니다. 보고서의 `attribution=confounded`, `verified=false`는 항상 유지합니다. 한 쌍의 실행으로 인과관계와 다른 작업에서의 효과를 확정할 수 없기 때문입니다. 근거가 잘렸으면 미확정으로 처리합니다. 도구 기록 누락, 스냅샷·모델 불일치, 잘못된 판정, 실행 오류와 예산 소진은 미완료 보고서로 남깁니다. 비교 선호로 스킬을 승격하지 않습니다. 채택 전에는 반복 실행과 별도의 작업으로 검증합니다.

Engram은 작업공간별 최근 학습 근거를 최대 100개 보관합니다. `/engram-evidence`는 최근 10개의 변경, 대화 근거 주장, 출처와 호스트 결과를 보여줍니다. 귀속은 항상 `confounded`이며 분석 모델이 바꿀 수 없습니다. 스킬 생성의 기존 검증된 턴 조건은 유지합니다. compare-and-exchange로 저장하고 손상된 상태를 보존하며, 다른 writer의 내용을 덮어쓰는 대신 저장 경합을 로그에 남깁니다.

## 독립 검증과 제어된 재사용

`verify_path`에는 기존 상대 경로 셸 스크립트를 지정합니다. 호스트는 모델 실행 전에 공통 소스 스냅샷에서 바이트와 SHA256을 확보하고, 실행 후 일반 bash 권한·샌드박스 경로로 원본을 실행합니다. 체크아웃의 사본을 바꿔도 검증기를 대체할 수 없습니다. 누락·거절·중단된 검사는 통과로 세지 않습니다. 스크립트는 자체 완결적으로 작성합니다. 체크아웃에서 불러오는 헬퍼·테스트는 여전히 수정 가능하므로 통과는 그 스크립트가 실제 확인한 범위만 뜻합니다.

`repetitions`는 학습 과제의 기준·후보 쌍을 1~3회 실행합니다. `holdouts`는 서로 다른 별도 과제·검증기 쌍을 최대 2개 받습니다. 별도 과제는 지침 제안에 전달하지 않으며 지침을 확정한 뒤 실행합니다. 후속 쌍은 실행 순서를 번갈아 바꿉니다. 반복·별도 과제 평가에는 주 검증기가 필요하며, 전체 스텝 예산 초과 요청은 실행 전에 거절합니다. 위 인자에 `"verify_path":"verify.sh","repetitions":2,"holdouts":[{"task":"별도 파서 사례 수정","verify_path":"verify-other.sh"}],"max_steps":10`을 추가할 수 있습니다.

평가에는 실제 통과·실패 횟수를 기록합니다. 학습 쌍을 최소 2회 실행하고 학습·별도 과제 모두 개선되며 관측된 퇴행이 없어야 `eligible`로 분류합니다. 근거 절단 시 채택 대상에서 제외합니다. 기준안이 통과한 검사를 후보가 실패하면 `regressed`로 분류하고 기준안 선호를 유지합니다. 이 조건은 채택 정책이며 성공 확률 측정치가 아닙니다. 보고서의 `verified=false`, `attribution=confounded`는 유지합니다.

새 비교를 시작하면 플러그인이 같은 작업공간에서 최근 채택된 보고서 중 새 작업의 작업·지침·적용 조건과 문자를 공유하는 최대 5개를 자동 조회합니다. 이 보고서는 제안·비교의 참고 근거일 뿐 지침을 몰래 적용하지 않습니다. 새 보고서에는 참고한 ID를 기록하므로 어떤 경험이 분석에 영향을 주었는지 확인할 수 있습니다. 채택 지침을 후보안으로 실제 사용하려면 계속 `reuse_report`를 명시해야 합니다.

`s2_validate`는 검토 전에 보고서를 다시 검사합니다. 각 실행의 실측 메트릭, 실행 합계와 사용량 합계, 고정 검증기 digest와 채택 이력을 대조합니다. 불일치하면 `valid=false`를 반환하며 보고서를 고치거나 채택하지 않습니다. 정확성이나 일반화를 입증하지는 않습니다. `s2_search`는 최근 보고서 ID 최대 100개에서 작업·지침·적용 조건의 문자 그대로 검색을 수행하고 완료된 보고서 최대 10개를 최신순으로 반환합니다. `applies_when`에 적용 조건을 기록합니다. 사용자는 적격 지침을 `/s2-engine-adopt REPORT_ID reason`으로 채택합니다. 명령은 채택 상태를 바꾸기 전에 보고서 일관성을 다시 검사합니다.

사용자는 `/s2-engine-withdraw REPORT_ID reason`으로 철회합니다. 변경 이력을 남기며 compare-and-exchange로 저장합니다. 채택은 후속 실험에서 명시적인 `reuse_report` 사용을 허용합니다. 전역 지침 변경이나 공유 스킬 게시로 이어지지 않습니다. 철회한 보고서는 재사용할 수 없습니다.

카운슬 프롬프트는 근거·한계·불확실성을 말로 요청합니다. 새 모델 응답에서는 숫자 신뢰도를 받지 않습니다. 과거 데이터 호환용 필드는 읽을 수 있지만 TUI·웹·IDE 투표 표시에서는 생략합니다. 실험 판정도 선호·관측 효과·이유만 보존하고 모델이 임의로 덧붙인 점수 필드는 버립니다. 토큰·시간·검증 결과의 실측 수치는 유지합니다.

## 후보 병렬 실행

후보가 둘 이상인 코딩 임시 클론에는 `execution_mode="parallel"`을 지정할 수 있습니다. 호스트는 `spawn_all`을 사용하고 후보마다 별도 trial 체크아웃과 scratch를 주며 메트릭도 후보별로 기록합니다. 자식 예산 상한은 그대로 적용합니다. 현재 체크포인트 분기와 holdout은 이 모드에서 순차 실행합니다. 이는 파일 종류의 제한이 아니라 핸들 격리 상태의 제한입니다. 독립 Office 파일 사본이나 독립 Figma 페이지 사본에 별도 핸들이 연결되면 같은 스케줄러를 사용할 수 있습니다.

## 체크포인트 분기와 최종 정리

`/subagents`에서 `s2_compare`와 함께 `s2_checkpoint`를 켜고 새 대화를 시작합니다. 코딩은 `s2_checkpoint{"action":"begin","kind":"git"}`, 로컬 문서·에셋은 `kind="directory"`로 세션 전용 트리를 생성합니다. Git은 미커밋 변경과 Git에 보이는 파일을 전용 저장소에 고정하고, 실행 분기는 그 저장소의 메타데이터만 공유하는 detached Git worktree로 만듭니다. 디렉터리는 Office 바이너리 문서를 포함한 일반 파일을 복사합니다. 심볼릭 링크·특수 파일은 거절하며 빈 디렉터리는 스냅샷 대상에서 제외합니다.

지원하는 호스트에서는 비교 실행에 체크포인트 분기를 기본 사용하며 첫 비교가 Git 또는 디렉터리 트리를 자동 생성합니다. `"checkpoint":true`는 이 경로를 명시적으로 요구하고 `false`는 기존 Git 전용 임시 클론 경로를 선택합니다. 실행마다 서로 다른 호스트 발급 분기 ID를 받으며 자기 분기와 전용 임시공간만 수정합니다. 보고서의 각 실행에 `branch`를 기록합니다. 실험 도구는 기존 로컬 파일·bash 허용 목록으로 제한합니다. 아직 실제 Office 앱의 자동화 대상이나 원격 Figma 문서 ID를 분기로 전환하지 않으므로 해당 도구들은 실험에서 사용할 수 없습니다. 디렉터리 격리만으로 원격 문서 수정을 허용하지 않습니다.

`s2_checkpoint{"action":"adopt","branch":"<실행의 분기 ID>"}`로 결과물을 선택합니다. 그 결과를 새 체크포인트로 고정하고 다음 분기는 여기서 시작합니다. 실행 중인 분기·이전 세대의 형제 분기·이미 봉인한 분기는 채택할 수 없습니다. 결과물 선택은 후속 실험에서 지침을 재사용하도록 허용하는 `/s2-engine-adopt`와 별개입니다. 결과물을 선택했다고 지침의 일반화가 입증되는 것은 아닙니다.

최종 결과물을 고른 뒤 `s2_checkpoint{"action":"finish"}`를 호출합니다. 이 호출은 반영을 예약합니다. 호스트가 최상위 작업의 실제 완료를 확인하면 원본이 바뀌지 않았는지 검사하고 변경 파일을 백업한 뒤 선택 결과를 반영하며 해시·권한을 확인합니다. 원본 Git 인덱스와 refs는 변경하지 않습니다. 성공하면 임시 worktree·스냅샷·백업·전용 저장소를 정리하고 분기 선택 이력의 작은 manifest만 감사 기록으로 남깁니다. 정리 후 `begin`을 호출하면 새 트리를 시작합니다.

원본이 바뀌었으면 반영을 거절하고 분기를 보존합니다. 취소·미검증 종료도 보존합니다. 반영 중 실패하면 적용한 변경을 되돌리며 예상 밖의 동시 편집은 보존하고 복구를 요구합니다. 반영은 파일 교체를 순서대로 기록하는 방식이며 외부 앱이나 동시 편집자 전체에 대한 원자적 트랜잭션은 아닙니다. 파일·디렉터리 종류 변경은 수동 해결이 필요합니다. 반영할 원본 문서는 닫아 둡니다. 현재 버전은 앱의 문서 핸들을 관리하지 않습니다.

manifest는 `<세션 저장소>/checkpoints/<세션 ID>` 아래에 남깁니다. 재시작 후 `begin`으로 기존 manifest를 열고 `status`로 확인하며 중단된 반영에는 `recover`를 사용합니다. 복구는 현재 값이 원본 또는 반영 시도한 결과와 일치할 때만 백업을 복원하고 예상 밖의 편집은 거절합니다. 검토한 뒤 `reopen`하거나 다시 `finish`를 요청합니다. 반영 완료와 정리의 재시도는 멱등적입니다. 세션 저장소 경로가 없는 환경에서는 프로세스 전용 임시 경로를 사용하므로 자동 재시작 탐색은 제공하지 않습니다.

## 기억 전달

기억 알림은 ID와 조회된 본문·태그의 지문을 함께 추적합니다. 같은 ID의 정정도 다시 안내합니다. 새 판은 대기 중인 옛 알림을 대체하고 최신 조회에서 빠진 알림은 버립니다. 압축에 성공하면 전달 구간을 새로 시작합니다. 다음 일반 조회에서 관련 기억을 다시 안내할 수 있으며 모델 스텝당 최대 3개입니다. 저장된 기억 전체를 주입하거나 고정 시스템 접두부를 바꾸지 않습니다. 전달 기록은 세션 메모리에 있으며 프로세스 간 영속 원장이나 기억 복제 프로토콜은 추가하지 않습니다.

실행 비교는 [Harness²](https://github.com/google-research/harness2)를, 판별 가능한 기억 갱신과 압축 경계는 로컬 `oh-my-openagent/packages/memory-core`의 회상 원장과 `omo-senpi`의 projection pin을 참고했습니다. 그 저장소의 Engram 서버는 별도 메모리 공유 서비스이며 magi의 학습 플러그인과 다릅니다. 해당 메모리 모듈·공유 서버의 코드를 복사하거나 서버 연동을 추가하지 않았습니다. 기존 Unicode 검색과 관리 기억 철회를 재사용합니다.

테스트는 부모·형제의 후속 편집에도 유지되는 미커밋 입력, 실험 병합 거절, 실행 중 문맥 제외, 보고서 저장·작업공간 격리, 구형 호스트, 잘못된 예산, 근거 누락·절단, 보수적 학습 귀속, 기억 정정과 압축 후 재안내를 다룹니다. 검증기 변조 방어, 반복·별도 과제 순서, 퇴행 거절, 채택·철회와 사용량 누락도 검사합니다. 실제 모델의 품질과 다른 과제로의 효과 전이는 추가 실험이 필요합니다.

### 검사 기록, 2026-10-24

앱·Lua·경험 저장소·계층·플러그인 테스트가 통과했습니다. 앱·Lua 전체 race 검사와 신규 사례의 별도 race 검사도 통과했습니다. 코어 빌드와 관련 패키지 vet가 통과했습니다. 통합 사례는 실제 Lua 플러그인·앱 루프·JSONL·Git 클론·내장 write·포그라운드 bash를 연결하고 실행·비교 모델의 응답만 고정합니다.

전사 자산 검사와 질문·자동완성·접근성·Markdown 묶음이 통과했고 접근성 위반은 0건입니다. 레이아웃은 기존 `#select-model` 대기에서 시간 초과됐으며 diff는 기존 인자 펼치기의 헤더 배치 검사에서 실패했습니다. 카운슬 UI는 과거의 숫자 신뢰도를 숨기고 결정과 정성적 근거를 유지하도록 변경했습니다. CLI에서는 기존 `TestShimSalvagesATruncatedToolCall`, `TestShimSaysWhyACallWasNotRun`, `TestCodexUsageDoesNotDoubleCountTheCache`가 실패했습니다. 변경하지 않은 shim 테스트 소스만 별도로 실행해도 변경된 앱·Lua 코드 없이 같은 실패가 재현됩니다. 이 실패들은 미해결입니다.

VS Code는 642개 통과·7개 건너뜀으로 실패가 없었고 JetBrains 코어 테스트·IntelliJ 컴파일과 웹 코딩 모듈 GWT 컴파일도 통과했습니다. Git worktree·디렉터리 시나리오에서 실제 Lua·앱·bash 실행, 다음 세대 분기, 최종 정리, 충돌, 재시작 로딩과 중단된 반영의 복구도 통과했습니다. macOS 실측에서는 분기 밖과 Git 메타데이터 쓰기가 거절됐습니다. 양쪽 Mermaid 문법과 기존 한·영 파리티 검사가 통과했습니다. 신규 문서 쌍의 절·그림·코드 예시도 일치합니다. 저장소 전체 문서 감사에는 기존 MANUAL의 `browser`, `companion_call` 누락이 남습니다. 실제 모델 벤치마크와 외부 기억 서버 연결은 실행하지 않았습니다.

## 파일 자원·컨텍스트·앱 수명

Office 파일 하나는 `s2_checkpoint{"action":"begin","kind":"file","path":"documents/report.docx"}`로 지정합니다. 상대 경로는 세션 작업공간 내부여야 하며 심볼릭 링크를 통과할 수 없습니다. 해당 파일만 분기에 복사하고 다음 체크포인트로 채택하며 원본에 반영합니다. 분기의 다른 출력과 원본의 이웃 파일은 제외합니다. 반환된 `resource`는 정확한 사본 경로입니다. 검증 스크립트는 별도로 고정하며 문서와 함께 원본에 반영하지 않습니다.

분기는 분기 도구 호출 전 모델이 받았던 같은 메시지 기록과 시스템 본문을 상속합니다. 기존 압축본과 런타임 참고자료는 추가 요약 없이 복사합니다. 결과가 없는 진행 중 도구 호출은 복사하지 않습니다. 자식은 각자의 세션 로그를 가집니다. 채택한 분기의 기록이 다음 실행으로 이어지고, 최종 정리 시 부모에 `checkpoint.context`로 보존하며 원래 감사 전사도 유지합니다. 이미지는 임시 작업공간을 지우기 전에 영속 컨텍스트 저장소로 복사합니다. 자식별 자동 압축은 끄므로 큰 실행은 서로 다른 요약을 만들지 않고 프로바이더의 컨텍스트 한도로 중단될 수 있습니다.

앱 어댑터 계약은 정확한 사본의 핸들을 소유하며 `OpenCopy`, `SaveAndClose`, `ConfirmClosed`를 제공합니다. 채택·완료·정리는 닫기가 확인되지 않으면 거절하고 사본을 유지합니다. 재시작 후에도 앱이 관리하던 트리에는 같은 어댑터가 필요하며 파일 삭제 성공을 Office 문서 닫기의 증거로 쓰지 않습니다. 수명 계약과 실패 시나리오는 주입한 어댑터로 테스트했습니다. 실제 Office COM·Office.js의 열기·바인딩·닫기는 아직 연결하지 않았으므로 현재 Office 지원은 파일 기반 실행입니다.

Figma에는 별도 페이지 사본 도구 `figma_checkpoint`를 추가했습니다. 클라이언트의 [체크포인트 절차](../clients/figma/README.ko.md#체크포인트-페이지)를 참고합니다. 텍스트·프레임의 격리 편집과 호스트 완료 확인 후 반영을 지원하지만 일반 하네스 비교의 자식 세션을 Figma 도구에 연결하지는 않았습니다. Plugin API 테스트는 모의 Figma 문서를 사용하며 실제 계정 인수는 남아 있습니다.
