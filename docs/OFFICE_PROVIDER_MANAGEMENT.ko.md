# Office 프로바이더 관리

[English](OFFICE_PROVIDER_MANAGEMENT.md)

PowerPoint·Word·Excel 작업창의 고급 메뉴에서 **프로바이더 관리**를 제공합니다. 이 컴퓨터의 Magi 전역 설정에 이름 있는 프로바이더 프로필을 저장합니다. 저장된 프로필은 기존 프로바이더 드롭다운에 실행 중인 백엔드와 함께 이름으로 표시합니다.

화면을 열고 저장된 프로필이나 **새 프로바이더**를 선택합니다. 이름(영문·숫자·하이픈·밑줄), HTTP(S) API 엔드포인트, 모델 ID와 필요한 API 키를 입력해 저장합니다. 저장에 성공하면 다이얼로그가 닫히며, 실패하면 열린 상태에서 오류를 안내합니다. API 키를 빈칸으로 두면 기존 키를 유지하며, 키 삭제 체크박스를 선택해야 지웁니다. 저장된 키는 화면으로 반환하지 않습니다. 키 입력란은 요청 후와 화면을 닫을 때 비웁니다. 프로필 삭제는 확인 후 수행합니다.

프로필은 인증된 헬퍼 API를 통해 Magi 전역 `config.toml`의 `[llm.profiles.NAME]`에 저장합니다. 여러 필드를 함께 검증한 뒤 한 번에 반영하고 무관한 설정·주석을 유지합니다. 갱신에 실패하면 기존 파일은 그대로입니다. 새 설정 파일은 소유자 전용 권한으로 만들고 기존 파일 권한은 유지합니다. 키는 로컬 설정에 저장하며 이 기능이 암호화 자격 증명 보관함을 추가하는 것은 아닙니다.

저장하면 다이얼로그를 닫고 기존 프로바이더 드롭다운을 갱신합니다. 저장한 이름을 드롭다운에서 선택하면 해당 프로필을 사용합니다. 별도의 적용 버튼은 없습니다. 화면에서는 이름만 보내며, 데몬이 설정에서 엔드포인트·키·모델을 읽어 선택한 대화에 함께 적용합니다. 응답이 진행 중이면 변경을 거절합니다. 다른 대화와 전역 기본값은 바꾸지 않습니다. 다음 요청부터 선택한 프로바이더를 사용하며 이후 모델을 바꿔도 해당 프로바이더를 유지합니다. 적용 자체가 엔드포인트를 실행하거나 네트워크로 인증 성공을 확인하지는 않습니다.

선택은 데몬을 재시작할 때까지 유지되므로 재시작 후에는 다시 적용해야 합니다. 모델 변경도 함께 임시 상태로 두어 재시작 후 다른 기본 엔드포인트에 해당 모델이 잘못 연결되지 않도록 합니다. 저장된 프로필을 삭제해도 이미 대화에 적용한 프로바이더는 유지됩니다. 같은 드롭다운에서 저장한 이름으로 구분하므로 동일한 엔드포인트의 서로 다른 키·모델도 선택할 수 있습니다.

## 검증

`go test -race ./clients/office/helper ./internal/config`와 `node clients/office/tools/provider-profiles-test.mjs`를 실행합니다. 브라우저 검증은 PPT·Word·Excel의 동일 관리 모듈에서 좁은 화면, 생성·수정·삭제, 키 유지·삭제, 비밀값 없는 조회, 요청 실패, 저장 성공 후 닫힘, 실제 드롭다운 렌더러·클릭 핸들러를 통한 이름만 전달하는 적용을 확인합니다. 실제 턴 테스트는 저장된 설정을 생산 데몬·프로바이더 생성 경로로 적용하고 일반·워크플로 메시지를 전송하여 실제 HTTP 모델 요청의 엔드포인트·인증 키·모델, 다른 세션 격리와 응답 진행 중 변경 거절을 확인합니다. 백엔드 테스트는 인증, 잘못된 주소·이름 거절, 키 처리, 영속 저장과 원자적 검증을 확인합니다. 브라우저 모의 실행이 실제 Office 설치 인수 통과를 뜻하지는 않습니다.

## Office 실물 인수와 Windows 시작 진단

이 Mac에서는 실제 접근성 인터페이스로 PowerPoint를 열고 새 빈 프레젠테이션을 만들었습니다. Magi 작업창에는 진입하지 못했으므로 Office 내부에서의 프로필 저장·적용은 아직 검증하지 못했습니다. 위의 세 브라우저 모듈 검사와 실제 HTTP 코어 검사는 이 인수를 대신하지 않습니다.

Windows Office 2021에서는 PPT를 연 직후와 30초 뒤에 `powershell -NoProfile -File clients/office/tools/process-diagnostics.ps1`를 실행합니다. 명령줄이나 키를 출력하지 않고 PID·부모·역할·실행 파일·시작 시간을 표시합니다. PPT만 사용하는 설치에서는 통합 Office 헬퍼 하나, PPT 컴패니언 하나, 설치된 경우 COM 편집 어댑터가 필요하며 데몬 실행기는 일시적으로 뜹니다. Magi가 7~10개 계속 남는다면 개수만으로 판단하지 말고 역할별로 확인해야 합니다. COM 시작기는 시작 mutex를 얻지 못하면 실행을 중단하도록 수정했고 `start.log`에 호스트·자식 PID를 기록합니다. 헬퍼 시작 로그에는 PID·부모·설정·소켓 위치를 기록합니다. 발견한 중복 시작 경로를 고친 것이며 사용자가 본 Windows 현상의 원인을 확정한 것은 아닙니다. Windows COM 시작 동작은 해당 PC에서 추가 검증해야 합니다.

헬퍼 시작 시 실행 중인 Office 앱의 컴패니언만 미리 준비합니다. 이전에는 PPT·Word·Excel 경로를 등록하면서 PPT만 열어도 세 컴패니언을 모두 시작했습니다. 이제 프로세스 감시기가 추가 앱의 실행을 감지하면 그 앱을 준비하고, 실행되지 않았거나 상태를 알 수 없는 앱은 시작하지 않습니다. 세 앱의 준비 조건과 실패한 준비를 백그라운드에서 반복하지 않는 동작을 테스트합니다. 워크플로 단계에서도 선택한 프로바이더를 유지하도록 수정했습니다. 이전의 프로바이더 직접 호출 테스트는 실제 워크플로 요청이 키 없는 기본 백엔드로 돌아가는 결함을 발견하지 못했습니다.

현재 대화에서 선택한 프로필을 수정해 저장하면 해당 프로필을 다시 불러옵니다. 엔드포인트·키·모델을 함께 적용하며 다음 요청부터 사용합니다. 다른 프로필을 선택한 대화와 다른 대화는 바꾸지 않습니다. 응답이 진행 중이면 설정은 저장하지만 현재 대화 반영 실패를 안내하며, 응답 후 같은 이름을 다시 선택할 수 있습니다. 이미 선택한 프로필을 다시 눌러도 다시 불러오므로 수정 전 엔드포인트가 메모리에 남지 않습니다. 식별자 입력란은 자동 대문자 변환·자동 교정·맞춤법 검사를 끕니다.

대화 아이콘은 왼쪽 정렬하고 새 대화, 규칙·가이드, 카운슬·컴패니언 세 그룹으로 묶습니다. 그룹 안 버튼 간격은 16px, 그룹 사이 간격은 24px입니다. 프로바이더·모델 드롭다운도 같은 왼쪽 정렬선에 맞추고 옆에 40px 설정 아이콘으로 프로바이더 관리를 제공합니다. 세 컨트롤은 320px에서도 한 줄에 배치됩니다. `node clients/office/tools/provider-toolbar-test.mjs`에서 320/420/600px 배치와 입력 속성을 검사합니다. 프로바이더 오류가 발생하면 실행 중인 요청은 실패로 표시하고, 턴이 끝난 뒤 미처리 요청은 다른 작업이 진행 중인 것처럼 안내하지 않습니다. `node clients/office/tools/request-state-test.mjs`에서 해당 이벤트 재생 순서를 검증합니다.

아이콘 버튼은 마우스 호버와 키보드 포커스에서 설명 툴팁을 즉시 표시합니다. 버튼의 현재 title 또는 접근성 이름을 사용하며 상태 변경과 나중에 생성된 버튼도 지원합니다. 설명은 화면 밖으로 잘리지 않고 설명 위로 마우스를 옮겨도 유지되며, Escape·실행·스크롤·창 크기 변경 때 닫힙니다. 기존 접근성 설명은 보존합니다. `node clients/office/tools/icon-controls-test.mjs`에서 세 앱의 해당 동작을 확인하고 툴바 검사에서는 실제 폭과 간격을 측정합니다.

`node clients/office/tools/icon-controls-boot-test.mjs`는 실제 작업창 HTML과 main 모듈 전체를 로드해 초기화·호버 설명과 pageerror 0건을 확인합니다. Office 토큰이나 실제 문서를 연결하지 않는 격리 브라우저 모의 실행입니다.
