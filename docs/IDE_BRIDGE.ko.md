# `magi ide-bridge` — 편집기 클라이언트가 저마다 하던 것을 한 벌로

[English](IDE_BRIDGE.md) · [클라이언트 계약](CLIENTS.ko.md) · [VS Code](../clients/vscode/README.md) · [젯브레인](../clients/jetbrains/README.md) · [비주얼 스튜디오 설계](../clients/visualstudio/docs/DESIGN.ko.md)

## 1. 왜 있나 — 주장이 아니라 실측입니다

편집기 클라이언트 둘이 같은 여덟 가지를 두 언어로 합니다. 그리고 **이미 갈렸습니다.**
앞으로 갈릴 것이라는 예측이 아닙니다. 2026-09-09 에 유도 하나를 두 벌에서 대조한 결과입니다.

| 완성 | 젯브레인(코틀린) | VS Code(타입스크립트) |
|---|---|---|
| 커서 앞뒤로 보내는 양 | **파일 전체** (`TextRange(0, offset)`) | **4,000자로 자름** (`around()`) |
| 답이 이미 친 글자와 겹치는 부분 | **그대로 둠** — 유령 글자로 그림 | **지움** (`usable()`) |

한 사람이 두 편집기에서, 같은 컴패니언과 같은 모델로 **다른 완성**을 봅니다. 어느 쪽도 자기가
어긋난 줄 모릅니다 — 대조하는 것이 없기 때문입니다. 답이 하나뿐인 규칙을
[비주얼 스튜디오](../clients/visualstudio/docs/DESIGN.ko.md)에서 C# 으로 또 쓰면 **세 벌**이 됩니다.

그래서 규칙을 편집기들이 이미 받아 두는 그 바이너리 안으로 옮기고, 편집기 층에는 정말로 그
편집기의 것만 남깁니다.

## 2. 무엇인가

코어 바이너리의 서브커맨드입니다. 편집기가 자식 프로세스로 띄우고 stdin/stdout 으로 줄 단위
JSON 을 주고받습니다. 소켓은 **브리지가** 두드립니다 — 편집기는 소켓을 모릅니다.

```
편집기  ──stdin/stdout, 줄 단위 JSON──▶  magi ide-bridge  ──유닉스 소켓──▶  데몬
```

**왜 소켓이 아니라 stdio 인가.** 소켓을 하나 더 두면 경로를 또 유도해야 하는데, 그 경로 유도가
바로 우리가 없애려는 여덟 중 첫째입니다. stdio 는 감독 프로세스 없이도 브리지의 수명을 편집기에
묶어 줍니다.

**자식 프로세스가 새 부담이 아닌 이유.** 편집기 클라이언트는 이미 이 바이너리를 받습니다 —
그래야 데몬을 띄우니까요. 한 번 더 띄우는 것은 프로세스 하나이지 의존성이 아닙니다.

## 3. 무엇을 담나

두 벌을 손에 쥐고 나서 비주얼 스튜디오 설계가 센 그 여덟입니다.

| | 편집기가 안 하게 되는 것 |
|---|---|
| 1. 소켓 경로 | `workspaceKey` 와 소켓 경로 유도. 두 벌이 각각 표준이 아닌 FNV 상수와 `Base("/")` 를 다시 구현했고 **둘 다 처음에 틀렸습니다** |
| 2. 전선 | 줄 단위 JSON, 쓰는 쪽을 안 닫기, 답을 요청에 맞추기 |
| 3. 전사 → 행 | 같은 로그를 두고 코틀린 601줄, 타입스크립트 114줄 |
| 4. 「무엇을 하는 중인가」한 단어 | `unknown` 은 `attached` 가 아니고, `attached` 는 `idle` 이 아니라는 것까지 |
| 5. 승인 어휘 | `allow` · `deny` · `always`. 틀리게 적으면 조용히 무시되는 대신 **여기서 거절**됩니다 |
| 6. 훑어본 말 가르기 | 어느 말이 줄에 걸리고 어느 말이 안 걸리나 — 구분자가 탭만이 아니라는 실측까지 |
| 7. 완성의 창과 겹침 | §1 에서 잰 그 드리프트 |
| 8. **나는 어느 판인가, 새 판이 있나** | ⚠ 반만. 아래를 보십시오 |

⚠ **여덟째는 통째로 옮겨오지 않습니다.** 코어를 받아야 브리지가 생기므로 부트스트랩은 브리지
안에 살 수 없습니다. 브리지가 답할 수 있는 것은 「나는 어느 빌드인가」와 「더 새 릴리스가 있나」
이고, **첫 사본을 받아오는 일은 편집기 층에 남습니다.** 이것을 다 옮겼다고 세면 될 수 없는 것을
세는 셈입니다.

## 4. 무엇을 안 담나

명령을 어디에 다나 · 대화를 무엇으로 그리나(웹뷰·XAML·스윙) · 인레이와 완성 API · 설정을 누가
그리나 · 알림의 규약. 이쪽은 **그 편집기 자신의 규약**이라 편집기마다 다르고, 그 규약을 따르는
것이 클라이언트의 일입니다. 여기에는 나눌 것이 없습니다.

## 5. 계약

한 줄에 JSON 객체 하나, 양방향입니다. 요청은 `id` 를 싣고 그 답이 같은 `id` 를 답니다. 구독이
보내는 프레임은 `id` 대신 `sub` 를 달고 아무 때나 옵니다.

```
$ magi ide-bridge -workspace /경로/프로젝트
```

워크스페이스마다 브리지 하나입니다 — 워크스페이스마다 컴패니언이 하나이기 때문입니다.

### 메서드

**지어진 것** (2026-09-09 현재, `internal/adapter/idebridge`):

| 메서드 | 하는 일 |
|---|---|
| `about` | 브리지의 판, **답하는 메서드 목록**, 그리고 데몬이 광고하는 것(`proto`·`caps`) |
| `activity` | **무엇을 하는 중인가를 한 단어로** — `not-running` · `attached` · `working` · `waiting` · `unknown` — 그리고 무엇 위에서 도는지 |
| `daemon` | **`req` 를 컴패니언에게 그대로 넘기고 답을 그대로 돌려줍니다** |

`about` 이 이 빌드가 답하는 메서드를 스스로 말하므로 클라이언트가 이 표를 믿을 필요가 없습니다 —
표는 늙고 광고는 안 늙습니다.

**`activity` 가 여덟 중 처음으로 들어온 유도입니다.** 넷째이고, 마침 **세 번째로 쓰일 참**이었기
때문입니다 — 규칙은 타입스크립트 `core/activity.ts` 에 있고 비주얼 스튜디오 클라이언트가 그것을
C# 으로 또 써야 했습니다. 규칙 둘이 함께 옮겨왔는데, 같은 질문이 옷만 바꿔 입은 것이라서입니다:
**소켓 경로가 주소 상한보다 긴가**와 **아무도 안 듣고 있는가**. 둘 다 예외가 아니라 같은 어휘로
답합니다.


> **옮기는 동안 사본은 둘입니다.** 이 패키지와 `clients/vscode/src/core/activity.ts`. 그 둘이 실제로
> 갈렸고(2026-09-09), 사람이 두 파일을 같이 여는 것에 기대면 안 되는 종류의 일이라 시험이 집니다 —
> `TestBothCopiesSpeakOneVocabulary` 가 타입스크립트 열거를 읽어 낱말 집합을 견줍니다. 어느 쪽에만
> 낱말이 있거나 없으면 그 낱말을 이름 대어 빨개집니다.

`unknown` 은 어깨를 으쓱하는 것이 아니라 답입니다 — 「물어볼 수 없었다」와 「답을 받았다」는 다른
사실입니다. 그리고 `attached` 는 그 셋째이지 idle 의 다른 철자가 아닙니다 — 데몬이 답했고 그
이상은 말하지 않았다는 뜻이고, 이 전선에서는 **평범하게 도는 턴이 정확히 그 모양**입니다.
`doing` 은 분 단위로 도는 툴의 진행 쪽지라 빌트인 도구 파일 50개 중 하나만 채우고, `status` 문에는
「턴이 돌고 있다」를 뜻하는 칸이 아예 없습니다. 그 침묵을 `idle` 이라 부르는 다리는 **한창 일하는
컴패니언을 쉬고 있다고 보고**하게 됩니다(2026-09-09 실측 — 이 패키지에서도, 이 패키지가 대신하려던
타입스크립트 사본에서도). `waiting` 이 `working` 을 이깁니다: 사람에게 막힌 턴도 돌고 있는
것이지만, 그 사람이 알아야 하는 것은 그것이 자기를 기다린다는 쪽입니다. 그리고 단어가 전부는 아닙니다 —
사연이 있으면 `why` 가 싣기 때문에, 클라이언트는 **어떤 종류의 없음**인지까지 말할 수 있습니다.

**아직 안 지어진 것.** 나머지 유도들이고, §1 의 드리프트를 끝내는 쪽은 이 절반입니다:

| 메서드 | 하게 될 일 |
|---|---|
| `watch` / `unwatch` | 행·활동·건드린 파일이 바뀔 때마다 |
| `look` | 버퍼에 번호를 매겨 묻고, 답을 걸리는 것과 안 걸리는 것으로 가릅니다 |
| `complete` | 커서 앞뒤를 창으로 잘라 묻고, 겹침을 지웁니다 |
| `touched` | 컴패니언이 고친 파일 — 디스크가 아니라 전사에서 읽습니다 |
| `serve` | 이 워크스페이스에 컴패니언이 돌고 있게 합니다 |

⚠ 이것들이 생기기 전까지 **§1 에서 잰 드리프트는 그대로 있습니다** — §1 이 실제로 잰 것은 완성
쪽이고, `complete` 는 아직 목록에 있습니다. 전달 문은 그것대로 값이 있지만(아무도 못 옮긴 열다섯
문에 닿습니다), 여덟 중에서는 아직 셋입니다: 전선, 소켓 경로, 그리고 이제 그 한 단어.

**`daemon` 은 일부러 멍청합니다.** 번역하지 않습니다 — 요청은 적힌 대로 가고 답은 온 대로
옵니다. 그래서 클라이언트들이 아직 못 옮긴 문들(`compact` · `rewind` · `cron-set` · `children` ·
`job-kill` · `mcp-attach` · `config-set` · `profiles` · `resume` · `session-new` …)이 **문마다 두
번째 어휘를 만들지 않고** 닿습니다. 번역하는 전달은 옛 계약과 발을 맞춰야 하는 새 계약입니다.

```json
→ {"id":1,"method":"about"}
← {"id":1,"ok":true,"version":"0.27.0","proto":1,"caps":["transcript","cron","settings"]}

→ {"id":2,"method":"daemon","req":{"method":"submit","text":"실패하는 시험 고쳐줘"}}
← {"id":2,"ok":true,"resp":{"ok":true,"session":"s_01J..."}}

→ {"id":3,"method":"watch"}
← {"id":3,"ok":true,"sub":1}
← {"sub":1,"rows":[{"seq":8,"who":"agent","text":"시험을 봅니다…"}]}
```

## 6. 이것이 바꾸지 않는 것

- **데몬 프로토콜.** 새 문이 없습니다. 브리지는 편집기들이 오늘 두드리는 그 소켓의 클라이언트라,
  직접 두드리고 싶은 클라이언트는 그대로 그럴 수 있습니다.
- **`docs/CLIENTS`** 가 문이 무엇인지의 정본으로 그대로 남습니다. 이 문서는 그 문들에서 **누가
  무엇을 유도하나**에 관한 것입니다.

## 7. 남은 것과, 어디서 해야 하는가

| | 어디서 |
|---|---|
| 위의 유도 다섯 | 아무 데서나. 평범한 Go 이고 골든은 이미 있는 두 이식본에서 가져올 수 있습니다 |
| **§1 의 드리프트 둘을 정하는 일** — 완성 창 크기, 겹침을 지울 것인가 | 이식이 아니라 **결정**이 필요합니다. 한쪽을 베끼면 그쪽을 얼떨결에 정답으로 삼는 셈입니다 |
| VS Code 를 브리지 위로 옮기기 | 아무 데서나. 이 일의 부수 효과가 아니라 별개의 일입니다 |
| **비주얼 스튜디오 클라이언트** | **윈도우.** 이 글을 쓴 기계에는 Visual Studio 도 `msbuild` 도 없고 VS for Mac 은 단종됐습니다 — [설계](../clients/visualstudio/docs/DESIGN.ko.md) §9 |

## 8. 재지 않은 것

- **편집기들이 실제로 옮겨탈지.** VS Code 에는 도는 이식본이 있고, 그것을 브리지 위로 옮기는 것은
  이 일의 부수 효과가 아니라 별개의 일입니다.
- **프로세스 값** — 창 하나마다 코어 프로세스가 하나 더 뜨는 시작 시간과 메모리.
- **윈도우.** 브리지도 다른 클라이언트처럼 AF_UNIX 를 두드리므로, 오피스 클라이언트가 `%AppData%`
  아래에서 겪은 함정이 여기에도 걸립니다. 다시 재지 않았습니다.
