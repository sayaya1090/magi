# 위임 작업 승인

다른 컴패니언이 요청한 도구 실행도 로컬 사용자의 승인이 필요합니다. 기존 `allow` 설정은 해당 요청의 승인을 대신하지 않습니다. 사용자는 위임 대화로 전환하지 않아도 요청을 검토할 수 있어야 합니다.

`App.PendingPrompts`는 위임 세션의 승인·질문 대기 목록을 수집합니다. 로컬 데몬은 `jobs.approvals`에 원본 `session`, 요청자 `requester`, 전체 `prompt`를 제공합니다. 기존 클라이언트는 이 선택 필드를 무시할 수 있습니다. 플릿의 접근 권한은 바뀌지 않습니다.

VS Code와 JetBrains는 채팅·현황 패널과 별도로 폴링합니다. 새 요청마다 한 번 알립니다. 대기 요청은 현황 패널에서 계속 열 수 있으며, VS Code는 상태 표시줄과 `magi.approvals` 명령도 제공합니다. 검토 영역에는 요청자, 원본 세션, 인자, 사유, 변경 내용, 질문 근거를 표시합니다. JetBrains는 일반 요청과 같은 `ReviewSurface`의 본문 서식·여백·배경을 메인 입력창 위에 사용하고, 원본 컴패니언이 정한 검토 항목·순서와 원본 세션 응답 경로를 유지합니다. 알림·현황의 검토 동작도 이 영역을 엽니다. 변경 내용은 기존 IDE 편집창에서 엽니다. 위임 질문의 직접 입력은 검토 영역 안에서 별도로 받아 메인 대화 초안을 보호합니다. VS Code는 현재 네이티브 검토 다이얼로그를 사용합니다. 검토 영역을 숨기거나 닫아도 대기를 유지합니다.

응답 직전 클라이언트는 원본 세션과 요청 ID가 여전히 대기 중인지 확인합니다. 데몬은 먼저 도착한 응답만 받습니다. 승인 동작은 ‘이번만 허용’, ‘거부’, ‘이 작업 자동승인’을 제공합니다. `task_allow`는 사용자가 응답한 원본 위임 작업의 일반 도구 호출만 승인합니다. 위험 동작의 강제 승인과 사용자 질문은 계속 표시합니다. 전체 거부 설정과 도구 접근 제한도 유지합니다. 작업 종료·취소·다음 작업 시작·프로세스 재시작 시 승인이 해제되며 프로젝트 설정에는 저장하지 않습니다. 질문은 기존 `answer` 메서드로 응답합니다.

대화형 위임 요청에는 승인 대기 제한시간을 적용하지 않습니다. 명시적인 응답, 취소, 프로세스 종료 시 대기가 끝납니다. 데몬 재시작 후 실행 중이던 호출의 복구를 보장하지는 않습니다. 일반 예약 작업과 헤드리스 실행은 기존 제한시간·권한 규칙을 유지합니다.

| `permission.decided.origin` | 의미 |
|---|---|
| `user` | 명시적인 승인 또는 거부 응답 도착 |
| `timeout` | 적용 가능한 제한시간 내에 응답 없음 |
| `policy` | 권한 설정 또는 보호 규칙에 따른 결정 |
| `cancelled` | 요청 컨텍스트 취소 |
| `headless` | 대화형 승인 경로 없음 |

거절된 도구 결과에는 기록된 사유를 사용합니다. 승인 성공에는 거부 사유를 넣지 않습니다. 선택 필드가 없는 과거 이벤트도 읽을 수 있지만, 기존 `deny` 값만으로 결정 경위를 신뢰성 있게 복원할 수는 없습니다.

회귀 테스트는 일반 제한시간을 넘긴 대기, 전체 요청 조회, 원본 세션으로 응답 전달, 검토창 닫기, 중복 알림 억제, 만료 요청, 거절 사유 구분을 검증합니다. 이미 시간 초과된 위임 요청은 자동으로 재시도하지 않습니다.
