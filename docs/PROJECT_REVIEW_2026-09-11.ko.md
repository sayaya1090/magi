# magi 프로젝트 평가 — 2026-09-11

[English](PROJECT_REVIEW_2026-09-11.md) · [↑ Docs](README.ko.md)

이 문서는 JetBrains·VS Code 수정과 카운슬 Think 전달 경로를 검토한 뒤, 사용자의 요청으로 남긴 Codex의 의견입니다. 평가 근거는 당시 읽은 코드와 실제 수정·검증 범위입니다. 전체 저장소 감사나 Windows IDE 실기 검증을 완료했다는 뜻은 아닙니다. 아래 우선순위는 제안이며 확정된 개발 계획은 아닙니다.

magi는 방향이 뚜렷하고 발전시킬 가치가 있는 프로젝트라고 봅니다. 지금 가장 필요한 일은 기능 확장보다 구성요소 사이의 연결을 믿을 수 있게 만드는 것입니다.

에이전트의 완료 선언과 실제 작업 증거를 구분하려는 설계가 특히 좋습니다. 카운슬은 작업을 검토하는 모델들의 합의 절차이며, 실행 기록·승인·작업 이력과 함께 완료 판단을 뒷받침합니다. 같은 워크스페이스의 컴패니언에 IDE·터미널·웹 등 여러 화면에서 접근하는 구상도 유용합니다. 다만 카운슬이 실제로 잘못된 완료를 얼마나 줄이는지는 별도의 측정이 필요합니다. 설계의 의도만으로 효과를 단정할 수는 없습니다.

가장 걱정되는 부분은 클라이언트가 늘면서 공통 계약을 유지하는 비용이 커졌다는 점입니다. 이번 Think 문제에서는 모델의 추론 수집, 이벤트 발행, 저장, 클라이언트 변환, 화면 표시 사이에서 값이 빠졌습니다. 원격 커밋에 필드와 표시 코드가 있어도, 실제 이벤트에 값을 싣는 두 곳이 빠지면 사용자의 화면은 비어 있었습니다. 정상 응답을 낸 공통 카운슬의 추론과 Office 세 제품의 표시도 누락돼 있었습니다. 수정 근거는 [731b404a](https://github.com/sayaya1090/magi/commit/731b404a)에 남아 있습니다.

테스트와 문서에 공을 많이 들였지만, 검증 방식의 균형을 조정할 필요가 있습니다. 소스에 특정 문구나 필드가 존재하는지 검사하는 테스트는 빠진 선언을 찾는 데 도움이 됩니다. 실제 실행도 함께 확인해야 합니다. VS Code 웹뷰는 템플릿에서 생성되는 JavaScript의 이스케이프 오류 때문에 실행이 멈출 수 있었고, 이는 브라우저 실행에서 드러났습니다. [브라우저 회귀 테스트](../clients/vscode/tools/transcript-test.mjs)와 [실시간·저장 이벤트 테스트](../internal/app/council_live_verdict_test.go)는 이번 결함이 발생했던 경계를 직접 확인합니다.

우선순위는 다음과 같이 제안합니다.

- **대표 클라이언트의 사용 흐름을 안정화합니다.** 주로 쓰는 IDE와 웹에서 설치, 연결, 작업, 재연결, 종료까지 확인합니다. 테스트 성공과 사용자의 실제 설치 환경에서 성공한 사실을 구분해 기록합니다.
- **공통 데이터 변환을 집중시킵니다.** 각 클라이언트가 이벤트를 따로 해석하는 양을 줄이고, 공통 브리지가 화면에 필요한 데이터를 일관되게 제공하도록 발전시킵니다. 전환 시에는 기존 클라이언트와의 호환성을 확인합니다.
- **카운슬의 효과와 비용을 함께 측정합니다.** 잘못된 완료를 잡은 비율뿐 아니라 불필요한 재작업, 완료 지연, 토큰 비용도 봅니다. 같은 작업 조건에서 비교해야 개선 여부를 판단할 수 있습니다.

앞으로의 완성도는 사용자가 “연결됐나?”, “왜 멈췄지?”, “정말 끝났나?”를 추측하지 않아도 되는 정도에서 결정될 것 같습니다. 그 신뢰가 쌓이면 이미 구현된 기능들의 가치도 더 잘 드러날 것입니다.

## 후속 구현 검토 — 2026-09-13

**정정:** 사람의 말·응답·Think가 공용 접기에서 잘린다는 우려는 해당 구현과 맞지 않았습니다. 이미 전문을 보존했습니다. `fd68d489`는 도구 인자와 실패 결과의 줄·길이 제한을 제거하고 목록용 `Row.Summary`를 추가했습니다. 다만 다음 두 손실은 남아 있습니다.

|---|---|---|
| P2 | [AskedFor](../internal/adapter/idebridge/fold.go)가 `path`, `command` 등에서 처음 찾은 문자열만 반환합니다. `{path, old_string, new_string}`은 경로만 남습니다. | 인자 전체를 구조화된 값 또는 전체 JSON으로 보존합니다. 대표 필드 선택은 요약에만 적용하고, 여러 필드를 가진 편집·실행 인자의 복원 가능성을 검증합니다. |

두 항목은 새 회귀가 아니라 전문 보존 계약에 아직 반영되지 않은 기존 손실입니다. 기존에 숨겼다는 이유로 정본에서도 버리면 클라이언트 이관 후 전문을 펼쳐 볼 수 없습니다. 긴 본문·여러 줄·이모지·Think와 도구 입출력의 무손실 검증을 먼저 마치고, **재생과 실시간 처리의 최종 행이 일치하는 계약**을 마련한 뒤 클라이언트를 순차 이관합니다. 그동안 기존 셰이퍼를 유지합니다.

검토자가 macOS에서 관련 Go 행·접기·출처 안내 테스트와 JetBrains 경로·심링크 테스트를 실행해 통과했습니다. `5d4b5a6f`의 Windows 업데이트 실물 테스트는 코드를 검토했으며 실행하지 않았습니다. 실제 IDE·Windows 인수 완료를 뜻하지 않습니다.
