## 현재 판단과 우선순위

실행 증거로 완료 선언을 검토하는 카운슬과, 같은 워크스페이스를 IDE·터미널·웹에서 사용하는 방향은 유용합니다. 다음 우선순위는 공통 계약의 유지 비용을 줄이고 실제 사용 흐름을 검증하는 것입니다.

| 우선순위 | 현재 상태와 다음 작업 |
|---|---|
| 1. 대표 클라이언트 안정화 | 검토한 수명주기 코드 지적은 해결됐습니다. 설치→연결→작업→재연결→종료의 실제 제품 인수는 [수명주기 설계](CLIENT_LIFECYCLE.ko.md) §§8–9에 따라 계속합니다. |
| 2. 공통 데이터 변환 | 사용자 입력·응답·Think는 전문을 보존하고 `Row.Summary`가 목록용 요약을 제공합니다. 아래 도구 입출력 손실을 해결한 뒤 실시간 전달 계약과 클라이언트 이관을 진행합니다. |
| 3. 카운슬 효과 측정 | 같은 작업 조건에서 잘못된 완료 탐지, 불필요한 재작업, 지연과 토큰 비용을 함께 측정해야 합니다. 설계 의도만으로 효과를 단정하지 않습니다. |

## 남은 구현 지적

| 우선순위 | 남은 문제 | 수정·인수 조건 |
|---|---|---|
| P2 | [AskedFor](../internal/adapter/idebridge/fold.go)가 `path`, `command` 등에서 처음 찾은 문자열만 반환합니다. `{path, old_string, new_string}`은 경로만 남습니다. | 인자 전체를 구조화된 값 또는 전체 JSON으로 보존합니다. 대표 필드 선택은 요약에만 적용하고, 여러 필드를 가진 편집·실행 인자의 복원 가능성을 검증합니다. |
| P2 | 도구 결과는 실패이며 advisory가 아닐 때만 `Out`에 남습니다. 성공 결과와 advisory 본문은 공용 행에서 읽을 수 없습니다. | 성공 여부와 무관하게 결과 본문을 보존합니다. 접거나 숨기는 기본 표시 정책은 별도로 두고, 성공 결과·실패 결과·advisory를 펼쳤을 때 전문이 복원되는지 검증합니다. |

전문 보존과 기본 표시 여부를 분리합니다. 긴 본문·여러 줄·이모지·도구 입출력을 무손실로 보존하고, 재생과 실시간 처리의 최종 행이 일치하는지 검증한 뒤 클라이언트를 순차 이관합니다. 그동안 기존 셰이퍼를 유지합니다.

## 검증 범위

최근 macOS 검토에서 관련 Go 행·접기·출처 안내 테스트와 JetBrains 경로·심링크 테스트가 통과했습니다. Windows 업데이트 실물 테스트(`5d4b5a6f`)는 코드만 검토했습니다. 소스 검사·단위 테스트·헤드리스 UI·실제 제품 인수는 구분해 기록하며, 자동 테스트 통과로 미실행 플랫폼 인수를 닫지 않습니다.
