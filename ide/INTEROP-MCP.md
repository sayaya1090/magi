Status: **검토 의견.** 인용한 코드는 이날 직접 열어 확인했다.

## 0. 먼저, 받은 것

`INTEROP.md` §5의 관찰 셋을 **전부 확인하고 전부 반영했다.** 셋 다 내 쪽이 틀렸다.

| | 지적 | 확인 | 반영 |
|---|---|---|---|
| (a) | `<socket>.stopped`를 쓰지 마라 — 유도된다 | `Serve` defer가 `ln.Close()` → `os.Remove(d.path)` → `release()` 순. 깨끗한 종료는 파일을 지우고 SIGKILL은 남긴다 | 표식 폐기. "파일 없으면 안 살림, 있는데 dial 실패면 살림"으로 교체 (`DESIGN.md` §5.3·§5.4) |
| (b) | 작별 프레임은 락스텝을 깬다 | `daemon.go`의 불변식 주석, `watch`가 유일한 예외 | §5.5에 명시. 죽음은 연결 끊김으로만 안다 |
| (c) | unlink 앞에 dial 프로브가 빠졌다 | `claimPath` → **`net.Dial`** → `os.Remove`. 코드 옆 주석: *"This Remove is only safe BECAUSE the dial above proved nothing is listening"* | 흐름도에 프로브 분기 추가 (`DESIGN.md` §5.3) |

(c)가 제일 아팠다. 나는 "락을 먼저 잡으면 안전하다"고 썼는데 **락이 안전을 만드는 게 아니었다.**
클레임을 모르는 옛 빌드가 살아있는 소켓을 쥐고 있으면 락은 비어 있고, 그대로 지우면 남의 리스너를
조용히 고아로 만든다. 자기 업데이트가 있는 제품이라 실제로 오는 상황이라는 지적도 맞다.

§1~§4는 이견 없다. 특히 §1의 "연동 질문 자체가 없어졌다"와 §4의 "공유 패키지는 안 만들고 시나리오
표를 공유한다"에 동의하고, §4의 세 시나리오는 `DESIGN.md` §9에 문장 그대로 넣겠다.

이 문서는 **새로 나온 것만** 적는다. 세 개다.

## 1. §3의 "고침의 모양은 작다"가 사실이 아니다 — 세 층이다

§3이 착수 전 확인할 것 둘을 남겼다. 둘 다 확인했고, **답이 둘 다 부정적이다.** 그리고 확인하는
김에 세 번째 층이 나왔다.

### 층 1 — `contentBlock`에 필드 추가 (작다, §3이 맞다)

`Data`·`MimeType`을 더하는 것. 이건 정말 작다.

### 층 2 — 툴 결과에는 이미지를 실을 자리가 없다

§3이 물은 것이다. 답: **없다.**

```go
// internal/core/session/session.go
type ToolResult struct {
	CallID  string          `json:"callId"`
	Content json.RawMessage `json:"content"`
	IsError bool            `json:"isError,omitempty"`
	// Advisory …
}
```

이미지 슬롯이 없다. 그리고 한 층 위가 더 문제다 — `Part`는 **태그드 유니온**이고 주석이
그렇게 못 박았다: *"Exactly one of the kind-specific fields is populated, selected by Kind."*
즉 **한 파트는 툴-결과이거나 이미지이지 둘 다일 수 없다.**

거기에 `ImageRef`는 바이트가 아니라 **참조**다:

```go
type ImageRef struct {
	Path string `json:"path"`
	MIME string `json:"mime"`
}
```

MCP가 base64로 준 것을 어딘가 파일로 쓰고 그 경로를 실어야 한다는 뜻이다. 스크래치에 쓸지,
언제 지울지, 리플레이 때 그 파일이 아직 있어야 하는지가 전부 새 질문이다.

선택지 셋이고 셋 다 대가가 있다.

| | 방법 | 대가 |
|---|---|---|
| A | `ToolResult`에 이미지 필드를 더한다 | 국소적이지만 유니온의 규율을 흐린다 |
| B | 툴 결과 뒤에 이미지 파트를 하나 더 붙인다 | 재구성기와 모든 렌더러가 기대하는 메시지 구조가 바뀐다 |
| C | 헬퍼가 PNG를 파일로 쓰고 경로만 텍스트로 돌려준다 | **magi 변경 0.** 대신 모델은 경로만 보고 픽셀은 못 본다 |

C가 공짜라서 솔깃한데, **C는 §2.2를 만족시키지 못한다.** 경로는 증거가 아니다.

### 층 3 — 모델에게 이미지를 보내는 경로가 애초에 없다 ← 이게 진짜다

층 1·2를 다 해도 모델은 여전히 이미지를 못 본다. **OpenAI 어댑터가 이미지를 안 보낸다.**

전 소스에서 `PartImage`를 읽는 비-테스트 코드가 **딱 하나**다:

```
cmd/magi-web/main.go:1591:   case session.PartImage:
```

콘솔이 사람에게 그려 주는 자리다. `internal/adapter/llm/openai/`에는 `PartImage`도
`image_url`도 없다. 요청 조립이 텍스트 전용이다.

그러니 이미지 증거를 쓰려면 **멀티모달 요청 조립을 새로 만들어야** 하고, 그건 magi가 한 번도
가진 적 없는 기능이다. 백엔드마다 모양이 다르고(OpenAI `image_url` vs 다른 것들), 모델이 이미지를
받는지 확인해야 하고, 못 받는 모델에서 무엇으로 대체할지 정해야 한다 — §3이 남긴 두 번째 확인
사항이 사실은 여기 걸려 있다.

### 덤으로 나온 것: `model.Vision`은 아무도 안 읽는 플래그다

```go
// internal/core/model/model.go:17
Vision        bool    // supports image input
```

gpt-4o, claude-opus-4-8, claude-sonnet-4-6, gemini 셋, grok-4에 `Vision: true`가 붙어 있다.
**그런데 그 값을 읽는 곳이 없다.** 어댑터가 이미지를 안 보내므로 읽을 이유도 없었다.

이 저장소가 이 결함 계열에 이름을 붙여 뒀다 — `MAGI_COUNCIL_KEEP`이 주석에만 광고되고 아무도 안
읽어서 기능 전체가 도달 불가였던 것, `MAGI_STEP_VERIFY`와 `MAGI_MAX_PLAN_DEPTH`가 주석에만 살아
있던 것. DIAGRAMS 부록이 *"advertising drift는 이 저장소가 반복해서 맞은 결함 계열"*이라고 적었다.
`Vision`은 같은 계열이고, **PowerPoint와 무관하게 별건으로 볼 값이 있다.**

### 그래서 결론이 바뀐다

§3은 "막고 있는 것 하나"라고 했는데, 정확히는 **막고 있는 것 셋이고 그중 하나는 새 기능**이다.
내 쪽 문서도 이걸 "작은 수정"으로 적었으므로 같이 틀렸다. `DESIGN.md`의 S7과 §7을 그에 맞게
고쳤다 — 픽셀 증거는 **M4의 전제가 아니라 M4 이후의 확장**으로 내리고, 그전까지 판정은 기록
증거만으로 돈다.

## 2. §6의 마지막 질문에 답한다 — 데몬 둘이 한 덱을 만질 때

> 헬퍼가 여러 magi 데몬에게 동시에 도구를 줄 때의 범위. 워크스페이스 둘이 같은 덱을 만지면
> 누가 이기는지는 `DESIGN.md` §5.6이 다루지만, magi 쪽에서 그게 어떻게 보이는지는 아직 안 그렸다.

§5.6은 **애드인이 여럿일 때**(창이 여럿)를 다뤘지 **magi 데몬이 여럿일 때**는 안 다뤘다.
지적이 맞고, 후자가 더 나쁘다.

**왜 더 나쁜가.** magi의 "한 워크스페이스에 한 턴"은 **프로세스 하나가 보장하는 것**이다.
데몬 A(저장소 1)와 데몬 B(저장소 2)는 별개 프로세스라 **동시에 턴을 돈다.** 둘 다
`[mcp.ppt]`를 갖고 있으면 둘 다 같은 덱에 `set_text`를 부를 수 있고, 그 사이에는 아무것도 없다.

**두 결과가 나오고, 두 번째가 조용하다.**

1. **쓰기 충돌.** 명백하고, 답도 명백하다 — **헬퍼가 문서 단위로 직렬화한다.** §5.6의 "한 문서에
   손은 하나"를 손(애드인)이 아니라 **호출자(magi 데몬)** 쪽으로도 확장해야 한다. 두 번째
   데몬의 쓰기는 기다리거나 거절되고, 거절이면 이유가 "다른 워크스페이스가 이 덱을 쓰는 중"이어야
   한다. 조용한 실패나 조용한 성공 둘 다 안 된다.

2. **거짓 완료.** 이게 조용한 쪽이다. **카운슬은 자기 데몬의 기록을 읽는다.** 데몬 A의 기록에는
   데몬 B가 한 편집이 없다. 그러니 A가 "슬라이드 3의 제목을 X로 바꿨다"를 자기 기록으로 확인하고
   done을 선언하는 동안, B가 그사이 그 제목을 Y로 덮었을 수 있다. **A의 기록은 참이고 A의 결론은
   거짓이다.**

   이건 §2.3(읽기 천장)이나 §2.2(픽셀 증거)로 안 잡힌다. A가 렌더를 떠도 그건 A가 마지막으로
   본 시점의 픽셀이고, 판정과 실제 사이에 B의 창이 있다. 이 저장소가 종료 판정에 쏟은 것이
   정확히 "기록이 실제와 어긋나는" 경우를 막는 것이었는데, **여기서는 기록이 맞는데 세계가
   움직인다.**

   막는 방법은 하나뿐이다 — **덱을 만지는 턴 동안 그 덱을 잠근다.** 도구 호출 단위가 아니라
   **턴 단위**로. 그런데 헬퍼는 magi의 턴 경계를 모른다(MCP에 그런 개념이 없다). 그래서 세 안이 있고,
   지금 고를 근거가 없다:

   | | 안 | 문제 |
   |---|---|---|
   | ㄱ | `lock_deck` / `unlock_deck`를 도구로 낸다 | 모델이 unlock을 안 부르면 덱이 영영 잠긴다. 리스로 시간 상한을 둬야 하고, 그러면 상한을 얼마로 할지가 또 미정 |
   | ㄴ | 첫 쓰기에 암묵으로 잠그고 유휴 N초에 푼다 | 모델이 몰라도 되지만 N을 잘못 잡으면 정상 작업이 서로를 막는다 |
   | ㄷ | 안 잠근다. 대신 매 쓰기 결과에 "그사이 남이 이 슬라이드를 바꿨다"를 실어 보낸다 | 막지 않고 **보이게만** 한다. 이 트리의 취향에 가장 가깝다 — 가드는 보고하고 결정하지 않는다 |

   **ㄷ이 맞다고 본다.** 이유는 magi 자신의 판례다. 가드가 자기 산술로 런을 멈추던 것을 걷어낸
   근거가 "멈춰서 얻은 것이 없다"는 실측이었고, 남은 것은 전부 **말하고 모델이 정하게 두는**
   모양이다. 덱 잠금도 같은 모양으로 두는 게 일관적이고, 무엇보다 ㄱ·ㄴ은 **잘못 잠갔을 때
   빠져나올 길이 없다.**

   다만 ㄷ에는 조건이 붙는다. "그사이 바뀌었다"를 말하려면 헬퍼가 **슬라이드별 개정 카운터**를
   들고 있어야 하고, 그건 상태다. 소켓 파일처럼 유도되는 종류가 아니라 헬퍼가 기억해야 하는
   것이라, 헬퍼가 재시작하면 사라진다. 사라졌을 때는 **"모른다"를 말해야지 "안 바뀌었다"를
   말하면 안 된다.**

## 3. 작은 이견 하나 — §4의 "서로 빌린 것"에 하나 빠졌다

§4가 빌린 것을 정리하면서 `ide/README.md` §2가 그쪽 §5.3에서 백오프·지터와 "못 붙었을 때
말하기"를 가져갔다고 적었다. 맞다. 여기에 하나 더 있는데, **방향이 반대라 적어 둘 값이 있다.**

`ide/README.md` §2의 **"세 가지 실패를 구분하지 않는다"**는 내 쪽이 못 하던 것이다. 내 첫
흐름도는 "파일 없음"과 "파일 있는데 거부됨"을 갈래로 나눠 그렸는데, 나눌 이유가 없었다 —
둘 다 답이 같고, 나누면 그 사이에 틈이 생긴다. 그쪽 문장이 그걸 한 줄로 정리했고 지금은 내
흐름도도 하나로 합쳐져 있다.

빌림 목록에 이걸 넣자는 이유는 예의가 아니라, **§4가 말한 "시나리오 표"에 이 항목이 들어가야
해서다.** "네 갈래를 만들고 결과가 하나인지 본다"는 시험은 구현이 갈래를 *구분하지 않아야*
통과한다. 그 의도가 표에 안 적히면 다음 사람이 갈래를 다시 나눈다.

## 4. 남는 것

| | 무엇 | 누구 | 바뀐 점 |
|---|---|---|---|
| 1 | **`model.Vision`이 죽은 플래그다**(§1 끝). PowerPoint와 무관한 별건 | magi | 새로 나옴 |
| 2 | 이미지 증거는 **세 층**이고 층 3은 새 기능(§1) | magi | §3의 "작다"를 정정 |
| 3 | 데몬 둘이 한 덱을 만질 때의 **거짓 완료**(§2). 안 ㄷ 추천 | powerpoint-agent | §6 질문에 답 |
| 4 | 시나리오 표에 "갈래를 구분하지 않아야 통과"를 명시(§3) | 셋 다 | 새로 나옴 |
| 5 | `DESIGN.md` §9에 §4의 세 시나리오를 문장 그대로 | powerpoint-agent | 받음 |

**우선순위가 바뀌었다.** 이미지가 세 층이면 그건 M4를 막는 것이 아니라 M4 다음이다.
`DESIGN.md`를 그렇게 고쳤고, 그 결과 **판정은 당분간 기록 증거만으로 돈다** — 코딩 에이전트와
같은 조건이다. §2.2가 주장한 우위는 유효하되 **아직 없는 우위**이고, 문서가 그렇게 말해야 한다.

## 5. 두 문서를 합칠 것인가

이 파일과 `INTEROP.md`는 같은 목적이고, 지금은 §1~§4가 거의 겹치지 않는다(그쪽은 경위와 관찰,
이쪽은 그 답과 새 발견). 당장은 나눠 두는 편이 읽기 쉽다.

다만 한 번 더 왕복하면 겹치기 시작할 것이다. 그때는 **`INTEROP.md`를 정본으로 두고 이 파일을
접는 쪽**을 제안한다 — 그쪽이 먼저 있었고 경위를 갖고 있다.
