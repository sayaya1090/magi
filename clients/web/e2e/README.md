# 브라우저에서 콘솔을 눌러 보는 시험

여기 있는 것은 **화면이 실제로 도는 동안**만 답할 수 있는 질문들이다 — 무엇이 그려졌나, 받은 값을
어떻게 다루나, 누른 것이 **데몬에 닿나**, 그리고 **회선에 무엇이 몇 번 나갔나**. 마지막 것이 이
자리가 생긴 이유다: 상세를 열면 `/jobs`·`/cron`이 스물두 번 나가던 결함이 있었고, 카드마다 「답이
같으면 다시 그리지 않는다」는 검사가 있어 **화면은 조용했다.** 그리기만 보는 시험은 그것을 영원히
못 본다.

## 무엇을 상대로 도는가

**진짜 데몬 둘과 진짜 `magi-web`**이다(`serve.mjs`가 세운다). 콘솔의 정적 데모로도 화면은 뜨지만,
거기서는 명단이 흐르지 않고 목이 fetch 앞에서 답을 가로챈다 — 그것을 상대로 재면 **규칙을 걷어내도
초록이 나온다**(실측했다). 데몬을 둘 세우는 이유도 같다: 하나뿐인 명단에서는 「컴패니언마다 한 번」과
「콘솔마다 한 번」이 같은 수를 낸다.

데몬은 턴을 돌리지 않는다. 이 화면들이 묻는 것(명단·잡·크론·모델 목록·승인 모드)은 전부 그 프로세스가
제 상태에서 답하는 것이라, 모델도 열쇠도 없이 선다. 자리는 매 런 새 임시 디렉토리이고, 어디에 세웠는지는
`.harness.json`에 적힌다(시험은 다른 프로세스라 그것 없이는 화면이 그린 경로가 진짜인지 못 가린다).

## 돌리기

    cd clients/web/ui && ./gradlew assembleConsole && cd -
    cd clients/web/e2e && npm install && npx playwright install --with-deps chromium
    npx playwright test

콘솔은 **미리 조립돼 있어야 한다** — 없으면 `serve.mjs`가 그 자리에서 멈추고 어느 명령이 빠졌는지
말한다. `magi`와 `magi-web`은 시험이 직접 빌드한다. 포트는 `MAGI_E2E_PORT`(기본 8199).

## 무엇을 재는가

| 파일 | 재는 것 |
| --- | --- |
| `asking.spec.mjs` | 열어 둔 화면이 회선에 몇 번 묻는가 |
| `detail.spec.mjs` | 명단 행이 실은 사실을 상세가 채워 그리는가 |
| `controls.spec.mjs` | 고른 것이 **데몬에** 닿는가, 고르개가 무엇을 내놓는가 |
| `screens.spec.mjs` | 레일의 문마다 화면이 서는가(그리다 터지지 않는가) |

## 이 시험들이 못 재는 것

`asking.spec.mjs`의 **첫 번째**는 회귀의 상한을 지키는 것이지 그 회귀를 재현해 잡는 것이 아니다.
한가한 컴패니언들 앞에서는 「명단이 바뀔 때마다 다시 묻기」와 「제 시계로 묻기」가 같은 수를 낸다 —
규칙을 걷어내고 재 봤고 셋씩으로 같았다. 재현하려면 실제로 도는 컴패니언이 필요하다(사람이 본 스물두
번은 그런 기계에서 났다). 같은 파일의 나머지 둘과 `detail`·`controls`의 값 검사들은 다르다: 고침을
빼고 재면 빨개진다(전부 실측했다).
