# web/ — 웹 콘솔 아키텍처 및 컷오버 기록

기존 단일 페이지 기반 웹 콘솔은 2026년 8월 29일 자로 완전히 대체되었습니다. 과거 `clients/web/server`가 서빙하던 레거시 자산(`page.html`, `page.js`, `page.css`) 및 개발용 프록시 서버는 제거되었으며, 현재 `clients/web/server`는 BFF(Backend For Frontend) 역할을 전담하고 본 디렉토리의 멀티모듈 산출물을 `/` 루트 경로에서 서빙합니다.

GWT 컴파일에는 JDK와 Gradle 도구체인이 필요하므로, Go 개발자가 불필요한 Java 빌드 환경에 종속되지 않도록 정적 자산 조립은 **CI 파이프라인에서 전담**합니다(`release-web.yml`, `test-web.yml`). 저장소의 `clients/web/server/console/`에는 자리지기 README만 커밋되어 있습니다. 콘솔 정적 자산이 포함되지 않은 상태로 빌드된 바이너리도 독립 BFF 서버로서 모든 API 경로에 정상 응답하며, `/` 접근 시 콘솔 자산이 미포함된 빌드임을 명확히 안내합니다. 로컬 개발 시에는 `magi-web -console clients/web/ui/build/console` 명령을 통해 디스크에 조립된 번들을 매 요청마다 즉시 다시 읽어 서빙할 수 있습니다.

UI 모듈별 상세 계약, 셸의 제어 흐름, 신규 화면 이식 절차 및 빌드 가이드는 [`ui/README.md`](ui/README.md)에 기술되어 있습니다.

```
web/
└── ui/       # GWT 멀티모듈 (Gradle) — 1개 화면 = 1개 독립 모듈
    ├── console-bridge/  # 셸↔화면 연동 규약: Render/Uri/Label 공유, SSE 단독 소유, FetchApi 추상화
    ├── ui-components/   # 공용 위젯 (트랜스크립트 렌더러, 게이지, 컴포저 등)
    ├── shell-ui/        # 레일, 마스트헤드, 테마, i18n, 라우팅, 모듈 주입(ModuleResolver)
    ├── fleet-ui/        # 컴패니언 목록 관리
    └── companion-ui/    # 컴패니언 상세 및 기본 타입 UI
```

## 컴패니언 타입별 고유 UI 구조

컴패니언 상세 화면은 단일 고정 모듈이 아니라, 컴패니언의 **타입(Type) 메타데이터를 기반으로 동적 해석(Resolve)**됩니다:

```
셸 ModuleResolver: (destination | companion.type) → 모듈 스크립트 경로
  companion 상세 진입 → 해당 컴패니언의 type 속성 조회 → 전용 모듈 존재 시 해당 모듈 로드
                                                      → 미존재 시 companion-ui(기본 모듈) 로드
```

- **연동 규약**: 타입 전용 UI 모듈 또한 `console-bridge` 계약(Render 등록 및 `CompanionContext` 수신: socket, type, peer)을 준수합니다. 기본 제공되는 `companion-ui`가 해당 계약의 표준 레퍼런스 구현체입니다.
- **매니페스트 관리**: 초기에는 셸 내부 상수 매핑으로 관리되며, 추후 동적 등록이 필요할 경우 BFF 라우트(`/ui-manifest`)로 확장 가능하도록 설계되었습니다.
- **보안 격차 불변식**: UI 모듈은 **시스템 오퍼레이터가 사전에 검증하고 설치한 것만** 로드합니다. 대상 컴패니언이나 워크스페이스가 임의로 전송한 스크립트를 관리자 콘솔에 로드하는 행위는 엄격히 금지됩니다(`.magi/plugins`의 보안 정책과 동일).
- **타입 메타데이터 출처**: 컴패니언 선언 레코드에서 공급되며, 셸은 `/fleet` 응답 데이터에 실려 온 값을 읽어 라우팅을 수행합니다.

## 프론트엔드 아키텍처 (클린 아키텍처)

모든 모듈의 의존성 흐름은 `interfaces → usecase → domain` 단방향을 엄격히 유지합니다. `console-bridge`는 각 화면 모듈이 공유하는 커널(브라우저 창 브리지, 와이어 DTO, 언어 팩, 통신 유틸리티)로 동작합니다.

- `client/domain` — 순수 비즈니스 로직 및 규칙: 상태 순서 및 그룹화(`AgentStates`), 버전 비교(`Versions`), 시간 축약(`Spans`), 명단 필터링 및 정렬(`Roster`). DOM에 전혀 의존하지 않습니다.
- `client/usecase` — 포트 인터페이스 및 스토어: `FleetRepository`(읽기 포트), `FleetCommander`(제어 명령 포트), `FleetStore`(초기 데이터 로드 및 SSE 스트림 소유권 관리).
- `client/interfaces` — 어댑터 구현체: `api/FetchFleetRepository`(`/fleet` + `/events` SSE), `api/FetchFleetCommander`(`/interrupt`, `/answer`), `FleetElement`(루트 컴포넌트), `CardListElement`(목록 카드 행 및 렌더링 캐시). 마크업 구조는 기존 `console.css` 스타일 계약과 호환됩니다.
- 의존성 주입: Dagger를 통해 포트에 구현체를 결합(`FleetModule`)하며, 테스트 환경에서는 동일한 위치에 가상 구현체를 결합(`FleetTestModule`)하여 HTTP mock 없이 순수 UI 로직을 검증합니다.

## 주요 서브시스템 구현 상세

### 1. 셸 드로어
- 사이드 레일(#rail) 구현: 햄버거 메뉴 애니메이션, 너비 제어(`nav=open`) 및 시각 스타일(`nav-wide`, 닫힘 시 250ms 지연)을 분리한 2속성 상태 머신을 적용했습니다.
- 스크림(scrim) 클릭 시 닫힘 처리, 키보드 방향키 탐색, URL 라우팅(`?v=` 쿼리 파라미터 및 `pushState`/`popstate`)을 지원합니다.
- `RenderStore`가 목적지별 렌더러 함수를 캐싱하여, 화면 재방문 시 스크립트를 재주입하지 않고 즉시 재렌더링하도록 처리했습니다.

### 2. 마스트헤드 및 단일 스트림 소유권
- **브라우저 창당 단일 스트림 원칙**: 셸의 `RosterStore`가 `/events` SSE 연결을 독점적으로 소유하고, `RosterSharing`(window `__magi_roster_subscribe`/`__magi_roster_refresh`) 인터페이스를 통해 하위 화면에 분배합니다.
- 상태 표시줄: 연결 상태(live, asking, lost), 총 컴패니언 수, 대기 중인 작업 카운트 및 점프 링크를 제공합니다.
- 툴팁 및 알림 채널: 단일 전역 팁 컨테이너(`TipElement`)를 두고 개별 화면은 `data-tip` 속성만 선언하도록 일원화했습니다. 마우스 호버뿐 아니라 키보드 포커스 및 모바일 길게 누르기(0.5초) 동작을 모두 지원합니다.

### 3. 경과 시간(Age) 클라이언트 타이머 기전
- 백엔드 명단 프레임은 단순 경과 시간에 대해 프레임을 매초 재송출하지 않습니다. 과거에는 이로 인해 컴패니언이 유휴 상태로 전환된 직후의 시간("방금")에 텍스트가 영구 고정되던 결함이 있었습니다.
- 이를 해결하기 위해 엘리먼트의 `data-since` 속성에 최종 수신 시점의 절대 타임스탬프를 기록하고, 창 전체에서 단 1개만 동작하는 1초 주기 타이머(`component.Ages`)가 텍스트를 갱신하도록 구조를 개선했습니다.
- 실제 표시 문구가 달라지는 순간에만 DOM을 수정하여 불필요한 렌더링 부하를 원천 차단했습니다.

## 빌드 및 배포 방법

- **프론트엔드 모듈 빌드**:
  ```sh
  cd clients/web/ui && ./gradlew build
  ./gradlew assembleConsole
  ```
  `build/console/` 디렉토리에 전체 UI 번들이 집결됩니다. 의존성은 `gradle/libs.versions.toml`에서 중앙 관리됩니다.
- **BFF 서버 빌드**:
  ```sh
  go build ./clients/web/server
  ```
  Java 도구체인이 없는 환경에서도 독립적으로 빌드 가능합니다.
- **로컬 개발 실행**:
  ```sh
  go run ./clients/web/server -console clients/web/ui/build/console
  ```
  디스크 상의 UI 정적 자산을 요청마다 실시간으로 읽어 서빙하므로, 프론트엔드 재빌드 후 브라우저 새로고침만으로 변경 사항이 즉시 반영됩니다.
