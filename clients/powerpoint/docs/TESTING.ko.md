# 무엇을 어디서 재나 — PowerPoint 레인

[↑ 설계](../DESIGN.md) · [사용자 매뉴얼](./MANUAL.ko.md) · [헬퍼](../helper/README.md) · [애드인](../addin/README.md)

> **왜 이 문서가 있나.** 이 레인의 시험은 층이 다섯이고, 층마다 **도는 조건이 다르다.** 어떤
> 것은 `go test` 한 줄이면 돌고, 하나는 진짜 데몬이 있어야 돌고, 두 층은 **PowerPoint 와 사람의
> 손**이 있어야 돈다. 그 조건을 모르면 「초록이니까 됐다」가 「그 층은 애초에 안 돌았다」와 같아
> 보인다 — 이 레인은 그 착각을 오래 안고 있었다. 헬퍼가 전부 초록인 채로 **PowerPoint 에 한 번도
> 안 붙어 본 날들**이 있었고, 붙인 첫날 5층에서만 결함 열둘이 나왔고, 이튿날 열아홉이 더 나왔다(§5.1).

⚠ **5층만 날짜가 뒤졌고, 그 사이 카탈로그가 27개에서 39개로 늘었다.** 열둘이 전수 스윕에 한 번도
안 들어갔다 — `add_chart` · `add_image` · `align_shapes` · `animate_slide` · `drop_suggestion` ·
`read_animation` · `read_notes` · `read_suggestions` · `read_tags` · `set_notes` · `set_tag` ·
`suggest`. 그중 여럿은 §5.1.1~5.1.3 에서 **하나씩** 실물에서 쟀다. 그건 스윕이 아니다 — 두 말을
한 줄에 적으면 「전수 통과」의 범위가 27개였다는 사실이 사라진다.

열 판(§7)이 그 열둘 중 **셋**을 실물에서 돌렸다 — `add_chart`(7판) · `set_notes`(7판) ·
`read_notes`(1판). **아홉은 여전히 한 번도 안 돌았다**: `add_image` · `align_shapes` ·
`animate_slide` · `drop_suggestion` · `read_animation` · `read_suggestions` · `read_tags` ·
`set_tag` · `suggest`. 모델이 자기 판단으로 고른 도구만 도는 자리라, 이 층은 **스윕을 대신하지
못한다** — 안 고른 것은 안 돈다.

## 1. 계약 — 규약대로 구는가

**이 층이 무는 것은 「우리가 남과 어떻게 맞물리기로 했는가」다.** 그래서 시험 이름이 곧 규칙이다.

| 규칙 | 시험 |
|---|---|
| 알림에는 **202** 를 준다(MCP 스펙의 MUST) | `ANotificationIsAcceptedWithTwoOhTwo` |
| 거절은 **도구 오류**로 오지 프로토콜 오류로 안 온다 | `RefusalsComeBackAsToolErrorsNotProtocolErrors` |
| 손이 없으면 **실패하고 사유를 댄다** | `WithNoAddinAttachedToolsFailAndSayWhy` |
| 문 둘 다 토큰을 요구한다 | `TheMCPDoorWantsTheToken`·`TheHandDoorWantsTheToken` |
| **연결이 둘이다** — 전사가 흐르는 동안에도 status 가 답한다 | `StatusAnswersWhileTheTranscriptIsStreaming` |
| 커서를 미는 것은 `seq > 0` 인 사건뿐 | `OnlyASeatedEventMovesTheCursor` |
| 한 번에 한 호출, 그러나 **한 호출은 반드시 돈다** | `OneCallAtATimeButOnlyOneCall` |
| 시한이 지나면 **누가 잘랐고 몇 초였는지** 말한다 | `ATimeoutSaysWhoCutItAndAtWhat` |
| 부르는 쪽이 포기한 것은 **애드인 잘못이 아니다** | `TheCallerGivingUpIsNotTheAddinsFault` |
| 아무도 안 기다리는 답은 **소리 내어** 거절한다 | `AnAnswerNobodyWaitsForIsRefusedOutLoud` |
| 모르는 문서는 **짐작 안 하고** 거절한다 | `AnUnknownDocumentIsRefusedNotGuessed` |
| 안 실린 문서는 **마지막으로 말한 덱**이 받는다 | `OmittingTheDocumentUsesTheDeckThatSpokeLast` |
| 저장 안 한 덱 둘은 **키가 둘**이다 | `TwoUnsavedDecksGetTwoKeys` |
| 같은 프레젠테이션으로 다시 붙으면 **키가 유지된다** | `RejoiningTheSamePresentationKeepsItsKey` |
| 판번호를 모르면 **「모른다」지 「안 바뀌었다」가 아니다** | `AMissingRevisionSaysUnknownNotUnchanged` |
| 인증서는 **이름 하나만** 덮는다(127.0.0.1) | `TheCertificateCoversTheOneName` |
| 개인키는 소유자만 | `ThePrivateKeyIsOwnerOnly` |
| 잡힌 포트는 **멈춤이지 우회가 아니다** | `ATakenPortIsAStopNotADetour` |
| 남의 리스너는 **지우지도 붙지도 않는다** | `AStrangerOnThePortIsRefusedNotAdopted`·`ATLSStrangerIsStillAStranger` |
| 애드인이 받는 것은 **캐시되지 않는다** | `NothingTheAddinLoadsIsCached` |
| 페이지가 **자기 토큰을 들고 나간다** | `ThePageCarriesItsOwnToken` |

## 2. 유도 가드 — 두 벌이 갈리는 것을 막는다

목록을 두 벌 적으면 안 재지는 쪽이 갈린다. 그래서 이 층은 **원천에서 유도한다.**

| 가드 | 무엇을 유도하나 | 시험 |
|---|---|---|
| 이름 넷은 한 문자열 | 매니페스트 XML 실물을 읽어 바인드·SAN·전송과 대조 | `TheFourNamesAreOneString` — 처음 돌렸을 때 매니페스트의 여덟 자리를 짚었다 |
| 애드인은 오리진을 **안 적는다** | `addin/` 전체를 훑는다 | `TheAddinDoesNotWriteTheOriginDown` |
| 매니페스트 스키마 순서 | XML 주석을 걷어 내고 `<Requirements>` 가 `<Hosts>` 앞인지 | `TheManifestKeepsTheSchemaOrder` |
| 허용 규칙은 「덱을 고치는가」로 갈린다 | 도구 표에서 규칙을 **만들어** 대조 | `AllowRulesCoverExactlyWhatDoesNotChangeTheDeck` |
| 스키마가 인자 검사를 켜 둔다 | **카탈로그 전부**의 `properties`·`required`·`additionalProperties` — 수를 안 적는 것이 일부러다(도구가 늘면 같이 자란다) | `EverySchemaKeepsTheArgumentCheckOn` |
| 도구 이름은 sanitize 를 견딘다 | magi 의 이름 규칙에 태워 본다 | `ToolNamesSurviveSanitizing`·`TheServerNameSanitizesToItself` |
| 서버 이름이 **내장 도구 이름과 안 겹친다** | 코어의 내장 목록과 대조 | `TheServerNameIsNotABuiltinToolName` |
| 읽기 도구도 **끝났다고 선언하는 법**을 설명에 싣는다 | 27개 설명문 | `ReadToolsSayHowToDeclareFinished` |
| **매뉴얼이 코드가 만든 허용 규칙을 그대로 옮겼는가** | `AllowRulesTOML()` 과 매뉴얼의 `allow = […]` 덩어리를 글자로 견준다 | `TheManualQuotesTheRulesWeGenerate` |
| **매뉴얼이 도구를 하나도 안 빠뜨렸는가** | 도구 표를 훑어 매뉴얼에서 이름을 찾는다 — 표에 없는 도구는 사람에게 없는 기능이다 | `TheManualNamesEveryTool` |
| **우리가 띄우는 컴패니언의 권한 모드** | `daemonArgs()` 에 `--permission ask` 가 있는가 — 안 묻는 것은 설정의 allow 규칙(덱 도구 전부·읽기·기억·검색, 2026-09-05) — 인자는 `Spawn` 이음매로 안 날라서 함수로 뺐다 | `TheCompanionWeStartAsksBeforeItChangesTheDeck` |
| **답은 stdout · 진단은 stderr** | `-version`·`-allow-rules`·`-cert-hint` 를 실제로 돌려 두 갈래를 본다 | `AnswersGoToStdoutAndDiagnosticsToStderr` |
| **그림이 글에 안 남는다** | `render_slide` 결과의 글 블록에 base64 가 없는가 | `ThePictureGoesOnceNotTwice` |
| **빈 배열은 인자 없음** | `[]`·`null`·`{}` 는 통과, 값이 든 배열은 거절 | `AnEmptyArrayIsAnEmptyCall` |
| **가이드: 끄는 것은 지우는 것이 아니다** | 추가·끄기·켜기·삭제와 이름 검사 | `DisablingIsNotDeleting` · `AGuideNameCannotBecomeAPath` |
| **가이드 설명은 모델이 받는 그것** | 프런트매터 → 없으면 첫 줄, magi 로더와 같은 규칙 | `TheDescriptionIsTheOneTheModelSees` |
| **문서가 적은 도구 수가 카탈로그와 같은가** | `len(catalogue())` 와 읽기/쓰기 갈래 수를 문서의 **정확한 문자열** 여섯 자리와 견준다. 정규식으로 안 훑는 것이 일부러다 — §5.1 의 실물 기록(「도구 28개」)은 그날 참이라 고칠 것이 아니다 | `TheDocsCountTheToolsWeAdvertise` — 처음 돌렸을 때 27·19·39 세 값이 갈려 있었다 |
| 생략했을 때의 뜻을 스키마가 적는가 | `slideProps` 와 도구 표 | `OmittingTheSlideMeansTheOneInFront` |
| 광고하지 않은 능력을 광고하지 않는다 | `set_table_cells` 는 서식을 안 건드린다 | `SetTableCellsAdvertisesNoFormatting` |

**매니페스트 순서 가드는 자기 바늘에 한 번 걸렸다.** 첫 판은 XML 주석 안의 `<Hosts>` 를 보고
울었다. 예외를 만들지 않고 **주석을 걷어 내고 보게** 고쳤다 — 스캐너가 제 바늘에 걸리는 것을
예외로 빼면 그 예외가 진짜 위반도 같이 가려 준다.

## 3. 상호운용 — 가짜 상대는 상대를 검사하지 않는다

**`MagisOwnClientAttachesToThisHelper`** 는 magi 의 진짜 MCP 클라이언트(`mcp.Manager.Attach`)를
이 헬퍼에 붙인다. 가짜 상대로 도는 시험은 **내가 상대를 어떻게 이해했는지**를 검사하지 상대를
검사하지 않는다 — 스펙이 MUST 로 적은 202 를 magi 가 유일하게 거절하던 시절, 스펙대로 만든
서버만 쫓겨났다.

**`attach_test.go`** 는 한 걸음 더 간다: `daemon.Listen`+`Serve` 로 **진짜 데몬을 세우고**
`mcp-detach`→`mcp-attach` 를 왕복한다.

| 규칙 | 시험 |
|---|---|
| 붙기 전에 **언제나 detach** | `AttachingAlwaysDetachesFirst` |
| 둘째 창이 첫째의 등록을 **안 뺏는다** | `ASecondWindowDoesNotStealTheFirstsRegistration` |
| 문 없는 컴패니언은 **못 고른다** | `ACompanionWithNoDoorCannotBeChosen` |
| 「못 물어봤다」 ≠ 「못 받는다」 | `NotAskedIsNotTheSameAsCannot` |
| 붙인 주소가 **우리가 내주는 그 주소**다 | `TheAttachedURLIsTheOneWeServe` |
| **진짜 데몬이 정말 하나는 섰다** | `ZZZAtLeastOneRealDaemonWasStarted` |

마지막 줄이 이 층의 계측기다. 데몬을 못 세우면 나머지 시험들이 조용히 「건너뜀」이 되는데, 그
스위트는 여전히 초록이다. **`ZZZ` 접두는 마지막에 돌라는 뜻이고**, 그 하나가 「이 층은 실제로
돌았다」를 증언한다.

## 4. 화면 규칙 — 값으로 재는 자리

작업창의 결정은 전부 `addin/src/ui/screen.js` 와 `src/domain/*` 에 있다. **DOM 을 안 만지고 값만
답하므로 잴 수 있다.** 뷰(`view.js`)가 하는 일은 부르고 대입하는 것뿐이다.

> 이 갈래는 실측에서 나왔다. 뷰에 심은 돌연변이 32개 중 **30개가 살아남았고**, 살아남은 줄은
> 거의 전부 DOM 코드 **안에 박힌 결정**이었다. 가짜 DOM 을 지어 재는 자리를 늘리는 것보다
> 결정을 재지는 자리로 옮기는 것이 쌌다.

`node tools/smoke.mjs` (725) 이 무는 것 중 몇 가지:

| 규칙 | 왜 |
|---|---|
| **대화 이름을 우리가 짓지 않는다** | 지어낸 이름에 붙으면 진짜 이벤트가 신원 그물에 전부 걸린다. 실물에서 그 화면을 봤다 — 덱은 바뀌었는데 창은 「보냈습니다」에 멈춰 있었다 |
| 남의 대화 이벤트는 안 섞인다 | 신원이 다른 이벤트를 조용히 섞으면 두 컴패니언의 로그가 한 화면에 선다 |
| 답은 **호출한 줄에** 접힌다 (`callId` 로) | 이름으로 짝지으면 세 번째 호출의 답이 첫 번째 줄에 붙는다 |
| **`isError` 하나로 ✗ 를 안 찍는다** | `advisory` 는 「했는데 읽을 것이 붙었다」다. 창 둘이 성공한 쓰기를 실패로 그린 적이 있다 |
| 짝 없는 답도 **줄이 선다** | 로그 중간부터 읽기 시작했다는 사실이다 |
| 말 없는 표를 **기권으로 안 적는다** | `CouncilVerdictData.Silent` — 백엔드가 죽은 것과 판단한 기권은 다르다 |
| 모르는 종류를 **안 버린다** | 버리면 화면이 「아무 일도 없었다」처럼 보인다 |
| **안 그리기로 한 것**과 **못 그리는 것**은 다른 줄 | 한 문장으로 합치면 「고칠 게 있다」와 「이대로가 맞다」가 같은 말이 된다 |
| `prompt.submitted` 는 **배우를 보고** 그린다 | 안 보면 정책이 한 일이 사용자 말풍선으로 붙고, 사용자 줄 수가 늘어 **사람이 적던 글이 지워진다** |
| 델타와 완성본은 **같은 줄** | 둘 다 쌓으면 모델의 답이 두 번 뜬다 |
| 붙기 전의 창은 **「고장 났다」고 말하지 않는다** | 고르라는 화면 위에 「데몬에 안 닿습니다」가 겹쳐 뜨면 사람은 고르기 전에 고장 난 줄 안다 |
| 끊김과 **되살아남**을 둘 다 알린다 | 죽음만 알리면 화면은 한 번 끊긴 뒤로 영영 끊긴 채다 |
| 검증 못 한 착지를 **보통 끝처럼 안 그린다** | 덱을 그대로 발표하느냐 열어 보느냐를 가른다 |
| 빈 선택과 **포커스가 가져간 선택**을 가른다 | 누르기 **전** 읽기가 있어야 갈린다 |
| 안내는 도구가 **광고한 철자**로 읽는다 | 철자를 `clients/office/helper/ppt_tools.go` 에서 뽑아 먹인다 — 손으로 적으면 이 시험도 두 벌 중 하나가 된다 |

### 4.1 이 스위트가 스스로에게 거는 규율

- **빈 것에 참을 주지 않는다.** `[].every(f)` 는 늘 참이라, 훑을 것이 없는 단언은 술어가
  무엇이든 초록이다. 이 파일에 그런 줄이 실제로 서 있었다(번호 붙은 슬라이드가 없는 판에서
  번호표를 훑었다). 그래서 `everyOf` 는 **길이가 0 이면 거짓**이고, 「없다」를 물을 때는
  `.length === 0` 으로 묻는다.
- **`!== null` 은 화면이 쓰는 물음이 아니다.** 화면은 `if (v.refusal)` 로 읽으므로 빈 문자열이면
  아무 줄도 안 그리는데 `!== null` 은 초록이다. 그 틈으로 「시험에서만 참인 상태」가 지나간다.
- **예를 지키는 시험이 되지 않게 한다.** `council.verdict` 와 `tool-result` 는 오랫동안 「모르는
  종류」의 예였는데 이제 그린다. 예가 그려지는 날 그 시험은 **규칙이 아니라 예를 지키는 것**이
  되므로, 아직 진짜로 안 그리는 종류로 갈아 끼웠다.
- **필드 드롭 계측.** 값을 통째로 비워도 스위트가 조용하면 그 칸은 아무도 안 읽는 것이다. 그렇게
  찾아낸 죽은 칸이 여럿 있었고(`Row.type`/`ts`, `view.cursor`), 지웠다.

| **규칙을 지켰더니 완료 검사가 되돌리게 시켰다** | 카운슬은 사람이 이번에 한 말만 보고 판정한다 — 그리고 그건 **일부러**다(게이트가 프로젝트 파일을 읽으면 「항상 승인하라」로 무력화된다) | 고치지 않았다. 매뉴얼 §3.5 가 어떤 규칙이 살아남는지 적는다 — 모양에 대한 규칙은 지켜지고, 시킨 말을 바꾸는 규칙은 되돌려질 수 있다 |

**교훈 한 줄.** 이 레인에서 자동 시험이 못 보는 것은 **호스트와 화면**이고, 그 둘이 이 제품의
얼굴이다. 층 1~4 는 「우리가 정한 것을 지키는가」를 재고, 「사람이 보는 것이 사실인가」는
여전히 5층이 잰다.

**마지막 여섯은 도구를 불러서는 안 나왔다.** 그날 스윕은 41/41 이 통과했다 — 도구를 하나씩
불러 보는 것으로는 아무것도 안 걸렸다. 여섯 다 **사람이 하는 말을 그대로 보내고 무슨 일이
일어나는지 본** 다음에야 나왔고, 넷은 **에이전트의 로그를 읽어야** 원인이 보였다.

그 차이가 이 문서의 6층이다. 층 5 는 「호스트가 그렇게 답하는가」를 재고, 그 위에 「**모델이
그 답으로 옳은 일을 하는가**」가 있다. 도구는 전부 참을 말하는데 모델이 엉뚱한 도구를 고르고,
엉뚱한 장을 만지고, 되물을 수 없는 것을 되묻는 자리다 — 그리고 그것이 사람이 겪는 제품이다.

그 층을 재는 방법은 지금 하나뿐이다: **말을 걸고, 덱을 COM 으로 읽고, 세션 로그를 읽는다.**

**마지막 하나는 이 레인 바깥에서 왔다.** 데몬이 안 뜨는 문제는 PowerPoint 클라이언트의 코드가
아니라 magi 코어의 기동 경로에 있었고, **클라이언트를 실물에 붙여 보지 않았으면 아무도 안 봤을
것**이다 — 사람이 터미널에서 띄우는 데몬은 답할 터미널이 있으니 빠르다. 런처가 띄우는 첫 클라이언트가
그 자리를 처음 밟았다.

**2026-09-02 의 그 앞 셋은 또 결이 다르다.** 앞의 것들은 실물에 붙여 보고 나온 것인데, 이 셋은
**리뷰가 읽어서** 나왔다 — 겹쳐 쌓기는 계산으로 짚은 뒤 실행으로 재현했고, 스텁 구멍은 「쓰기를
지우고 시험을 돌려 보니 전부 초록」으로 증명됐다. 5층이 못 본 것을 리뷰가 봤다는 뜻이 아니라,
**시험이 스스로 눈이 먼 자리는 시험을 돌려서는 못 찾는다**는 뜻이다. 그 자리를 찾는 방법은 지금
둘뿐이다: 실물에 붙여 보기, 그리고 다른 눈이 코드를 읽기.

### 5.1.1 2026-09-03 — 리뷰 열, 그리고 실물만 볼 수 있었던 하나

차트·그림·노트·메모 넷을 붙인 뒤 리뷰를 받았다. 열 개가 나왔고, 그중 셋은 **이 저장소가 제일
싫어하는 모양**이었다.

| 무엇 | 어떻게 나왔나 |
|---|---|
| `set_tag` 가 **저장 안 된 키를 저장했다고** 답했다 | 리뷰가 읽었다 |
| `read_slide` 가 노트를 아직 **「못 읽는 것」**에 적었다 — `read_notes` 가 생긴 뒤에도 | 리뷰가 읽었다 |
| OOXML 로 가는 넷에 **실행 시험이 하나도 없었다** | 리뷰가 읽었다 |
| 가짜 손이 차트·그림을 **덱 끝**에 넣었다(실물은 짚은 장 바로 뒤) | 리뷰가 읽었다 |
| 뼈대 걷기가 **선·조건부 채움·묶음**을 남겼다 | 리뷰가 읽었다 |
| 차트·그림 장이 **남의 발표자 노트**를 물려받았다 | 리뷰가 읽었다 |
| 차트 기본 너비가 **4:3 덱에서 넘쳤다** | 리뷰가 읽었다 |
| 되읽기가 **낡은 값**을 줬다 | **실물에 붙여 보고** |

#### 시험이 스스로 눈이 멀었던 자리

세 번째가 제일 나빴다. `node tools/officehand.mjs` 는 초록이었고 도구를 전부 불러 보는 검사도
있었는데, 그 검사는 「모르는 도구」만 실패로 셌다. 스텁의 `exportAsBase64` 가 zip 이 아닌
글자를 주므로 `add_chart` 는 네 줄째에서 죽었고, **그게 통과로 세어졌다.** `#addChart` 의
본문을 통째로 `throw` 로 바꿔도 초록이었다.

고친 방법은 단언을 더하는 것이 아니라 **스텁이 진짜 zip 을 내주게** 한 것이다(`fakePackage`).
그러고 나니 넣기로 들어간 꾸러미를 도로 풀어서 잴 수 있게 됐고, 위의 네 결함 중 셋이 그
시험에 걸린다 — 지워 보고 빨개지는 것을 확인했다.

#### 여덟 번째는 실물만 볼 수 있었다

`set_tag` 를 고치면서 **쓴 것을 되읽어** 답하게 했다. 스텁에서는 완벽하게 돌았다. 실물에서는:

```
거절: 메모를 붙였는데 되읽으니 없습니다 — 슬라이드 295#… 의 'magi.check2'
```

그런데 `read_tags` 로 따로 물으면 **그 메모는 덱에 있었다.** 쓰기는 갔고, **같은 묶음 안에서
같은 프록시를 다시 `load` 한 되읽기가 쓰기 전 목록을 줬다.** 장을 새로 잡아 읽으니 맞았다.

스텁에는 그런 캐시가 없다. 그래서 이건 **우리 가지로는 영영 안 잡히는 갈래**이고, 리뷰도 못
봤다 — 코드만 읽어서는 호스트가 캐시를 언제 버리는지 알 수 없다. 5층(실물)이 있어야만 보이는
것이 아직 있다는 뜻이다.

### 5.1.2 2026-09-03 — 그림이 같아서 안 보였던 것

애니메이션의 `paragraphs: "each"` 를 실물에 처음 걸었더니 **줄이 셋인 상자에 걸음이 하나**
생겼다. 우리 코드는 맞았다 — 그 덱에 문단이 정말 하나였다.

Office.js 는 `\n` 을 소프트 줄바꿈으로, `\r` 을 문단 나누기로 받는다. 우리 도구는 모델이 준
`\n` 을 그대로 넘겨 왔다. 그래서 이 클라이언트가 만든 **모든 글머리 목록은 문단이 하나**였다.

그런데 **그림이 같았다.** 두 방식으로 만든 장을 PNG 로 내보냈더니 바이트까지 같았다 — 글머리
자리표시자는 소프트 줄바꿈에도 글머리 기호를 붙인다. 화면으로 재는 5층도, 코드를 읽는 리뷰도
이걸 볼 이유가 없었다. **문단 단위로 뭔가를 하려고 해서야** 드러났다.

| 층 | 이걸 볼 수 있었나 |
|---|---|
| 1~4층 (우리 가지) | 아니다 — 스텁은 `\n` 을 저장하고 우리가 그걸 다시 읽는다 |
| 5층 (실물, 눈으로) | 아니다 — **그림이 같다** |
| 리뷰 (코드 읽기) | 아니다 — 코드는 시킨 대로 하고 있었다 |
| 문단을 쓰는 기능을 붙이기 | **여기서 나왔다** |

새 기능이 **옛 기능을 재는 자**가 되는 일이 있다. 애니메이션을 안 붙였으면 이 결함은 계속
안 보였을 것이다.

### 5.1.3 2026-09-03 — Office 가 작업창 파일을 캐시한다

제안 카드(§6.20)를 실물 작업창에서 확인하려는데 **오늘 고친 화면 코드가 안 뜨는** 일을 겪었다.
확인한 것:

| 잰 것 | 결과 |
|---|---|
| 헬퍼가 내주는 `taskpane.html`·`src/ui/view.js` | **새것**(진단 문구가 들어 있다) |
| 그 응답의 캐시 머리 | `cache-control: no-store, must-revalidate` |
| 작업창을 닫았다 열기 | 옛 화면 |
| PowerPoint 를 껐다 켜기 | 옛 화면 |
| `%LOCALAPPDATA%\Microsoft\Office\16.0\Wef\webview2` 를 지우고 켜기 | 그래도 옛 화면 |

`no-store` 를 줘도 그렇다. Office 의 애드인 캐시는 WebView2 의 캐시와 따로 있고, 우리가
캐시 머리로 끄지 못한다.

**그래서 화면은 목업에서 잰다.** 이건 옹색한 대안이 아니라 원래 이 저장소가 화면을 재는
자리다(§4). 실제로 제안 카드는 목업에서 눈으로 확인했다 — 세 장이 뜨고, 「적용」이 글을
바꾸고 카드가 사라지고, 「무시」가 덱을 안 고치고 카드만 뗀다. 거기서 결함도 하나 나왔다:
카드 글에 마크다운 별표를 적어 뒀는데 카드는 `textContent` 로만 글을 넣으므로 사람이
`**덮어씁니다**` 를 글자 그대로 봤다.

**실물 작업창의 그림은 이 판에서 못 찍었다.** 안 찍은 것을 찍은 것으로 세지 않는다 — 도구가
답하는 것(제안이 붙고·읽히고·적용되고·기억은 안 지워진다)은 전부 실물에서 쟀고, 그 결과는
§6.20 에 있다. 남은 것은 **그 카드가 실물 작업창에 그려지는 그림 하나**다.

### 5.1.4 2026-09-03 — 기획자로 여러 판, **6층에서만 보이는 것들**

앞의 다섯 층은 전부 「도구가 계약대로 구는가」를 잰다. 이 판에서 잰 것은 다른 것이다:
**사람이 말로 시켰을 때 모델이 그 도구로 옳은 일을 하는가.**

방법은 이렇다. 대기업 기획자인 척하고 **줄거리만** 준다(숫자와 사례는 모델이 스스로 찾게
한다). 디자인 규칙은 작업창의 「늘 지킬 것」에 넣는다. PPT 는 내가 안 건드린다. 오간 것을
통째로 갈무리하고, 만들어진 덱을 가이드에 대고 잰다.

#### 왜 이 층이 필요한가 — 첫 판이 통째로 실패했다

도구는 전부 초록이었다. 그런데 모델은 `list_slides` 를 세 번 부르고 세 번 다 45초 뒤에
실패를 받은 뒤 **덱이 안 열려 있다고 판단하고 사람에게 빈 파일을 올려 달라고 했다.** 덱은
그동안 열려 있었다.

그 판에서 나온 것 셋:

| 무엇 | 왜 앞 층이 못 봤나 |
|---|---|
| `pick("")` 이 「가장 최근에 붙은 손」을 골라 **답 못 하는 연결 하나가 모든 호출을 삼켰다** | 연결이 하나인 시험에서는 안 갈린다 |
| 「덱은 이미 열려 있다」가 **MCP `instructions` 에만** 있었고, 그 문장은 magi 에 안 닿는다 | 도구를 직접 부르면 이 사실이 필요 없다 |
| 갓 만든 덱에 **노트 마스터가 없어** `set_notes` 가 통째로 막혔다 | 시험 픽스처에는 늘 마스터가 있었다 |

노트가 네 번 거절당하자 모델은 노트 대신 **슬라이드 위에 「확인 필요: 발표자 노트」라는
글상자를 놓았다.** 사람이 보는 장에 없어야 할 글이 생긴 것이고, 도구 시험으로는 영영 안 보인다.

#### 실패의 값이 크다 — 모델은 우회하고, 우회는 파괴한다

도구가 죽으면 모델은 가만있지 않는다. 실측:

```
write  create_report.ps1        ($ppApp = New-Object -ComObject PowerPoint.Application …)
bash   powershell -File create_report.ps1
write  create_report_fixed.ps1
bash   powershell -File create_report_fixed.ps1
…                                        (스크립트 일곱 개)
```

`New-Object -ComObject PowerPoint.Application` 은 **사람이 쓰던 PowerPoint 에 그대로 붙는다.**
그 판 뒤 PowerPoint 는 사라져 있었다. 워크스페이스에는 PowerShell 스크립트 여덟 개와 `.pptx`
네 개가 쌓였고, 그중 무엇도 사람이 보고 있는 덱이 아니다.

**그래서 우리 쪽 실패는 「느리다」로 끝나지 않는다.** 거절문이 무엇을 하면 되는지까지 적어야
하는 이유가 이것이다.

#### 사슬을 끝까지 따라갔다

| 고리 | 무엇이었나 |
|---|---|
| 작업창이 죽는다 | 대화 조각 하나마다 화면을 통째로 다시 그렸다. `onChange` 는 글자마다 뛰고 `renderRows` 는 모든 줄을 새로 만든다 — 줄 N, 사건 M 이면 DOM 을 N×M 번 짓는다 |
| 죽으면 호출이 45초씩 | 헬퍼는 답 없는 연결을 45초 기다린다 |
| 그 뒤 「열린 덱」에 유령이 남는다 | 붙어 있다는 것과 일하고 있다는 것을 안 갈랐다 |
| 모델이 COM 으로 우회한다 | 거절문이 「그러지 말라」를 안 적었다 |

넷 다 고쳤다. 다섯째 고리(45초 지연이 **처음 시작되는** 이유)는 아직 못 잡았다 — 30·60·120초를
쉬어 봐도, 모달 대화상자를 띄워 놔도 재현이 안 됐다(전부 20~40ms).

#### 부르는 쪽이 바라는 것과 도구가 하는 일이 다르면, 그 자체가 파괴다

`add_chart{slide:5}` 를 우리는 「5번 뒤에 새 장을 만들어 거기 넣는다」로 구현했고, 부르는 쪽은
「5번 장에 넣는다」로 읽었다. 그 차이를 모델은 **자기 실수로 읽고 고치려 들었다** — 넣고 →
늘어난 장을 지우고 → 다시 넣기를 여덟 번, 25분을 태우고 덱을 비웠다.

늘 새 장을 만드는 것이 「아무것도 안 부수는」 안전한 선택이라고 적어 뒀었다. 실제로 써 보니
반대였다.

#### 「늘 지킬 것」은 실제로 지켜진다

디자인 가이드를 넣어 두면 모델이 따른다. 노트 마스터를 고친 뒤의 판에서:

```
1. [생성형 AI, 우리 회사는 무엇부터 할 것인가]  노트 106자
2. [왜 지금인가]              본문 5줄  노트 70자
3. [우리의 강점·과제]          본문 5줄  노트 60자
…
6. [90일 로드맵]              표 O      노트 106자
가이드 어긋남 합계: 0
```

#### 계측 도구도 사실을 말해야 한다

한 판이 **모델 한도(429)에 걸려 끊겼는데** 나는 그것을 못 보고 도구 거절만 훑었다. 그래서
「도구가 죽자 모델이 bash 로 갔다」를 도구 실패 탓으로 읽었다 — 그 판에는 한도 초과가 섞여
있었고, 인과는 지금도 안 잡혔다. 계측기가 이제 그것을 **맨 앞에** 적는다.

그리고 관찰용 붙임 하나가 **「열린 덱」으로 세어져** 모델의 호출을 삼켰다. 계측 도구가 재려는
것을 바꾼 셈이고, 그 사실이 결함 하나를 드러내기도 했다(답 못 하는 연결이 덱으로 세어지는 것).

바뀜. **PowerPoint 가 안 되돌렸다** — §7b 의 테마 교체와 다르다. 이어서 덱 전체(8장, 런 112곳)에도

자식마다 Windows 가 새 창을 연다 — 터미널에서 띄운 magi 는 자식이 그 터미널을 물려받아 안 보였던 것이다.
고침: `internal/quietconsole` — magi 에게 콘솔 창이 없을 때만 자식에 `CREATE_NO_WINDOW`. `DETACHED_PROCESS` 가
아니다(그건 출력 캡처를 깨뜨렸다고 `sandbox_windows.go` 가 적어 뒀다). 스폰 자리 아홉 곳에 붙였다(셸 도구
셋·taskkill·git 넷·MCP·LSP). 시험: 콘솔이 없으면 플래그가 붙고 샌드박스 토큰이 남는지, 있으면 아무것도 안
바꾸는지, 그리고 **숨긴 콘솔로 띄운 진짜 powershell 의 출력이 파이프로 돌아오는지**. 고친 뒤 실측: 같은 자식이
`Start-Sleep 4` 동안 살아 있는데 창 핸들 0. 같은 날 `internal/app` 의 `TestWhatThisSessionBuiltIsNotAskedAbout` 가
빨간데, 내 변경을 걷어내도 빨갛다 — 이 머신의 기존 실패다.

**엑셀 판을 같은 2021 에 깔다가 파워포인트 판의 카탈로그 키가 사라졌다(2026-09-06).** Excel 2021 은 `TrustedCatalogs`
아래에 키가 둘 이상이면 뜰 때 전부 지운다 — 가설 셋(관리 공유·GUID 대소문자·매니페스트 내용)을 하나씩 걷어내고 남은
것이 개수였다(엑셀 판 INSTALL §3.3). 두 설치기가 `~/.magi/catalog` 하나에 키 하나를 같이 쓰게 했다. 이 머신에서 확인한
것: 키 하나면 Excel 재시작 뒤에도 남고, 공유 폴더에 두 애드인이 각자 서고, 엑셀 창에서 시킨 편집이 셀에 들어간다.

**같은 날 저녁, 컨텍스트 띠·프로바이더/모델 고르기(메인 `a58dbc52` 까지)를 2021 에서 다시 깔아 봤다.** 처음 판에서는 두
판 모두 브랜드 줄이 「대화 없음」이고 띠가 안 섰다 — 같은 덱으로 `/api/status` 를 물으면 세션이 있는데 창이 몰랐다.
메인의 `3b32b1d1`(상태 포트가 대화 이름을 떨어뜨렸다)·`a58dbc52`(띠를 ⋯ 줄 안으로) 뒤에 다시 깔아 보니 브랜드 줄이
「대화 s_…」를 적고, ⋯ 를 펴면 「~0 / 131,072 토큰 · 0%」 띠와 접기 단추, 프로바이더·모델 고르기가 두 판 모두 선다.
새 문 `/api/context`·`/api/models` 도 두 헬퍼에서 답한다. 안 잡은 것 하나: 엑셀 쪽 `/api/context` 가 한 번
`used 160,858 / window 131,072`(parts 합은 약 29,800)를 냈다 — 데몬의 `context` 문이 내는 수라 여기서 안 건드렸다.

**리본 이름과 아이콘(2026-09-06, 사용자).** 이름을 바꾸고 다시 추가해도 「magi 창」이 남았다 — Office 는 리본
customization 을 레지스트리(`WEF\PowerPoint_*RibbonCustomizationExpire`·`PowerPoint_RibbonCache`)에 캐시한다.
그 값을 지우고 껐다 켜고 다시 추가하니 새 이름이 섰다(설치기가 매니페스트가 바뀌면 그렇게 한다). 그룹 이름은
한 줄만 그린다 — 「Magi(AI Assistant)」가 그룹을 넓혀서 그룹 「AI Assistant」·단추 「Magi」로 갈랐다(사용자).
아이콘은 세 겹이었다. ① 리본은 9월 1일 M365 시절의 82바이트 주황 네모를 `Wef\Resources` 에 물고 있었다 —
주소가 같으면 서버가 새 그림을 내도 안 받는다. 주소에 판 번호를 넣었다(`/assets/v3/icon-32.png`, 헬퍼가 그 칸을
벗긴다). ② 새 주소로 받게 해도 **파란 육각형(기본 자리표시자)**가 떴다 — WinHTTP 로 직접 받으면 200 인데.
원인은 `Cache-Control: no-store` 였다: 페이지 손잡이가 모든 것에 걸어 둔 것인데, 리본은 아이콘을 **캐시 파일에서**
그린다. 아이콘에만 `max-age` 를 주니 마크가 섰다. ③ 그 사이 쿼리(?v=2)로도 해 봤는데 그때는 no-store 가 살아
있어서 그 실패는 원인이 둘 섞인 것이다 — 쿼리 자체가 되는지는 다시 안 쟀다. 시험: 판 번호 경로가 같은 바이트를
내고 엉뚱한 칸은 404(`icon_version_test.go`), 아이콘은 캐시 가능하고 페이지는 여전히 no-store(`icon_cache_test.go`).
둘 다 변이로 확인했다.

**카운슬 스위치를 2021 에서(2026-09-06).** 메인이 더한 `/api/council` 과 고급 줄의 저울 단추를 설치본으로 눌러 봤다.
누르니 컴패니언이 다시 떴고(데몬 하나, 새 세션), 설정 파일이 `[council] enabled = false` 가 되고, 상태가 council=false 를
말한다 — 된다. 다시 뜨는 20초 남짓 동안 상태가 reachable 을 몇 번 오갔고 한 번은 council=true 를 지나갔다 — 옛
데몬이 내려가고 새것이 올라오는 사이의 값이다. 그리고 **누를 때마다 검은 창이 떴다**(사용자): 헬퍼가 띄우는
`magi --daemon --detach` 가 콘솔 프로그램인데 헬퍼는 콘솔 없이 떠 있어서다 — 앞의 셸 도구와 같은 자리, 같은 고침
(`quietconsole.Apply`, own.go). 그런데 그것만으로는 **똑같았다**(사용자). 다시 재니 창의 주인이 달랐다: 작업 표시줄에
남는 검은 창은 `conhost` 이고 제목이 `…\magi\ppt\magi.exe` 였다 — 데몬이 「restarting onto the binary on disk」로
**자기를 다시 띄울 때**(`internal/graceful` 의 Windows reexec) 생긴 것이다. 첫 데몬은 `--detach` 로 콘솔 없이 뜨는데,
그 후임은 `CREATE_NEW_PROCESS_GROUP` 만 주고 띄워서 콘솔 없는 부모의 콘솔 자식 → Windows 가 새 창을 줬다. 부모에게
콘솔이 없으면 후임도 `DETACHED_PROCESS` 로 띄운다(`reexecAttr`, 터미널의 magi 는 그대로). 시험 둘 + 변이(조건을
죽이면 빨갛다). 이 창은 카운슬 스위치뿐 아니라 설치기가 magi.exe 를 새로 놓을 때마다 떴을 것이다 — 데몬이 디스크의
새 바이너리를 보고 스스로 다시 뜨기 때문이다.

**여기서 배운 것:** 손이 둘이면 계약도 둘이 되고, 그 갈라짐은 **양쪽을 다 돌려 봐야만** 보인다.
`hand_com_parity_test.go` 가 도구 **이름**의 차집합은 잰다. **답의 칸 이름은 아무도 안 잰다.**

**안 잰 것을 잰 것으로 세지 않는다.**

## 6b. 「못 한다」가 재 본 것이 아니었다 — 2026-09-04

이 레인의 문서 여러 곳이 **「그건 1.10 이라 못 한다」**를 적고 있었다. 슬라이드 배경, 테마 색,
판 크기, 있는 표 고치기. 그런데 그건 **스펙을 읽고 적은 것**이지 호스트에 물어본 것이 아니었다 —
`OfficeDeck.capabilities()` 의 탐침이 **1.8 에서 멈춰 있었고**, 1.9·1.10 은 한 번도 안 물어봤다.

물어보게 고치고 재니 **여덟 개 전부 ✓** 였다(16.112.3).

```
PowerPointApi 1.2 ✓ 1.5 ✓ 1.6 ✓ 1.7 ✓ 1.8 ✓ 1.9 ✓ 1.10 ✓ · SharedRuntime 1.1 ✓
```

**왜 아무도 다시 안 쟀나.** 잴 수 있는 자리가 창 안뿐인데(`Office.context.requirements`), 그
값이 창에만 있었다 — **사람이 화면을 읽어야만 아는 값**이었다. 그래서 창이 잰 것을 헬퍼로
넘기고 `/api/status` 의 `caps` 로 낸다. 요약하지 않고 그대로 나른다: 여섯이 여덟이 되던 날
요약이 있었으면 그 둘이 사라졌다.

그 위에 도구 넷이 섰다 — `set_background` · `set_theme_colors` · `read_theme_colors`(1.10),
`format_table_cells`(1.9). **넷 다 호스트가 그 집합을 지원할 때만 손이 광고한다**(`ops`), 그리고
검사가 그 게이트를 문다(게이트를 벗기는 변이 셋이 전부 울었다).

곡예도 하나 걷었다. 차트 기본 크기 600×380 은 좋은 값이라서가 아니라 **판 크기를 못 물어봐서**
고른 값이었다 — 4:3 에서 안 넘치게 깎느라 16:9 에서는 오른쪽이 360pt 비었다.

> **다음 사람에게.** 이 문서의 「안 되는 것」 목록을 읽을 때, 그 줄이 **잰 것인지 읽은 것인지**를
> 먼저 보라. 잰 것이면 날짜가 붙어 있고, 아니면 그 줄이 이 절의 다음 후보다.

## 7. 열 판을 이어 돌려 본 것 — 2026-09-04

같은 부탁 하나(「임원 보고용 6~7장을 처음부터, 숫자는 웹에서 직접 찾아」)를 **열 번** 연달아
돌리고, 판 사이에 나온 결함을 고쳤다. 한 판은 12분 안팎이고 도구는 60~90회다.

| 4 | 4 | 3 | (판 중간에 헬퍼를 갈아 끼워 등록이 떨어졌다 — 내 실수이지 제품 결함이 아니다) |
| 5 | 8 | 1 | 목업이 **열린 덱으로 등록**돼 브라우저를 다시 읽을 때마다 문서 번호가 갈렸다 |
| 6 | 3 | 3 | — |
| 7 | 0 | 0 | 첫 무결 판 |

## 7b. 테마 글꼴을 OOXML 로 갈아 끼울 수 있나 — **없다** (2026-09-04)

Office.js 에 글꼴 스킴이 없다는 것은 레퍼런스로 확인했다(`Slide`·`SlideMaster` 둘 다
`themeColorScheme` 뿐, 프리뷰에도 없음). 그런데 **파일을 여는 쪽에서는 되는 일**이고(claude.ai
의 pptx 스킬이 그렇게 한다), 우리에게도 OOXML 길이 있다 — 차트·그림·표가 그 길로 간다.

**읽는 절반은 참이었다.** 장을 뜨면 꾸러미에 `ppt/theme/theme1.xml` 이 통째로 들어 있다:
44개 파트 중 하나, 8732바이트, `<a:fontScheme name="Office">` 의 major·minor 가 둘 다
`맑은 고딕`. 색도 `<a:accent1><a:srgbClr val="156082"/>` 로 `read_theme_colors` 와 일치했다.

**쓰는 절반이 안 됐다.** `<a:latin typeface>` 를 Georgia 로 바꿔 `insertSlidesFromBase64` 로
되넣고 셋을 쟀다:

| 잰 것 | 값 |
|---|---|
| 되넣은 그 장 | **Georgia** |
| 그 뒤 새로 만든 장 | **맑은 고딕** — 안 물려받는다 |
| `describe_style`(14장) | **맑은 고딕** — 덱 테마 그대로 |

**PowerPoint 가 들어오는 테마를 안 받고 목적지 테마로 되매핑한다.** 그래서 그 길은 결과가
`set_deck_font` 와 같으면서 **장을 다시 짓느라 id 까지 바꾼다** — 더 나쁘다. 붙였다가 재고 뺐다.

> 다음 사람에게: 이 생각은 자연스럽고, 그래서 다시 하게 된다. 코드 주석(`#deckFont`)과 이 절에
> 같이 적어 뒀다 — **재 봤고 안 된다.**
