# 오피스 사용 시나리오

도구를 하나씩 부르는 스윕(`clients/{excel,word}/addin/tools/sweep.mjs`, `clients/powerpoint/tools/sweep.ps1`)은
「이 도구가 도는가」를 본다. 여기 시나리오는 **사람이 실제로 하는 일 한 덩어리**를 끝까지 걸어서 「앞 도구가 남긴 것
위에서 뒤 도구가 맞게 도는가」를 본다. 표를 만든 뒤의 정렬, 추적을 켠 뒤의 거부, 스냅숏 뒤 망가뜨리고 되돌리기,
장을 복제한 뒤의 순서 같은 것이다. 스윕이 다 통과하는 날에도 여기서 버그가 나왔다(아래 「잡은 것」).

**기능을 고치면 돌린다.** 어느 시나리오를 돌릴지는 아래 「언제 무엇을」 표에 있다. 결과는 맨 아래 「실행 기록」에 한 줄 더한다.

## 돌리는 법

1. 헬퍼를 띄우고, Excel·Word·PowerPoint 를 각각 열어 **magi 작업창을 연다.** 문서는 새 빈 문서여도 되고 사람의 문서여도
   된다. 시나리오는 자기가 만든 것만 만지고 끝에 지운다.
2. 돌린다.

```bash
node clients/office/scenarios/run.mjs --com
```

| 옵션 | 뜻 |
|---|---|
| `--app xl\|word\|ppt\|all` | 한 앱만(기본 all) |
| `--only <id>` | 시나리오 하나만(`xl-report` 등) |
| `--origin <url>` | 헬퍼 주소(기본 `https://127.0.0.1:26411` — 설치본). 개발용 헬퍼는 `-port` 에 맞춘다 |
| `--com` | Windows 에서 파일을 COM 으로 직접 읽어 한 번 더 대조한다 — 도구의 답이 아니라 문서를 본다 |
| `--verbose` | 호출마다 인자와 원문 답을 찍는다. 실패를 캘 때 |

끝에 시나리오마다 통과·실패 수가 나오고, 실패가 하나라도 있으면 종료 코드가 1 이다. 작업창이 안 붙은 앱은 **건너뜀**으로
따로 적는다. 통과로 세지 않는다.

## 약속

- **자기가 만든 것만 만지고, 실패해도 정리는 돈다.** 정리는 「처음 모양으로 돌아왔는가」까지 잰다: 장 수, 문단 수와 표 수,
  빈 문서였으면 첫 문단의 스타일. 이것을 안 재던 판은 사람의 문서에 빈 줄과 제목 스타일을 남기고도 정리가 다 통과였다.
- **「했다」는 답을 믿지 않는다.** 되읽는 도구로 다시 보고, `--com` 이면 파일을 직접 읽는다. PowerPoint 2021 의
  `add_shape` 는 별을 부르면 네모를 세우고 「추가했습니다」라고 답했다(2026-09-26).
- **닿지 못한 것은 통과가 아니다.** 연결이 안 되면 거절을 기대하던 단계도 실패로 센다. 거절을 기대하는 단계는 거절 사유에
  들어 있어야 할 말도 같이 잰다 — 엉뚱한 이유로 거절돼도 통과하지 않게.
- **번호가 아니라 이름·글·id 로 따라간다.** 표·목록이 끼면 문단 번호가 밀리고, 순서를 바꾸면 장 번호가 다른 장을 가리킨다.

## 시나리오

### XL-1 `xl-report` — 월 매출 보고서

새 시트 하나에서 끝까지 짓는다. 끝에 시트와 이름을 지운다.

| 단계 | 하는 일 | 재는 것 |
|---|---|---|
| 1 | 데이터 6행 + 이익 수식 | 수식이 매출−비용으로 계산됨 |
| 2 | 표로 만들기 → 겹친 표 거절 → 매출 내림차순 정렬 | 정렬 순서, **정렬 뒤에도 수식이 제 행을 따라감** |
| 3 | 표에 행 추가 → 이름 `총매출 = SUM(매출표[매출])` → 그 이름을 쓰는 수식 | 이름 합계가 새 행까지 셈, 선행 추적 |
| 4 | 숫자 형식 · 데이터 막대 · 목록 유효성 | 각각 되읽힘 |
| 5 | 차트 만들기 → 제목·범례·값 표시 고치기 | 고친 제목이 되읽힘 |
| 6 | 없는 필드로 피벗(거절) → **표 이름을 원본으로** 지역별 피벗 | 거절 사유에 있는 머리글, 피벗에 서울 2700 |
| 7 | 스냅숏 → 일부러 지움 → 되돌림 | 매출·비용이 돌아옴 |
| 8 | 시트 보호 → 쓰기 거절 → 보호 풀기 → 쓰기 | 보호가 실제로 막음 |
| 9 | 찾기(표 둘 + 피벗 하나) → 바꾸기 → 피벗 새로 고침 → 찾기 | **바꾼 수가 실제로 바뀐 칸 수**, 안 바뀐 피벗 칸을 이름으로 댐, 새로 고친 피벗이 새 이름을 따름 |
| 10 | 제안 붙이기 → 읽기 → 떼기 | 제안이 읽힘 |
| COM | 파일 직접 | G2 합계, 표 이름, 차트 수 |

### WD-1 `word-contract` — 계약서 초안 검토

문서 끝에 계약서 여섯 문단을 쓰고 검토 한 바퀴를 돈다. 빈 문서에서 시작하면 Word 가 빈 첫 문단을 먼저 채운다. 그래서
넣은 자리는 손의 답(`from`)을 따른다.

| 단계 | 하는 일 | 재는 것 |
|---|---|---|
| 1 | 제목·조 머리 스타일 → 없는 스타일 거절 | 스타일이 되읽힘 |
| 2 | 번호 목록 셋을 본문 뒤에 | 셋이 목록으로 읽힘 |
| 3 | 대금 표 → 머리 행 서식 → **평평한 목록 하나로 열 추가** → 열 수 불일치 거절 → 행 추가 | 4행 3열, 기존 값이 안 덮임 |
| 4 | 각주 · 책갈피 | 각주가 되읽힘 |
| 5 | 추적 켬 → 문단 고침 → 추적 기록 → 거부 → 추적 끔 | 기록이 남음, 거부 뒤 원래 글 |
| 6 | 댓글 → 답글 → 해결 → 되읽기 → 지우기, 없는 댓글에 답 거절 | 답과 해결 상태 |
| 7 | 스냅숏 → 조 머리 지움 → 되돌림 | 지운 것이 돌아옴 |
| 8 | 우리 범위 안에서만 바꾸기 | 바꾼 말이 찾아짐 |
| 9 | 글 일부를 콘텐츠 컨트롤로 감쌈 → 글 바꿈 → 되읽기 → 지우기 | 바꾼 글이 되읽힘 |
| 10 | 제안 붙이기 → 읽기 → 떼기 | 제안이 읽힘 |
| COM | 파일 직접 | 남은 추적 기록 0, 추적 꺼짐, 책갈피 있음 |
| 정리 | 표 → 문단(끝 문단 포함) | **문단 수·표 수가 처음과 같음** |

`read_comments`·`read_tracked_changes`·`review_changes` 등은 `to` 를 빼면 **`from` 한 문단만** 본다(계약이 그렇다). 범위가
필요하면 `to` 를 준다. 이것을 모르고 `from` 만 주면 거부가 0건으로 끝나 추적 기록이 문서에 남는다. 이 시나리오가 처음
그렇게 틀렸다.

### PP-1 `ppt-quarterly` — 분기 보고 덱

덱 끝에 세 장을 개요로 짓고 다듬는다. 장은 id 로만 부른다. 2021(COM 손)과 365(작업창 손) 어느 쪽이 붙어도 같은 흐름이다.

| 단계 | 하는 일 | 재는 것 |
|---|---|---|
| 0 | `add_slides` 로 세 장 | 제목이 개요대로 |
| 1 | 본문의 한 낱말만 굵게·빨갛게, 없는 낱말 거절 | 거절 사유에 실제 글 |
| 2 | 표 → 행 추가 → 칸 쓰기 → 머리 행 서식 | **`read_slide` 가 표의 칸을 싣는다**, 새 행과 기존 값 |
| 3 | 차트 · 별과 타원 · 모르는 도형 거절 · 맞추기 · 묶기 → 풀기 | 묶음 없이 도형 둘 |
| 4 | 복제 → 맨 끝으로 → 지움 | id 로 본 순서 |
| 5 | 스냅숏 → 제목 망가뜨림 → 되돌림 → 옛 id 거절 | 새 id, 원래 제목 |
| 6 | 노트 · 배경 · 애니메이션(fade), 없는 효과(fly) 거절 | 노트와 걸음 수 |
| 7 | 글로 도형 찾기, 제안 붙이기 → 읽기 → 떼기 | 찾은 장, 제안 |
| COM | 파일 직접 | 끝의 세 장 제목, 마지막 장의 차트 |
| 정리 | 만든 장(되돌리며 바뀐 id 포함) 지우기 | **장 수가 처음과 같음** |

2021 의 작업창 제안 카드(사람이 누르는 「적용」·「무시」)는 이 실행기가 못 누른다. 그 확인은 `clients/powerpoint/docs/TESTING.ko.md`
의 「2021 작업창에 제안 카드가 뜬다」 절차대로 사람이 한다.

### COM 전용 셋 — Windows 에서만 (`windowsOnly`)

Office.js 에 길이 없어 헬퍼(Word·Excel)나 COM 손(PowerPoint 2021)이 COM 으로 하는 도구들이다. 다른 OS 에서 실행기는 이 셋을
**건너뜀**으로 적는다. 만든 PDF 는 임시 폴더에 두고 끝에 지운다.

| id | 흐름 | 재는 것 |
|---|---|---|
| XL-2 `xl-com` | 이익 수식 → `goal_seek`(매출이 얼마면 이익 1000?) → 스파크라인 넣기·지우기 → 표 → 슬라이서(없는 열·없는 표 거절) → 넣기·지우기 → 시트 PDF | 찾은 값과 원래 값, 통장에 들어간 값, 스파크라인 칸 수·표식, 슬라이서와 **빈 캐시가 안 남음**, 진짜 PDF(`%PDF`), 덮어쓰기 거절 |
| WD-2 `word-com` | 오타 든 문단 → `proofread`(제안까지) → 고침 → 다시 검사 → `document_stats` → PDF → 견줄 .docx 를 COM 으로 만들어 `compare_documents` | 짚은 오타·문단 번호·제안, 범위 규칙(to 없으면 from 하나), 고친 뒤 사라짐, 쪽·단어 수, 비교 결과 문서의 변경 수(끝에 그 문서를 닫는다) |
| PP-2 `ppt-show` | 세 장 → 한 장에 `set_transition`(효과·자동 넘김) → `hide_slide` → `add_section` 둘·이름 바꾸기 → 애니메이션 들어오기·강조·끝내기 → 같은 크기 no-op → PDF | `read_slide` 의 전환, 목차의 숨김·구역, 「기본 구역」이 생긴다는 안내, 세 종류가 다 되읽힘, 숨긴 장이 PDF 에서 빠졌다는 답, COM 으로 전환·숨김 대조, **정리 뒤 구역도 처음대로** |

덱 전체를 바꾸는 호출(`set_transition{all}`, 크기 바꾸기)은 사람의 장까지 건드리므로 PP-2 는 제 장에만 걸고, 크기는 같은 크기
no-op 과 거절만 잰다.

## 언제 무엇을

| 고친 곳 | 돌릴 것 |
|---|---|
| `clients/excel/addin` (ExcelHand·화면) | `--app xl` |
| `clients/word/addin`, 헬퍼의 `word_com*.go`·`word_render*` | `--app word` |
| `clients/powerpoint/addin`, `clients/powerpoint/hand-com` | `--app ppt` (2021 과 365 가 있으면 둘 다) |
| 헬퍼의 공통부(`mcp.go`·`hand.go`·`serve.go`·`hostcaps.go`·`bridge.go`) | 전부 |
| 도구 설명(`*_tools.go`)만 | 해당 앱. 설명이 약속한 것을 시나리오가 부르는지 본다 |

작업창 코드(`clients/*/addin/src`)를 고쳤으면 **그 앱의 작업창을 닫았다 다시 열어야** 새 코드가 돈다. 헬퍼나 COM 손을 고쳤으면
다시 빌드해 띄운다.

## 잡은 것

시나리오가 처음 돌며 찾은 제품 버그. 스윕은 다 통과하던 때다. 시나리오의 해당 단계가 회귀 시험이다.

| 날짜 | 앱 | 증상 | 고친 곳 |
|---|---|---|---|
| 2026-09-27 | Excel | `add_pivot` 에 표 이름을 원본으로 주면 머리글 빠진 몸통으로 풀려 「ItemNotFound」 한 줄로 실패. 없는 필드도 같은 한 줄 | `ExcelHand.js #addPivot` — 표 이름은 머리글까지, 없는 필드는 있는 머리글을 대며 거절 |
| 2026-09-27 | Excel | `replace_all` 이 못 바꾼 피벗 칸까지 「바꿨다」고 셈(3개라 답하고 2개) | `ExcelHand.js #replaceAll` — 바꾼 뒤 다시 읽어 세고, 안 바뀐 칸을 댐 |
| 2026-09-27 | Word | 끝 문단을 지우면 글만 비고 문단은 남는데 「지웠습니다(1개)」. 문서 끝에 쓴 것을 치우면 빈 줄이 남음 | `WordHand.js #deleteParagraphs` — 앞 문단의 표시를 지우고 서식을 되입힘, 센 대로 말함 |
| 2026-09-27 | Word | `edit_table add_columns` 에 평평한 목록을 주면 Office.js 의 InvalidArgument 한 줄 | `WordHand.js #editTable`·`word_com_more.go` — 평평한 목록은 한 열, 개수 불일치는 사유를 대며 거절 |
| 2026-09-27 | PowerPoint 2021 | `read_slide` 가 표의 칸을 안 실음(`text: ""`) — 모델은 방금 채운 표를 못 읽음 | `hand-com/src/Hand.cs` — 작업창 손과 같은 `rows`·`columns`·`cells` |
| 2026-09-27 | 헬퍼(COM 도구) | 헬퍼가 답하는 도구의 답에 `changed`·문서 이름이 빠짐, COM 정수(int32)를 0 으로 읽어 스파크라인 「0칸」·있는 표를 「없음」 | `mcp.go` — Local 답에도 싣고, `intOf` 가 COM 정수를 읽음 |
| 2026-09-27 | Excel | `remove_slicer` 가 지우고 나서 치워진 컬렉션을 만져 「Object required」로 실패를 답함 | `xl_extra_windows.go` — 지우기 전에 세고 뒤에는 안 만짐 |
| 2026-09-27 | PowerPoint 2021 | 뒤에 구역이 있는 첫 구역을 지우면 COM 의 「Illegal value」 한 줄 | `Hand.Show.cs` — 이유를 대며 거절(뒤 구역을 먼저 지우라고) |

## 시나리오 더하기

`clients/office/scenarios/<앱>-<이름>.mjs` 를 두면 실행기가 줍는다. 모양은 이렇다.

```js
export default {
  id: 'xl-budget', app: 'xl', title: '한 줄 설명',
  async run(s) {
    const made = await s.call('add_sheet', { name: '시나리오-예산' });   // 실패하면 단계 실패, null
    s.cleanup(() => s.call('delete_sheet', { sheet: '시나리오-예산' }, '정리'));  // 역순으로, 실패해도 돈다
    await s.refuse('write_range', { address: 'A1', values: [[1, 2]] }, /모양/, '모양 불일치');  // 거절 + 사유
    s.check('되읽은 값이 맞다', cond, detail);                         // 판정
    const com = s.com(`$w = Get-MagiWorkbook '${s.document.label}'; @{ n = 1 } | ConvertTo-Json -Compress`);
  },
};
```

`s.com` 의 PowerShell 에는 `Get-MagiWordDoc <문서 키>`·`Get-MagiWorkbook <이름>`·`Get-MagiDeck <이름>` 이 미리 있다. 작업창이 붙은
**그 문서**를 찾는다. 새 시나리오는 위 「시나리오」 절에 표 하나로 적는다. 무엇을 재는지가 코드보다 먼저 읽혀야 한다.

### 기존 빈 끝 문단의 복원

`word-contract`는 삽입 전 `read_paragraphs`로 원문과 스타일을 확보합니다. 원문을 전부 읽지 못하면 문서를 변경하지 않습니다.
`ins.from`이 기존 마지막 빈 문단이면 그 문단은 보존하고 새로 추가한 문단만 삭제한 뒤 원래 빈 내용과 스타일을 복원합니다.
정리 후 기존 본문과 스타일도 비교합니다. 실행기 수정 시 빈 문서, 본문만 있는 문서, 본문 뒤 빈 문단이 있는 문서에서 각각 실행합니다.
