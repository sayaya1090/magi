# 발표자료 작성과 검증

## 공통 적용 기준

사용자가 지정한 산출물 언어와 문체를 우선합니다. 지정이 없으면 기존 문서의 언어·표기 관례를 유지하고, 새 문서는 사용자 요청의 언어를 따릅니다. 대화 언어와 산출물 언어가 다를 수 있습니다. 혼합 언어, 직접 인용, 고유명사는 임의로 번역하지 않습니다. 한국어 개조식·공문 형식을 다른 언어에 강제하지 않습니다. 날짜·소수점·통화·단위는 대상 문서의 지역 관례를 따릅니다. 도구 이름·인자·수식 문법은 번역하지 않고 API 규약을 따릅니다.

아래 수치·배치·호출은 예시입니다. 사용자 지정 내용과 기존 템플릿이 우선하며, 예제의 숫자·날짜·이름을 사실로 복사하지 않습니다. 현재 도구 목록과 인자 설명을 확인한 뒤 제공된 도구만 호출합니다. 운영체제나 Office 연도만으로 지원을 단정하지 않습니다. 완료 검증 도구가 없으면 호출하지 않고 수행 결과·검증 범위·미완료 항목을 답변으로 보고합니다.


사용자가 지정한 내용과 문체, 조직의 템플릿을 우선합니다. 이 문서의 수치와 배치는 권장 시작점이며 제품의 기술적 제한이 아닙니다. 스킬의 예제에 도구가 등장해도 현재 세션에서 제공된다는 뜻은 아닙니다.

## 0. 작성 전 확인

- `list_slides`, `list_layouts`, `describe_style`로 기존 내용·레이아웃·서식을 확인합니다. 레이아웃 이름을 추측하지 않습니다.
- 기존 자료를 수정할 때는 요청받지 않은 제목·브랜드 색·슬라이드 크기를 임의로 변경하지 않습니다.
- 현재 도구 목록과 각 도구의 인자 설명을 확인합니다. Office 연도만으로 지원 여부를 판단하지 않습니다. COM 연동과 웹 작업창의 지원 범위가 다릅니다.
- 도구가 없으면 호출하지 않습니다. 도구가 등록돼 있지만 실행기가 지원하지 않는다고 답하면 완료로 기록하지 않고 실패한 도구와 이유를 보고합니다. 같은 요청을 반복하지 않습니다.

## 1. 글꼴

기존 테마와 사용자가 지정한 글꼴을 우선합니다. 특정 글꼴이 모든 Windows·Mac 환경에 설치됐다고 가정하지 않습니다. 대체 글꼴이 필요하면 한국어 지원과 실제 표시를 확인하고 변경 사실을 알립니다.

`font`와 한국어 글꼴 적용 범위는 실행 경로에 따라 다릅니다. `apply_style{ea_font}`가 필요한 경우 도구 설명을 확인합니다. 슬라이드를 재생성하는 경로에서는 ID가 바뀔 수 있으므로 반환된 ID를 이후 호출에 사용합니다. 글꼴 통일 후 다시 렌더링합니다.

## 2. 레이아웃

적합한 자리표시자가 있으면 활용합니다. 비교도·출처·라벨 등에는 텍스트 상자를 사용할 수 있습니다. 항목 수만으로 레이아웃을 강제하지 않고 내용의 관계와 읽는 순서로 고릅니다. 사용하지 않는 자리표시자와 의도하지 않은 빈 공간을 확인합니다.

좌표를 지정하기 전 실제 슬라이드 크기를 확인합니다. 960×540pt는 16:9 예시이며 모든 16:9 파일의 크기가 같지는 않습니다.

## 3. 한국어 문체 — 개조식과 명령형을 구분

- 한국어 발표 슬라이드의 본문은 간결한 **개조식**을 기본으로 합니다. 예: 「매출이 12% 증가했습니다」 → 「매출 12% 증가」, 「검토할 필요가 있습니다」 → 「추가 검토 필요」.
- 개조식은 **명령형이 아닙니다**. 「비용 23% 감소」를 「비용을 줄여라」로 바꾸지 않습니다. 사실·제안·계획·불확실성의 의미를 보존합니다. 「감소 가능성」을 「감소」로 단정하지 않습니다.
- 제목도 「3분기 매출 12% 증가」처럼 핵심 메시지를 담은 명사구를 허용합니다. 표지·목차·구역 제목은 「연구 방법」 같은 주제형 제목이 자연스럽습니다. 사용자가 지정한 제목은 유지합니다.
- 같은 수준의 불릿은 종결 형식을 맞춥니다. 본문은 3~5개 항목을 시작점으로 삼고, 내용과 가독성에 따라 조정합니다. 조사와 연결어를 모두 없애 뜻이 모호해지지 않도록 합니다.
- 발표자 노트는 자연스러운 설명 문장으로 작성합니다. 직접 인용·질문·슬로건·사용자가 요청한 문체는 목적에 맞게 유지합니다.
- 줄바꿈은 `\n`을 사용합니다. 자리표시자의 글머리 기호와 직접 입력한 기호가 중복되지 않게 확인합니다.

## 4. 표·차트·이미지

추세와 비교는 차트, 정확한 값과 대응 관계는 표를 우선 고려합니다. 숫자가 몇 개 있다는 이유만으로 차트를 강제하지 않습니다. 지원되는 경우 `add_chart`, `add_table`, `add_image`를 사용합니다.

표 서식은 현재 도구가 제공하는 인자만 지정합니다. 기존 테마를 유지할지, 셀 서식을 직접 적용할지 선택하고 결과를 확인합니다. 글꼴을 지정하면 반드시 표 스타일이 사라진다고 단정하지 않습니다. 이미지에는 내용에 맞는 대체 텍스트를 제공합니다.

## 5. 배치와 정렬

제목·본문·시각 자료 사이의 여백과 읽는 순서를 확인합니다. 글과 차트의 세로 배치도 공간이 충분하면 가능합니다. 여러 도형은 `align_shapes`로 정렬할 수 있습니다. 가로로 놓인 도형은 top/middle, 세로로 놓인 도형은 left/center 등 정렬 축을 확인하고 의도하지 않은 겹침이 없는지 봅니다.

## 6. 색과 테마

기존 브랜드·템플릿을 보존합니다. 새 자료에 별도 지정이 없으면 `design-guide`의 예시를 참고할 수 있지만 기본 테마 자체를 결함으로 판단하지 않습니다.

`read_theme_colors`, `set_theme_colors`, `set_background`는 현재 도구 목록에 있을 때만 사용합니다. 테마 색 변경이 모든 배경과 도형에 반영된다고 가정하지 않습니다. 직접 지정한 색은 남을 수 있으므로 영향을 받은 슬라이드를 확인합니다. 배경과 글자색은 함께 검토하고 색만으로 정보를 구분하지 않습니다.

## 7. 내용과 화면 검증

완성한 슬라이드는 `render_slide`가 제공되면 렌더링해 제목·본문 잘림, 대비, 겹침, 여백을 확인합니다. 640px 미리보기로 시작하되 작은 표나 출처가 읽히지 않으면 도구가 허용하는 더 높은 해상도로 확인합니다. 렌더링을 할 수 없으면 화면을 확인했다고 보고하지 않습니다.

도구의 경고는 확인할 단서입니다. 경고가 없다고 가독성이 보장되지는 않으며, 의도한 겹침이나 두 줄 제목을 무조건 오류로 처리하지 않습니다. 최종 글꼴·테마 변경 뒤에는 영향을 받은 장을 다시 확인합니다.

## 8. 실행 경로에 따른 기능

COM 경로에는 화면 전환·구역·숨김·크기·PDF 도구가 구현돼 있습니다. 웹 작업창에서는 같은 기능이 제공되지 않을 수 있습니다. `delivery`의 예제도 현재 도구 목록을 확인한 뒤 사용합니다. 배경·테마·표 편집·그룹 기능 역시 실제 도구와 인자 설명을 기준으로 판단합니다.

## 9. 완료 보고

`list_slides`로 구성과 제목을 확인하고, 수정한 내용은 필요한 범위에서 `read_slide`로 대조합니다. 수행한 작업, 검증한 범위, 실패·미확인 항목을 구분해 보고합니다. 자동 검증 도구가 현재 목록에 제공된 경우에만 그 도구의 설명을 따릅니다. 제공되지 않은 도구는 호출하지 않습니다.

## 10. 최종 체크리스트

1. 사용자 요청과 기존 자료의 의미·문체를 보존했는가
2. 한국어 개조식을 명령형으로 바꾸지 않았는가
3. 수치·인용의 출처와 불확실성을 정확히 표시했는가
4. 실제 화면에서 잘림·대비·배치를 확인했는가
5. 글꼴·테마 변경 후 영향을 받은 장을 다시 확인했는가
6. 이미지 대체 텍스트와 필요한 발표자 노트를 제공했는가
7. 실패한 도구와 검증하지 못한 범위를 보고했는가

해당하지 않는 항목은 제외하고 실제 확인한 범위를 적습니다. 고정된 만점이나 검증하지 않은 PASS를 보고하지 않습니다.
