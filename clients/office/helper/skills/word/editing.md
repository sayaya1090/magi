# 고치기

## 공통 적용 기준

사용자가 지정한 산출물 언어와 문체를 우선합니다. 지정이 없으면 기존 문서의 언어·표기 관례를 유지하고, 새 문서는 사용자 요청의 언어를 따릅니다. 대화 언어와 산출물 언어가 다를 수 있습니다. 혼합 언어, 직접 인용, 고유명사는 임의로 번역하지 않습니다. 한국어 개조식·공문 형식을 다른 언어에 강제하지 않습니다. 날짜·소수점·통화·단위는 대상 문서의 지역 관례를 따릅니다. 도구 이름·인자·수식 문법은 번역하지 않고 API 규약을 따릅니다.

아래 수치·배치·호출은 예시입니다. 사용자 지정 내용과 기존 템플릿이 우선하며, 예제의 숫자·날짜·이름을 사실로 복사하지 않습니다. 현재 도구 목록과 인자 설명을 확인한 뒤 제공된 도구만 호출합니다. 운영체제나 Office 연도만으로 지원을 단정하지 않습니다. 완료 검증 도구가 없으면 호출하지 않고 수행 결과·검증 범위·미완료 항목을 답변으로 보고합니다.


- **남의 문서는 변경 추적을 켜고 고친다** — `set_track_changes{mode:"TrackAll"}`. 사람이 고친 곳을 하나씩 받아들이거나 거부할 수 있다.
  작업창이 못 하는 판(2019·2021)은 Windows 면 헬퍼가 COM 으로 대신한다. 그래도 안 되면 고치기 전에 `snapshot_paragraphs` 를 찍고
  무엇을 바꿨는지 답에 적는다.
- **찾아 바꾸기는 `replace_all`** — 먼저 `find` 로 몇 군데인지 본다. 흔한 낱말이면 `from/to` 로 범위를 좁히고 스냅숏을 찍는다.
- **한 문단을 다시 쓰려면 `replace_paragraph`** — 스타일은 남고 글자 서식은 사라진다. 굵은 낱말이 있었으면 `format_text{text}` 로 되살린다.
- **의견은 고치지 말고 남긴다** — `add_comment`, 안 되면 `advise` 로 작업창에. 「이렇게 바꾸는 게 어떠냐」는 `suggest` 로
  카드를 붙이면 사람이 한 번에 적용한다.
- **끝나면 `read_html` 로 고친 구간을 보고, `read_paragraphs` 로 되읽어 확인한 것을 답에 적는다.**
- 범위를 받는 읽기 도구(`read_comments`·`read_tracked_changes`·`review_changes` 등)는 **`to` 를 빼면 `from` 한 문단만** 본다.
  구간 전체가 필요하면 `to` 를 준다 — 이것을 모르고 거부하면 0건으로 끝나 추적 기록이 문서에 남는다.

## 맞춤법·문법 — 짐작하지 말고 Word 에게 묻는다

Windows 의 Word 면 `proofread` 가 **Word 자신이 밑줄 친 것**을 준다(맞춤법은 제안까지). 자동 검사 결과에도 누락과 오탐이 있을 수 있으므로 문맥을 함께 검토합니다.

```
proofread {from:1, to:40}         # 구간을 좁히면 빠르다. limit 기본 50
# → items: [{kind:"spelling", text:"되요", paragraph:12, suggestions:["돼요"]}, {kind:"grammar", text:"…", paragraph:18}]
snapshot_paragraphs {from:12, to:18}
replace_all {find:"되요", replace:"돼요", from:12, to:12}
```

- 고유명사·제품명·업계 용어는 밑줄이 쳐져도 **그대로 두고** 답에 「그대로 둔 것」으로 적는다.
- 문법 표시는 문장 단위다 — 문장을 통째로 다시 쓸 때는 `replace_paragraph`.
- 빈 결과만으로 정상 여부나 교정 도구 설치 여부를 단정하지 않습니다. 검사 범위·언어·교정 설정을 확인하고 직접 검토합니다.

## 문장 다듬기 — 무엇을 바꾸는가

| 문제 | 고친 꼴 |
|---|---|
| 긴 문장(한 문장에 뜻 둘 이상) | 둘로 나눈다. 한 문장 40자 안팎 |
| 수동·명사 나열(「검토가 진행될 예정」) | 능동(「검토할 예정」 — 담당자와 기한은 원문에 있을 때만 추가합니다) |
| 결론이 끝에 | 첫 문장으로 올린다(두괄식) |
| 같은 뜻 반복(「미리 예측」「다시 재검토」) | 하나만(「예측」「재검토」) |
| 모호한 양(「상당히」「대폭」) | 숫자(「18%」「3일」) — 원문에 숫자가 없으면 지어내지 말고 메모로 묻는다 |

- **글쓴이의 문체는 지킨다.** 고치라는 것은 문장이지 목소리가 아니다. 존댓말·반말, 개조식·서술식을 바꾸지 않는다(부탁이 없으면).
- 한 번에 다 고치지 말고 **절 단위로** 고친 뒤 `read_paragraphs` 로 확인한다.

## 두 판 비교 — 「뭐가 바뀌었는지 보여 줘」

Windows 의 Word 면 `compare_documents{path:"C:\\…\\계약서_v2.docx"}` 가 **새 문서**를 만들어 차이를 변경 추적으로 보여 준다.
두 파일은 그대로다. 그 파일이 옛 판이면 `as:"original"`.

- 비교 결과 문서에는 magi 작업창이 안 붙어 있다 — 그 문서에서 더 고치려면 사람이 거기서 작업창을 열어야 한다고 답에 적는다.
- 파일 경로는 사람에게 받는다. 지어내지 않는다.

## 예제 — 「이 보고서 검토해서 고칠 데 고쳐 줘」

```
list_paragraphs {}                              # 구조 파악
set_track_changes {mode:"TrackAll"}             # 사람이 하나씩 받아들이게
proofread {}                                    # 맞춤법·문법 목록 (Windows)
replace_all {find:"되요", replace:"돼요"}          # 확실한 것만 바로 고친다
replace_paragraph {paragraph:5, text:"3분기 매출은 125억 원으로 목표를 4% 넘었다. 신규 고객 40곳이 견인했다."}
add_comment {from:9, comment:"이 수치의 출처를 붙여 주세요 — 원문에 없습니다."}   # 모르는 것은 고치지 말고 묻는다
read_tracked_changes {from:1, to:<끝>}          # 무엇을 바꿨는지 되읽어 답에 목록으로
```
