# Magi 메일 클라이언트

로컬 브라우저에서 IMAP/SMTP 계정 하나를 Magi와 연결합니다. INBOX의 최근 50건을 표시하며, 읽기 전용 일반 텍스트 본문과 별도의 MIME 원문을 제공합니다. 메일을 선택하면 계정·메일함·UIDVALIDITY·UID로 식별하는 Magi 세션을 연결합니다. UIDVALIDITY는 서버에서 메일함이 재생성되었는지 구분하는 값입니다. 이 값이 바뀌면 목록을 새로고친 뒤 메일을 다시 여세요.

모델은 선택한 메일을 읽거나 초안을 저장할 수 있습니다. 발송 도구는 제공하지 않습니다. 사용자가 브라우저에서 받는 사람·제목·본문 전체를 검토하고 발송 확인 대화상자에서 승인해야 합니다. SMTP DATA 뒤 오류가 발생하면 전달 여부가 불확실할 수 있습니다. 재시도하기 전에 보낸 편지함이나 수신자를 통해 확인하세요.

## 실행

같은 설정 디렉터리를 사용하는 Magi 데몬을 먼저 실행한 뒤 다음 명령을 사용합니다.

```sh
export MAGI_MAIL_IMAP=imap.example.com:993
export MAGI_MAIL_SMTP=smtp.example.com:465
export MAGI_MAIL_USER=you@example.com
export MAGI_MAIL_PASSWORD='your-app-password'
export MAGI_MAIL_FROM=you@example.com
go run ./clients/mail/cmd
```

`http://127.0.0.1:8793`을 열고 프로세스가 출력한 로컬 접속 토큰을 붙여 넣은 뒤 **INBOX 새로고침**을 누릅니다. 서비스에서 요구하면 앱 비밀번호를 사용하세요. 인증정보는 소스 저장소와 셸 명령 기록에 남기지 마세요. 인증정보를 Magi 도구 결과에 넣지 않습니다. `MAGI_CONFIG_DIR`은 데몬 설정 디렉터리를 지정합니다. `MAGI_MAIL_ADDR`은 루프백 수신 주소를 변경하고, `MAGI_MAIL_TOKEN`은 로컬 UI 토큰을 지정합니다.

IMAP은 연결 시작부터 TLS를 사용합니다. SMTP 기본값도 이 방식이며 보통 465번 포트입니다. 587번 포트는 `MAGI_MAIL_SMTP_TLS=starttls`로 지정하세요. 서버가 STARTTLS 보안 연결을 만들지 못하면 인증과 발송을 중단합니다. TLS 인증서를 검증하며 최소 TLS 1.2를 사용합니다. 서버 연결과 명령 실행에는 제한 시간이 있습니다.

## 범위

초기 버전의 UI는 계정 하나·초안 수신자 한 명·INBOX만 지원합니다. 읽기 API는 명시적으로 요청한 다른 메일함도 처리합니다. OAuth, 첨부파일, 검색, 폴더 UI, 답장 스레드, 삭제·이동, 자동 발송 재시도, 보낸 편지함 저장은 지원하지 않습니다. multipart의 일반 텍스트와 base64·quoted-printable은 해독하지만 UTF-8 외의 구형 문자셋 변환은 아직 구현하지 않았습니다. HTML은 HTML로 렌더링하지 않습니다. HTML 전용 메일은 본문에 안내를 표시하고 MIME 원문으로 확인합니다. 2 MiB를 넘는 메일과 1 MiB를 넘는 초안은 거부합니다.

Magi 이벤트는 사용자 메시지·모델 답변·도구 호출과 결과·오류·완료 안내로 표시합니다. 초기 버전은 일반 텍스트 대화 행이며 Markdown은 렌더링하지 않습니다. 승인 요청에는 허용·거부 버튼을, 질문에는 선택지·직접 답변 입력을 제공합니다. 다른 메일을 선택하면 받는 사람·제목·본문·채팅 입력을 비우고 이전 이벤트 스트림을 취소하며, 도구는 원래 선택한 메일에 귀속됩니다. 초안은 현재 프로세스에만 보관하며 재시작하면 사라집니다.

## 검증

`go test ./clients/mail/...`과 `go test -race ./clients/mail/...`을 실행합니다. 선택한 메일의 세션 귀속, 발송 도구 미제공, 명시적 발송 확인, 헤더 삽입 거부, MIME 해독, 초안 크기 제한, DOM의 텍스트 표시를 검증합니다. 가짜 계정을 사용하므로 실제 메일을 발송하지 않습니다.

실제 IMAP/SMTP 계정은 아직 검증하지 않았습니다. 사용 전 테스트 메일함에서 유효한 TLS 인증서로 목록·본문 조회, UIDVALIDITY 변경, 만료된 인증정보, SMTP STARTTLS, 확인 후 단일 발송, 취소, 재접속, 서로 다른 메일의 세션 격리를 확인하세요. 실제 초안의 수신 주소와 전달된 MIME도 대조하세요. 브라우저 자동화는 메일·Magi API를 모의 처리해야 하며 실제 메일을 발송하면 안 됩니다.

## 빌드와 복구

`go build -o /tmp/magi-mail ./clients/mail/cmd`로 실행 파일을 만든 뒤 동일한 환경변수를 전달하여 `/tmp/magi-mail`을 실행합니다. 브라우저 페이지를 Go 실행 파일에 포함하므로 별도 웹 디렉터리는 필요하지 않습니다. 로컬 검증이 통과한 뒤 PATH에 설치하세요. 로컬 접속 토큰은 IMAP 비밀번호와 별개인 클라이언트 연결 비밀입니다. 토큰이 포함된 콘솔 출력을 공유하지 마세요.

Magi에 요청하기 전에 메일을 선택합니다. **Magi 초안 가져오기**로 선택한 메일의 저장된 초안을 편집기에 불러온 뒤 수정하고 발송을 확인합니다. 다른 메일로 전환하면 이전 수신자가 눈에 띄지 않게 남는 일을 막기 위해 표시한 초안을 비웁니다. 전환 뒤 도착한 이전 초안 응답은 무시합니다. 질문·승인 버튼은 원래 세션 연결에 귀속되며 다른 메일의 요청에 답할 수 없습니다.

접속 토큰이 틀리면 올바른 토큰으로 바꾸고 INBOX를 새로고칩니다. IMAP 인증이 실패하면 클라이언트를 종료하고 앱 비밀번호를 갱신한 뒤 다시 실행합니다. Magi 연결이 실패하면 `magi`가 PATH에 있고 모델 설정이 유효한지 확인한 뒤 메일을 다시 선택합니다. 브리지는 별도 컴패니언을 자동 실행할 수 있습니다. 이벤트 연결이 끊기면 오류를 표시합니다. 메일을 다시 선택하면 연결을 복구하고 저장된 대화를 재생합니다. 저장하지 않은 편집 내용과 메모리 초안은 재시작하면 사라집니다. 요청 실패 뒤에는 입력 내용을 보존하므로 연결 오류를 해결한 뒤 재시도할 수 있습니다.

브라우저 테스트는 `npm ci --prefix clients/web/e2e`로 의존성을 설치하고 해당 패키지의 Playwright 도구로 Chromium을 설치한 뒤 `node clients/mail/test/ui-playwright.mjs`를 실행합니다. 이전 초안 초기화, 늦은 초안 응답 거부, text/plain 브리지 오류의 읽기 쉬운 안내도 검사합니다. 계정 인증정보 없이 실행할 수 있습니다.
# 공식 프로토콜 검토

2026-10-12에 [IMAP4rev2, RFC 9051](https://www.rfc-editor.org/rfc/rfc9051.html), [메일 TLS, RFC 8314](https://www.rfc-editor.org/rfc/rfc8314.html), [SMTP AUTH, RFC 4954](https://www.rfc-editor.org/rfc/rfc4954.html) 원문과 대조했습니다. 현재 `go-imap` v1 의존성은 IMAP4rev1을 구현하므로 이 클라이언트가 IMAP4rev2 전체를 지원한다고 보장하지 않습니다. 서버는 여기서 사용하는 rev1 명령을 수용해야 합니다. rev2 전환에는 별도 기능 협상 및 상호운용 검토가 필요합니다.

`mail.go`는 IMAP에 암시적 TLS를 사용하고 서버 인증서를 검증하며 TLS 1.2 이상을 요구합니다. SMTP는 암시적 TLS(통상 465)와 필수 STARTTLS(통상 587)를 지원하며 평문 인증으로 전환하지 않습니다. SMTP AUTH는 현재 TLS 위의 PLAIN을 사용합니다. OAuth나 다른 인증 방식만 허용하는 서버는 구현 범위에 포함되지 않습니다. 선택한 메시지는 메일함 UIDVALIDITY와 UID에 귀속하며, 본문 조회에는 읽음 표시를 바꾸지 않는 PEEK를 사용합니다.

이번 검토는 구현 계약을 확인한 것입니다. 실제 메일 제공자와의 상호운용이나 전달 성공을 검증한 것은 아닙니다.


## 세션과 실행 제어

채팅 화면의 새 세션 버튼은 선택한 메일 대상을 유지하면서 새 대화를 만듭니다. 모델 입력란과 모델 변경 버튼으로 모델을 지정하고, 작업 중단 버튼으로 현재 실행을 중단합니다. 실패한 요청의 입력은 유지하며 새 세션으로 바뀐 뒤에는 이전 세션 이벤트를 표시하지 않습니다.

본문 조회 전에 RFC822.SIZE로 2MiB 초과 여부를 확인합니다. 허용된 메시지도 BODY.PEEK의 부분 조회로 최대 2MiB+1바이트만 요청합니다. `network_test.go`는 로컬 TLS IMAP 서버에서 큰 메시지가 본문 조회 전에 거절되고 작은 메시지는 부분 조회되는지 확인합니다. 실제 제공자 시험과는 구분합니다.

발송 본문은 UTF-8을 quoted-printable로 인코딩하여 8BITMIME를 지원하지 않는 서버에도 전달할 수 있게 합니다. MIME 본문 줄은 76바이트 이내로 접으며, 한국어·긴 문장의 디코딩 왕복을 단위 테스트로 확인합니다. 실제 서버 전달 확인은 별도 인수 항목입니다.
