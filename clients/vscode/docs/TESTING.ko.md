# 무엇을 어디서 재나

[↑ 클라이언트 개요](../README.md) · [설계](./DESIGN.ko.md) · [형제: 젯브레인](../../jetbrains/docs/TESTING.ko.md)

> 층이 둘이라 재는 자리도 둘이다. `core` 는 편집기 없이 재고, 매니페스트는 **실물 VS Code 를
> 띄워야만** 잰다 — 그 둘을 섞으면 한쪽이 다른 쪽인 척한다.

## 1. `src/test/` — 편집기 없이 (`node --test`)

| 시험 | 무엇 |
|---|---|
| `workspace.test.ts` | **소켓 키 골든.** 코어의 `daemon.WorkspaceKey` 가 직접 답한 값이다. 여기가 틀리면 **에러가 안 난다** — 아무도 없는 소켓을 찾고 「실행되지 않음」이라 말한다. 한글·악센트·일본어 경로가 들어 있다(ASCII 만이면 utf8/latin1 이 구별되지 않는다). 설정 디렉토리 세 갈래, 소켓 경로 상한 |
| `wire.test.ts` | **와이어 대조.** Go 소스를 읽어 우리가 읽는 필드 이름이 데몬이 쓰는 이름인지 본다. 프로토콜 판 번호와 승인 어휘도. 태그를 40개 미만 찾으면 **그것부터 실패한다** |
| `wire.test.ts`(추가) | **컴포저의 첨부가 `refs` 로 가나, 사람의 말 앞에 끼워지나.** 코어가 발췌를 워크스페이스 감옥 안에서 렌더하고, 캡을 씌우고(ref 16KB·전체 64KB), 프롬프트와 함께 영속한다 — 문장에 적힌 경로는 그중 아무것도 못 받는다. `submit` 문이 정말 `r.Refs` 를 읽는지도 같이 본다(가드가 제가 이름 대는 와이어보다 오래 살면 안 된다). 줄 철자 셋(`12`·`12-40`·전체)은 `sliceLines` 가 **파싱 못 하면 조용히 파일 전체로 낙하**하므로 따로 못 박는다 |
| `stream.test.ts`(추가) | **컴포저가 `steer` 와 `submit` 을 가르나, 그 사실을 어디서 읽나.** `submit` 은 새 최상위 요청이라 코어가 `resetForNewTopLevel` 을 돌린다 — 도는 턴에 한 마디 거들면 **그 턴의 계획이 지워진다**. 사실은 이 창이 흘려보는 전사에 있다(답 없는 `pending` 행); `status` 문에는 「턴이 돌고 있다」 칸이 아예 없다. 코어에서 두 문이 아직 다른지도 같이 읽는다 |
| `webview.test.ts`(추가) | **안 간 말이 조용히 사라지지 않나.** 컴포저는 엔터를 누르는 순간 스스로 비운다(그 행은 잠시 뒤 스트림으로 오므로 빈 상자가 유일한 표시다) — 그래서 거절을 버리면 **침묵이 「갔다」로 읽힌다**. 사유·말·칩 셋을 다 돌려주는지 본다: 하나만 빠져도 반쪽 고침이다. 젯브레인은 `if (r.ok)` 뒤에만 상자를 비우고 그 주석이 같은 함정(사라지는 첨부)을 이름 댄다 |
| `webview.test.ts`(추가 2) | **사람이 누르는 문이 전부 답을 「읽나」.** 목록이 아니라 **훑는다** — 단추가 하나 늘고 아무도 이름을 안 적으면 목록형 규칙은 통과하면서 결함이 나간다. 예외 넷은 사유와 함께 적는다. ⚠ **묶는 것과 읽는 것은 다르다**: 첫 판은 「이름에 대입하면 통과」였는데 `const v = await ask(…); void v;` 변이가 그대로 살아남았다(결함은 완전히 복원된 채로) — 살아남은 것은 변이가 약해서가 아니라 **가드가 눈멀어서**였다. 지금은 그 이름이 `.ok` 로 시험되거나 넘겨지는지까지 본다 |
| `webview.test.ts`(정보 카드) | **웹뷰가 명령 이름을 고르지 못하나, 그리고 카드가 내미는 단추가 전부 진짜 명령인가.** 웹뷰는 페이지다 — 이름을 그대로 넘겨 주면 거기 스크립트가 들어오는 순간 확장 호스트가 할 수 있는 일을 전부 할 수 있다. 그래서 **목록이 있나**가 아니라 **그 목록이 판정에 쓰이나**를 문다: 변이 둘(`!` 을 뗀 것, 상수를 물어보는 것)이 둘 다 컴파일되고 둘 다 잡혔다. ⚠ **자리를 잘못 훑으면 목록이 비어도 초록이다** — 첫 판은 단추 세 개만 읽고 여섯을 못 봤다(카드가 이름을 두 모양으로 적는다: 행은 `[…, 'magi.chooseModel']`, 단추는 `['restart', 'magi.restartDaemon']`). 지금은 `drawInfo` 안의 `magi.*` 를 전부 읽고, **여섯 미만이면 훑기가 죽은 것으로 보고 그것부터 실패한다**. 매니페스트 선언까지 같은 시험에서 대조한다 — 안 적힌 명령은 눌러야 알 수 있다 |
| `webview.test.ts`(신호등) | **컴패니언이 어떤 상태든 제 색으로 그려지나.** 콘솔처럼 **상태 낱말이 곧 클래스**이고 색은 스타일시트가 정한다 — 그래서 낱말이 하나 늘면 규칙 없는 상태가 **기본 회색**으로 떨어지는데, 회색이 바로 「물어보지 못했다」의 모양이다. 상태 목록은 `core/activity.ts` 에서 읽고(넷 미만이면 훑기가 죽은 것), 규칙 하나를 지우는 변이로 확인했다 |
| `plan.test.ts`(추가) | **편집기 도구가 왜 안 붙었는지 사람이 알 수 있나.** 갈래 셋(광고 없음·포트 없음·둘째 창이라 거절)이 **증상이 똑같았다** — 하나는 조용한 return, 둘은 `console.warn`(확장 호스트 로그, 아무도 안 연다). 셋이 각각 문장을 쓰는지, 그 문장이 **화면까지 가는지**를 본다. ⚠ **선언은 읽기가 아니다**: `tools` 가 와이어에 선언돼 있는지만 보던 첫 판은, 문구를 「attached」로 납작하게 만든 변이가 그대로 살아남았다 — 「묶으면 읽는 것」과 같은 눈멂이다 |
| `setup.test.ts`(추가) | **화면이 데몬이 한 적 없는 주장을 하지 않나.** `status` 의 세 모양 중 「둘 다 빈 것」이 평범한 갈래인데(`doing` 은 빌트인 50 중 하나만 채우고, 문에는 「턴이 돈다」 칸이 없다) 그것을 `idle` 로 그렸다 — **일하는 내내 「쉬는 중」**. 갈래가 아니라 **낱말**을 못박는다: 이 모듈 주석이 같은 결함의 1판(Unknown→idle)을 적고 있고, 2판이 바로 그 아래 줄에 그만큼 살아 있었다. 갈래만 보는 가드는 두 번 다 통과했을 것이다 |
| `stream.test.ts`(추가 2) | **도구 행이 「어느 호출」인지 말하나.** 이름만 그리면 명령 서른 번이 `bash ✓` 서른 줄이다 — 전사가 답하라고 있는 그 물음을 못 답한다. 인자 요약을 지어내지 않고(빈 객체는 요약도 없음), 버리지도 않고(못 알아본 것은 원본을 자름), 한 줄로 가두는지 본다. ⚠ **있는 것과 도는 것은 다르다**: 「원본이 `r.args` 를 언급하나」만 보던 첫 판은 갈래를 `false &&` 로 죽인 변이가 그대로 지나갔다 — 조건문 자체와 append 를 못박아 고쳤다 |
| `stream.test.ts`(추가 3) | **도구 결과가 물음 둘에 답하나** — 「일이 일어났나」와 「읽을 것이 있나」. 훅·언어서버는 일부러 `isError` 를 세우고(그게 모델을 세운다) 화면은 그걸로 글리프를 그려서, **쓰고 린트 걸린 파일이 「쓰기 실패」로** 떴다(코어가 실물 런에서 재고 `Advisory` 로 가른 그 결함). 셋을 가르는지 · 실패만 사유를 싣는지 · **값을 읽지 표현을 읽지 않는지**(JSON 문자열 재-stringify 는 이스케이프를 화면에 남긴다)를 본다 |
| `stream.test.ts`(추가 4) | **평결이 전부 행이 되나, 그 행이 투표를 싣나.** 말 없이 투표한 멤버는 행이 통째로 안 만들어져 **셋짜리 카운슬이 둘로** 그려졌다 — 자리가 빈다는 말은 어디에도 없이. `silent` 는 코어가 그 빈 경우를 부르는 낱말이니 **없음이 아니라 사실**이고 제 행을 받는다. 실려 온 rationale 은 절대 낙하 문구로 안 바꾼다(젯브레인 주석의 라이브 보고 — 「왜 다 '답이 없었다'야?」). `decision`·`round` 도 같이 못박는다 |
| `manifest.test.ts`(추가 6) | ★ **거울상 가드 — 코어가 쓰는 사건을 전부 읽거나, 안 읽는다고 사유와 함께 적었나.** 「분기하는 이름이 코어에 있나」의 반대이고 더 비싼 쪽이다: 코어가 사실을 쓰는데 아무도 안 읽으면 **기능이 통째로 없고 아무도 안 운다.** 실측으로 셋이 나왔다(`council.decided`· `interjection.deferred`·`interjection.answered`). 예외 열넷은 사유를 적는다. ⚠ 첫 판이 **점 없는 이름을 못 봤다**(`compaction`·`error`) — 저장소가 이미 기록한 함정을 다시 밟았고, 자기검사에 그 둘을 못 박았다 |
| `stream.test.ts`(추가 5) | **파킹된 프롬프트가 그렇다고 말하나, 그 표시가 화면까지 가나.** ⚠ 스타일 검사를 파일 전체에서 하면 TypeScript 의 `r.queued` 가 `.queued` 로 걸려 **CSS 를 지워도 초록**이다 — `<style>` 블록 안에서만 본다 |
| `setup.test.ts`(추가 2) | **사람을 데몬이 부르는 이름으로 부르나.** SSO 류 플러그인이 `magi.set_user_label` 로 심고 `status` 가 답하는데, 두 IDE 다 그 칸을 버려서 누가 로그인했든 화면은 「user」였다(ide-bridge 의 같은 함수는 처음부터 담고 있었다 — 사본 셋 중 둘이 틀림). 와이어 선언 · 빈 이름 낙하 · **라벨까지 가는지**를 같이 본다 |
| `setup.test.ts`(추가 3) | **「무엇 위에서 도나」 셋을 다 싣나** — `permission`·`model`·`council` 이 같은 답에 오는데 둘만 읽고 있었다. **세 갈래**를 못박는다: 켬·끔·**말 안 함**(낡은 데몬). 안 말한 것을 「끔」으로 그리면 모르는 것을 아는 척하는 것이다(§0.5-7) |
| `wire.test.ts`(추가 2) | ★ **부르는 문의 답을 선언은 했나 — 「읽는 것이 전선에 있나」의 짝.** 선언이 없으면 **읽을 수가 없다**: 답은 오고, 화면은 아무것도 안 읽고, 아무것도 안 터진다. 한 세션에서 이 부류로 셋을 잃었다(`tools`·`user`·`council`). **부르는 문만** 센다 — 안 두드리는 문의 칸은 결함이 아니다. ⚠ 채우는 칸 스캔은 **Response 리터럴 안**만 본다: `answerJobs` 의 `BackgroundJob{Exit:…}` 를 `Response.exit` 으로 읽어 잘 읽고 있는 칸을 오보했다 |
| `touched.test.ts`(고침 + 추가) | ★ **물음이 어느 종류인지 실리나, 그리고 두 종류를 다 보나.** 화면은 `kind === 'permission'` 으로 갈라 allow/deny/always 를 세우는데 그 칸이 **한 번도 안 실려서** 모든 승인이 질문 갈래로 떨어졌다 — 단추 셋은 코드에 있는 채로 안 그려졌다. `question.requested` 는 아예 안 읽혀서 선택지 있는 물음이 상자도 못 세웠다. ⚠ **옛 시험이 결함을 못박고 있었다** — `kind` 없는 모양을 deepEqual 로. 모양을 재고 효과를 안 잰 시험이다 |
| `touched.test.ts`(추가 2) | ★ **승인이 「무엇을」 허가하는지 싣나.** 화면이 도구 이름 한 줄만 그려서 사람이 명령도 diff 도 모르고 allow 를 눌렀다 — 코어는 요청의 나머지를 「viewer 가 요청의 **설명**이 아니라 요청을 그리도록」 이미 나르고 있었다. 셋을 따로(`args`=그 자체·`reason`=산문·`diff`=바뀌는 것), 빈 값은 안 싣고, **아무것도 안 왔으면 그렇다고 말하는지**까지 본다. ⚠ 이름을 대는 것은 그리는 것이 아니다 — 배열을 비운 변이가 살아남아 **순회하는 값 자체**를 못 박았다 |
| `touched.test.ts`(추가 3) | **물음이 「몇 중 몇」인지 말하나.** 코어가 사유를 적었다 — 다른 기계의 뷰어는 「이걸 답하면 또 온다」를 알 길이 **그것밖에 없다**. 다섯 중 첫 물음을 답한 사람이 끝난 줄 안다. 젯브레인은 그리고 있었다. **둘 이상일 때만** 붙이는 것도 같이 본다 — 「(1/1)」은 정보인 척하는 소음이다 |
| `touched.test.ts`(추가 4) | **물음이 「무엇을 근거로」 나왔는지 싣고 그리나.** 결정보고 스킬이 모은 근거인데 두 IDE 다 버려서, 근거를 실어 보낸 물음이 **맨 문장 하나와 단추**로 도착했다. 코어가 사유를 두 번 적었다 — 「근거가 뒤에 남은 프롬프트가 바로 이것이 막으려는 것」, 그리고 「결정의 사유는 한 달 뒤에 물으러 오는 사람이 찾는 부분」. 빈 근거는 안 싣는다: 단추 위의 빈 줄은 **사유를 준 것처럼 읽힌다** |

## 2. `src/live/` — 실물 VS Code 안에서

**매니페스트는 단위 시험이 못 잰다.** `contributes` 의 오타는 모든 단위 시험을 통과하고 편집기
에서 아무 일도 안 한다 — 아무도 등록 안 한 뷰는 그냥 안 나타나기 때문에 에러도 없다.

`selfcheck.ts` 가 도는 편집기 안에서 잰다:

- 확장이 **실제로 활성화되나**(기다린다, 경주하지 않는다 — `onStartupFinished` 는 이 시험보다 늦다)
- 매니페스트가 약속한 명령 **스물셋이 전부 등록됐나**(목록에서 세는 것이라 늘어도 안 늙는다)
- 뷰가 **둘뿐이고** 둘 다 웹뷰이며, 대화는 패널 컨테이너에 계획은 `magi-side` 에 있나
- 그 `magi-side` 가 **보조 사이드바에 걸려 있나** — 자리는 매니페스트의 한 낱말이라, 왼쪽으로
  되돌아가도 뷰와 id 는 그대로여서 위의 줄들이 전부 통과한다
- 설정이 **진짜 설정**이지 웹뷰가 아닌가
- 대화 뷰가 **실제로 열리나**(리졸브에서 터지는 프로바이더를 잡는 자리)
- 이 창이 계산한 소켓 경로에 **진짜 데몬이 있나**

```
cd clients/vscode && npx tsc -p . && node out/live/run.js
```

내면 빨강.

## 3. CI 가 안 재는 것

- **실물 검사는 CI 에서 안 돈다.** 편집기를 띄워야 하고, 그러려면 러너가 VS Code 를 통째로
  내려받는다. 릴리스 레인은 단위 시험만 돌린다 — 그러니 **매니페스트 회귀는 CI 가 못 잡는다.**
  손으로 §2 를 돌리고 나서 태그를 단다.
- **웹뷰 안의 그림.** 행이 어떻게 보이는지, 테마가 바뀌면 어떻게 되는지는 아무도 안 잰다.
- **인라인 완성·인레이가 화면에 실제로 뜨는지.** 프로바이더가 등록된 것까지만 잰다.
- **승인 답하기의 왕복.** 단추가 보내는 것까지는 코드에 있고, 컴패니언이 그것으로 진행하는지는
  실물 턴이 필요해 안 쟀다.
