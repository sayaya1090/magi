# 무엇을 어디서 재나

[↑ 클라이언트 개요](../README.md) · [설계](./DESIGN.ko.md) · [형제: 젯브레인](../../jetbrains/docs/TESTING.ko.md)

> 층이 둘이라 재는 자리도 둘이다. `core` 는 편집기 없이 재고, 매니페스트는 **실물 VS Code 를
> 띄워야만** 잰다 — 그 둘을 섞으면 한쪽이 다른 쪽인 척한다.

## 1. `src/test/` — 편집기 없이 (`node --test`)

| 시험 | 무엇 |
|---|---|
| `workspace.test.ts` | **소켓 키 골든.** 코어의 `daemon.WorkspaceKey` 가 직접 답한 값이다. 여기가 틀리면 **에러가 안 난다** — 아무도 없는 소켓을 찾고 「실행되지 않음」이라 말한다. 한글·악센트·일본어 경로가 들어 있다(ASCII 만이면 utf8/latin1 이 구별되지 않는다). 설정 디렉토리 세 갈래, 소켓 경로 상한 |
| `wire.test.ts` | **와이어 대조.** Go 소스를 읽어 우리가 읽는 필드 이름이 데몬이 쓰는 이름인지 본다. 프로토콜 판 번호와 승인 어휘도. 태그를 40개 미만 찾으면 **그것부터 실패한다** |
| `layering.test.ts` | `core/**` 가 `vscode` 를 import 하지 않는다. 스캐너 자기검사 포함 |
| `manual.test.ts` | **이식표가 젯브레인 매뉴얼의 항목을 전부 이름 대나.** 매뉴얼에서 뽑아 대조한다 — 표는 사람이 적는 글이라 표만으로는 안 선다 |
| `handoff.test.ts` | **다른 컴패니언에게 일 넘기기.** 라벨 첫머리의 마크는 코어에서 베낀 것이고 (`fleet.go` 가 그 상수를 「읽는 이가 셋이라 철자는 하나여야 한다」고 적는다), 그것이 없으면 받는 쪽 셋이 조용히 빠진다. **거절과 끊김을 가른다** — 거절은 「그만 기다려라」(재시작·만료)이고 끊김은 「못 물어봤다」다. 합치면 죽은 접수증을 창 수명만큼 폴한다 |
| `hand.test.ts` | **이 편집기가 컴패니언에게 내놓는 도구.** 실물 HTTP 로 네 메서드를 왕복한다 — 젯브레인이 202/204 불일치를 진짜 클라이언트로만 잡았고, 제 프로토콜 사본을 부르는 시험은 어느 쪽이든 통과했을 것이다. **`readOnlyHint` 를 싣는지**가 핵심이다: 안 싣으면 파일을 열어 보인 것이 코어 기록에 「이 턴이 그 파일을 고쳤다」로 오른다. 토큰 없는 호출은 403, 모르는 도구는 거절, 모르는 메서드는 HTTP 200 + JSON-RPC 에러(500 이면 전송 고장으로 읽힌다) |
| `manifest.test.ts`(추가 4) | **코어가 로그에 넣을 수 있는 part 종류를 전부 그리거나, 일부러 안 그린다고 적었나.** 안 적으면 조용히 사라진다 — 웹 콘솔이 같은 것을 겪고 주석에 그 사유를 남겼다. ⚠ 자기검사가 판정 대상을 겸하면 안 된다: 처음에 `image` 를 자기검사에 못 박아서, 그 갈래를 지웠을 때 판정 문장이 아니라 「가드가 깨졌다」가 떴다 |
| `manifest.test.ts`(추가 3) | **분기하는 사건 이름이 전부 코어에 있는 사건인가.** `switch` 도 `if (e.type === …)` 도 없는 이름에 조용히 지나쳐 — 컴파일도 통과하고 그 갈래만 영영 안 돈다. 젯브레인에 먼저 걸었고 같은 이유로 이쪽에도 건다. **점 없는 이름도 사건이다**(`compaction`·`error`) — 자기검사에 못 박았고, 그것을 죽이는 변이로 확인했다 |
| `manifest.test.ts`(추가 2) | **웹뷰 메시지가 아무에게도 안 가거나 아무도 안 보내는 것이 없나** — 양방향, 웹뷰 둘 다. 웹뷰는 스크립트 문자열이라 두 쪽을 맞춰 주는 것이 없고, 고아 종류는 조용히 실패한다(보내는데 아무도 안 듣고, 기능은 그냥 없다). 처음 돌렸을 때 **가드 자신이 오탐**을 냈다 — 확장 쪽이 `case` 와 `if (m.kind === …)` 두 모양으로 받는데 앞의 것만 읽고 있었다 |
| `manifest.test.ts`(추가) | **`state` 메시지가 판이 그릴 문장을 싣는가.** 웹뷰는 스크립트 문자열이라 유닛이 못 본다 — 변이로 찾았다: 셋 중 하나에서 `note:` 를 빼도 어떤 시험도 달라지지 않았다 |
| `manifest.test.ts` | **자리와 engines 바닥이 같이 움직이나.** `secondarySidebar` 는 1.106 것이고, 그 밑에서는 이 열쇠가 **남의 확장 뷰 위치까지 흔든다**(QwenLM/qwen-code#2432) — 우리 뷰가 안 뜨는 것이면 눈에 띄지만 남의 배치가 틀어지는 것은 그쪽이 제 확장을 의심한다. 자리 이름이 셋 중 하나인지도(흔히 잘못 적히는 `secondarySideBar` 를 잡는다), 모든 뷰가 선언된 컨테이너를 가리키는지도. 그리고 **값이 그 문이 읽는 칸으로 가는지** — `cron-set` 의 예약 시각을 `args` 안에 넣었더니 `args` 는 와이어에 **있는** 칸이라(도구 문이 읽는다) 버려지지도 않고 데몬이 빈 스케줄을 받았다. 젯브레인은 처음부터 최상위로 보냈고 이쪽만 틀렸다 |
| `look.test.ts` | 훑어본 말을 줄에 거는 규칙(**구분자가 탭만이 아니다** — 실측), 버퍼 번호 매기기(줄 경계에서 자른다), 완성의 겹침 제거 |
| `stream.test.ts` | **답이 오는 동안 대화가 움직이나.** `part.delta` 가 조각을 싣고 사실(`part.appended`)은 스트림이 끝나야 쓰인다 — 델타를 무시하면 긴 답 내내 판이 멈춰 보인다. 사실은 초안을 **대체**한다(둘 다 두면 답이 두 번 그려진다), 한 메시지의 추론과 본문은 **다른 초안**이다, 그리고 **턴이 끝나면 고아 초안을 쓴다** — 조각만 흘리고 사실을 안 쓰는 길이 여럿이라 반쪽 답이 붙어 있던 창에만 남는다. 그리고 **도구가 돌려준 그림이 바닥에 안 떨어지나** — 폴드가 이름 대지 않는 part 종류는 빈 행이 아니라 **애초에 없던 행**이고, 아무것도 그렇게 말하지 않는다 |
| (`stream.test.ts` 계속) | **취소된 물음은 기다린다고 말하지 않는다.** `pending` 은 어시스턴트 조각이나 `turn.finished` 가 내리는데 중단된 물음은 둘 다 못 받아, 막대가 창 수명만큼 서 있었다. 두 사건이 같은 id 를 **다른 이름**으로 싣는 것(`messageId` vs `msgId`)까지 Go 소스와 함께 문다 |
| `plan.test.ts` | **계획판에 계획이 있나.** UI 설계가 「todo 와 그 상태」를 약속하는데 판은 계기 다섯만 그리고 있었다 — 젯브레인은 `todos.changed` 를 읽고 이쪽은 그 사건을 무시했다. **마지막 사건이 이긴다**(매번 목록 전체가 오므로 누적하면 두 번째부터 틀린다), 글자 없는 항목은 항목이 아니다, 모르는 상태도 빈칸이 아니라 네모로 그린다 |
| `panel.test.ts` | **계획판의 사실을 데몬이 실제로 채우는 칸에서 읽는다.** `jobs`·`roster`·`context` 는 구조체로 답하고 `out` 을 **한 번도 안 채운다**(실물 실측) — 판은 넷 다 `out` 을 읽어서 다섯 칸 중 셋이 모든 빌드에서 비어 있었고, 「백그라운드 잡 멈추기」는 늘 「도는 게 없다」고 답했다. 아무것도 실패하지 않았다: 없는 칸은 빈 문자열이고, 빈 문자열이 바로 「보고할 것 없음」의 모양이다. 그리고 **`children` 은 제 칸으로 온다** — `sessions` 를 읽으면 영영 「자식 없음」이다(Go 의 태그와 명령의 읽기를 함께 문다) |
| `setup.test.ts` | **무엇으로 도나를 읽는 규칙**(모델·백엔드·승인 모드). 데몬은 늘 보내 왔고 이쪽이 버리고 있었다. 세션을 안 준 답에는 모델이 **없다**는 것(빈칸이 아니라 「안 말했다」), 공백은 값이 아니라는 것, 그리고 `jobs`·`cron` 의 산문에서 id 를 **알아볼 때만** 뽑는다는 것 |
| `touched.test.ts` | **컴패니언이 고친 것을 전사에서 읽는 규칙.** 어떤 파일이 바뀌었나, 그리고 무슨 글자를 넣었나(`new` — 표식이 찾을 것이 그것이다). 실패한 호출·아직 안 끝난 호출은 안 센다, 통째로 쓴 파일은 넣은 글자가 없다, bash 는 이름 댈 파일이 없다 |
| `webview.test.ts` | 웹뷰 템플릿에 백틱이 없나(템플릿 리터럴을 닫아 버린다 — 실제로 겪었다), `innerHTML` 을 안 쓰나, CSP 가 빡빡한가. **주석은 벗기고 잰다** — 낱말이 주석에 있다고 통과하면 안 된다 |

## 2. `src/live/` — 실물 VS Code 안에서

**매니페스트는 단위 시험이 못 잰다.** `contributes` 의 오타는 모든 단위 시험을 통과하고 편집기
에서 아무 일도 안 한다 — 아무도 등록 안 한 뷰는 그냥 안 나타나기 때문에 에러도 없다.

`selfcheck.ts` 가 도는 편집기 안에서 잰다:

- 확장이 **실제로 활성화되나**(기다린다, 경주하지 않는다 — `onStartupFinished` 는 이 시험보다 늦다)
- 매니페스트가 약속한 명령 **스물셋이 전부 등록됐나**(목록에서 세는 것이라 늘어도 안 늙는다)
- 뷰가 **둘뿐이고** 둘 다 웹뷰이며, 대화는 패널 컨테이너에 계획은 `magi-side` 에 있나
- 그 `magi-side` 가 **보조 사이드바에 걸려 있나** — 자리는 매니페스트의 한 낱말이라, 왼쪽으로
  되돌아가도 뷰와 id 는 그대로여서 위의 줄들이 전부 통과한다
- 설정이 **진짜 설정**이지 웹뷰가 아닌가
- 대화 뷰가 **실제로 열리나**(리졸브에서 터지는 프로바이더를 잡는 자리)
- 이 창이 계산한 소켓 경로에 **진짜 데몬이 있나**

```
cd clients/vscode && npx tsc -p . && node out/live/run.js
```

**변이로 확인했다**(2026-09-08): 매니페스트에 없는 명령을 약속하게 하면 빨강, 뷰 id 에 오타를
내면 빨강.

## 3. CI 가 안 재는 것

- **실물 검사는 CI 에서 안 돈다.** 편집기를 띄워야 하고, 그러려면 러너가 VS Code 를 통째로
  내려받는다. 릴리스 레인은 단위 시험만 돌린다 — 그러니 **매니페스트 회귀는 CI 가 못 잡는다.**
  손으로 §2 를 돌리고 나서 태그를 단다.
- **웹뷰 안의 그림.** 행이 어떻게 보이는지, 테마가 바뀌면 어떻게 되는지는 아무도 안 잰다.
- **인라인 완성·인레이가 화면에 실제로 뜨는지.** 프로바이더가 등록된 것까지만 잰다.
- **승인 답하기의 왕복.** 단추가 보내는 것까지는 코드에 있고, 컴패니언이 그것으로 진행하는지는
  실물 턴이 필요해 안 쟀다.
