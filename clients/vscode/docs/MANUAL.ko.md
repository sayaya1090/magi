# VS Code 확장 — 사용자 매뉴얼

[↑ 클라이언트 개요](../README.md) · [설계](./DESIGN.ko.md) · [화면 설계](./UI.ko.md) · [플랫폼 규약](./PLATFORM.ko.md) · [형제: 젯브레인 매뉴얼](../../jetbrains/docs/MANUAL.ko.md)

> **여기 적힌 것은 지금 도는 것뿐이다.** 설계에 있고 아직 안 만든 것은 여기 없다 — 매뉴얼이
> 없는 기능을 설명하면 사람은 자기 설치가 고장 났다고 읽는다.
>
> 지금은 [설계 §9](./DESIGN.ko.md) 의 **1단계(척추)** 까지다. 무엇이 아직 없는지는 §6 에 적었다.

---

## 1. 시작하기

1. 확장을 깐다.
2. **폴더를 연다.** 컴패니언은 워크스페이스의 것이라, 폴더가 없으면 이 확장은 아무것도 안 한다.
3. 아래쪽 **패널**에 `magi` 탭이 선다(터미널·문제가 사는 그 자리다). 안 보이면 명령 팔레트에서
   **magi: Open the conversation**.

`magi` 실행 파일이 있으면 이 워크스페이스의 컴패니언을 **알아서 띄운다**. 없으면 상태 표시줄이
「not running」이라 말하고, **magi: Start the companion for this workspace** 를 누르면 어디서
받는지 알려 준다.

### 엔진은 창보다 오래 산다

컴패니언은 VS Code 밖의 프로세스다. 창을 닫아도 계속 돌고, 다시 열면 **하던 대화가 그대로**
있다. 대화의 원천이 이 확장이 아니라 데몬이기 때문이다. 같은 워크스페이스를 터미널의 magi 나
웹 콘솔로 열면 **같은 대화**가 보인다.

---

## 2. 패널 「magi」 — 대화

### 2.1 전사 읽는 법

컴패니언의 턴을 일어나는 그대로 본다. 행의 종류:

- **사람** — 보낸 글 그대로. 답을 기다리는 동안 왼쪽에 막대가 선다.
- **magi** — 컴패니언의 답.
- **(생각)** — 흐리게. 접힌 채로 온다.
- **도구 한 행** — 이름 한 줄. 결과가 오면 같은 행에 **✓/✗** 가 얹힌다(행을 갈라 그리지 않는다).
- **카운슬** — melchior·balthasar·casper 는 자리 색을 받는다. 그 셋 말고는 색이 없다.
- **오류** — 편집기의 오류 색으로. 회복된 오류에는 `(recovered)` 가 붙는다. 턴이 끝난 것이 아니라는 뜻이다.

색은 하나도 이 확장이 정하지 않는다. 전부 지금 쓰는 테마의 것이라, 테마를 바꾸면 같이 바뀐다.

### 2.2 입력줄

**Enter 로 보낸다. Shift+Enter 는 줄바꿈이다** — 터미널도 웹 콘솔도 그렇다.

### 2.3 세우기

패널 툴바의 **정지 아이콘**이 도는 턴을 세운다.

---

## 3. 상태 표시줄

왼쪽 끝에 한 칸이 선다. **패널을 접어 둬도 보인다.** 그것이 이 칸이 있는 이유다.

| 보이는 것 | 뜻 |
|---|---|
| `magi: idle` | 붙었고, 지금은 노는 중 |
| `$(loading~spin) magi: working · …` | 턴이 도는 중. 뒤에 도구가 남긴 말이 붙는다 |
| `magi: waiting on you · …` | **사람의 답을 기다린다** |
| `magi: not running` | 이 워크스페이스에 컴패니언이 없다 |
| `magi: cannot say` | 물어봤는데 답을 못 받았다. **「노는 중」과 다른 말이다** |

마지막 두 줄을 가르는 것이 중요하다. 「없다」와 「모른다」는 다른 사실이고, 둘을 같은 글자로
그리면 화면이 모르는 것을 아는 척한다.

**누르면** 대화 패널이 선다.

⚠ 승인을 기다릴 때도 **배경색이 바뀌지 않는다.** 글자로 말한다 — 기다리는 것은 오류가 아니고,
상태 표시줄에 색을 쓰는 것은 VS Code 가 「최후의 수단」으로 두는 자리다.

---

## 4. 명령

명령 팔레트(⇧⌘P)에서 `magi` 로 찾는다.

| 명령 | 무엇 |
|---|---|
| **magi: Open the conversation** | 패널의 대화를 연다 |
| **magi: Start the companion for this workspace** | 컴패니언을 띄운다 |
| **magi: Stop what the companion is doing** | 도는 턴을 세운다 |

**기본 단축키는 없다.** 남의 키를 덮지 않으려는 것이라, 원하는 키는 직접 묶으면 된다
(Keyboard Shortcuts → `magi`).

---

## 5. 설정

Settings → `magi` 로 찾는다. **별도 설정 화면은 없다.** VS Code 가 그리는 것을 쓴다.

| 설정 | 기본 | 무엇 |
|---|---|---|
| `magi.startCompanion` | 켜짐 | 폴더를 열 때 컴패니언이 없으면 띄운다 |

승인 모드·모델처럼 **데몬이 원천인 값**은 여기 없다. 그것들은 컴패니언의 설정이지 이 확장의
것이 아니고, 지금은 터미널의 magi 나 웹 콘솔에서 바꾼다.

---

## 6. 아직 없는 것

설계에는 있고 아직 안 만든 것이다. 있는 척하지 않으려고 적는다.

- **계획·계기판**(우측 사이드바) — 계획·컨텍스트·잡·플릿.
- **편집기 안의 것** — 인라인 완성, 타이핑 중 훑어보기, 인레이, 훑어보기 띠, 컴패니언이 고친
  줄 표식.
- **진입점** — 코드 액션(「이 코드 물어보기」), 대화에 첨부, 커밋 메시지 초안, 이 줄을 누가 썼나,
  오류 물어보기.
- **승인에 답하기** — 컴패니언이 물으면 지금은 전사에 보이기만 한다. 답은 터미널이나 웹 콘솔에서.
- **`@` 멘션과 참조 칩**, **컴포저 제안**, **대화 탭**(한 컴패니언의 여러 대화).
- **코어 자동 내려받기** — 지금은 `PATH` 나 이미 받아 둔 것만 쓴다. 창이 여럿일 때 한 번만 받는
  일이 따로 만들 값이 있어 미뤘다.

무엇이 어느 단계에 들어가는지는 [설계 §3 이식표](./DESIGN.ko.md)에 있다. 그 표는 손으로 쓰지 않는다. 젯브레인 매뉴얼에서 뽑아 시험이 대조한다.

---

## 7. 알아두면 좋은 것

- **창을 껐다 켜도 대화는 그대로다.** 원천이 데몬이다.
- **데몬이 답을 물고 늘어지면** 이 확장이 마감에서 연결을 끊고 그렇게 말한다. 조용히 멎지 않는다.
- **같은 폴더를 창 둘에 열면** 대화도 둘이다. 데몬은 하나라 전사는 같지만, 입력이 두 자리다.
- **여러 폴더를 한 창에 열면**(멀티 루트) 첫 폴더의 컴패니언만 본다. 한 화면에 엔진 둘은 어느
  쪽이 답했는지 말할 방법이 없다.
