## 1. 시작하기

### 설치 절차

```sh
cd clients/vscode
npm install && npx tsc -p .
npx --yes @vscode/vsce package --no-dependencies --allow-missing-repository
code --install-extension magi-0.2.0.vsix --force
```

설치 완료 후 **작업 폴더를 엽니다.** 컴패니언은 워크스페이스 단위로 격리되어 동작하므로 폴더가 열려 있지 않으면 확장은 비활성 상태를 유지합니다(다중 루트 워크스페이스의 경우 첫 번째 루트 폴더를 바인딩합니다).

시스템 `PATH` 또는 사전에 다운로드된 경로에 `magi` 바이너리가 존재할 경우, 확장이 해당 작업 디렉토리의 컴패니언 데몬을 **자동으로 감지하거나 구동**합니다. 바이너리가 부재할 경우 상태 표시줄에 `magi: not running` 상태가 표기됩니다.

### 데몬 프로세스의 수명 주기

컴패니언 데몬은 VS Code 외부의 독립 운영체제 프로세스입니다. 편집기 창을 닫아도 백그라운드에서 실행을 유지하며, 창을 다시 열면 **진행 중이던 대화 세션이 그대로 복원**됩니다. 동일한 워크스페이스를 터미널 CLI(`magi`)나 웹 콘솔에서 열더라도 **동일한 대화 전사 내역**이 실시간 동기화됩니다.

## 2. 화면 영역 안내

| 화면 영역 | 배치 컴포넌트 및 역할 |
|---|---|
| **하단 패널 `magi`** (🤖) | 주 대화 뷰. 터미널 및 문제 패널과 동일한 컨테이너에 위치하며 창 실행 시 기본 노출됩니다 |
| **우측 보조 사이드바 `magi`** | 계획 및 계기판 뷰 |
| **상태 표시줄 좌측** | 컴패니언 실행 상태 **및 적용 모델명**. 클릭 시 상세 메뉴(§5.1)가 호출됩니다 |

패널이 보이지 않을 경우 커맨드 팔레트(⇧⌘P)에서 **magi: Open the conversation**을 실행하십시오. 창 오픈 시 패널 자동 노출 여부는 `magi.openConversation` 설정으로 제어할 수 있습니다 (`whenRunning`(기본값), `always`, `never`).
우측 보조 사이드바가 접혀 있을 경우 **보기 > 모양 > 보조 사이드바**(⌥⌘B)로 열 수 있습니다.

## 3. 대화 패널

컴패니언이 **미실행 상태이거나 통신이 불가능할 경우** 입력창 상단에 해당 상태가 안내되며 **Start one** 단추가 노출됩니다. 연결 장애 발생 시에도 복구 단추가 상시 제공되므로 사용자가 손쉽게 프로세스를 재기동할 수 있습니다.

### 3.1 대화 전사(Transcript) 표시 규칙

- **사람 (User)** — 사용자가 입력한 메시지 원본. 응답 생성 중에는 좌측에 진행 인디케이터 바가 표시됩니다.
- **magi (Assistant)** — 컴패니언의 마크다운 응답 본문.
- **(생각) (Reasoning)** — 모델의 내부 추론 과정. 기본적으로 흐린 서체로 접혀 있습니다.
- **도구 한 행 (Tool Call)** — 호출된 도구명과 요약 인자. 실행 결과 도착 시 동일 행에 **✓/✗** 상태가 갱신됩니다.
- **데몬 내부 프롬프트 구분** — 플래너 및 카운슬의 내부 노트는 사용자의 발화와 구분하여 `⟳ 누가 note: …` 행으로 표기되며, 서브에이전트 보고는 해당 서브세션 전사에 격리됩니다.
- **카운슬 합의 (Council)** — 3인 카운슬 멤버(melchior, balthasar, casper)는 고유 색상으로 표시됩니다. **라운드가 열리는 것도 한 줄로 섭니다**(`opened · majority r1`) — 그 줄이 무엇을 판정하는지와 **문턱**을 말합니다. 문턱이 없으면 「둘은 계속, 하나는 완료」가 과반으로 지나가는 것인지 셋 다여야 하는 것인지 알 수 없습니다. 라벨에 **검토 렌즈와 투표 결과**가 표기되고(`[correctness] ✗ reject r2`), 하단에 **판정 근거**(`on:`) 및 **유지 요구사항**(`keep:`)이 첨부됩니다. 판정 근거는 diff 데이터이므로 **고정폭 글꼴로 원본 줄바꿈을 유지**하여 렌더링합니다.
- **오류 (Error)** — VS Code 테마의 오류 색상 적용. 재시도 등을 통해 회복된 오류는 `(recovered)` 표식을 덧붙여 턴이 중단되지 않았음을 명시합니다.

모든 시각 요소는 사용자가 설정한 VS Code 테마 토큰을 100% 반영합니다.

### 3.2 프롬프트 입력창

**Enter 키로 전송하며, Shift+Enter는 줄바꿈을 수행합니다.**

입력창 상단에는 **참조 칩(Chip)**이 표시됩니다. 에디터 컨텍스트 메뉴의 「Add this code to the conversation」으로 첨부된 코드 조각들이며, 전송 시 함께 전달된 후 자동으로 비워집니다. 개별 `clear` 버튼으로 제거할 수도 있습니다.

### 3.3 승인 및 선택지 질의

**두 인터랙션은 명확히 구분됩니다.** 컴패니언이 위험 도구 실행을 시도할 때는 **allow · deny · always** 3개 버튼이 노출되며, 컴패니언이 **사용자의 의견을 질의**할 때는 선택지 버튼들과 함께 「answer in the box」 버튼이 표시됩니다. 후자를 선택할 경우 입력창의 내용이 **해당 질의의 응답으로 전달**되며 신규 턴을 임의 개시하지 않습니다.

질의 헤더에는 **질의가 생성된 시각**이 고정 표기됩니다(당일인 경우 시:분, 이전 날짜인 경우 날짜 포함). 상대 시간(예: "40분 전")이 아닌 절대 시각을 표기하는 이유는, 사용자가 자리를 비운 사이 작업이 멈춘 시점을 명확히 인지할 수 있도록 보장하기 위함입니다.

### 3.4 `@` 멘션을 통한 파일 탐색

입력창에서 단어 시작 위치에 `@` 문자와 2글자 이상을 입력하면 컴패니언이 접근 가능한 파일 목록을 자동완성 팝업으로 추천합니다. 에디터 워크스페이스뿐만 아니라 **컴패니언 데몬이 참조 가능한 전체 경로**를 대상으로 탐색합니다.

완성에 보내는 문맥은 **커서 양쪽 4000자**로 끊고, 읽는 것도 그만큼만 읽는다 — 파일 전체를
복사하지 않는다.

### 3.5 인라인 컴포저 제안

프롬프트 작성 중 입력을 잠시 멈추면 하단에 `Tab: …` 자동완성 힌트가 나타나며, **Tab** 키를 눌러 수락할 수 있습니다.

### 3.6 뷰 툴바 액션

- **눈 아이콘 (`magi.lookNow`)** — 현재 열린 파일 코드 훑어보기(Look over) 즉시 요청
- **정지 아이콘 (`magi.interrupt`)** — 현재 진행 중인 턴 즉시 중단
- **톱니바퀴 아이콘** — 컴패니언 카드 호출(§3.6a)
- **`…` 더보기 메뉴** — 세션 전환 및 환경설정

### 3.6a 컴패니언 정보 카드

컴패니언의 현재 런타임 환경과 주요 제어 명령을 한곳에 집약한 카드 UI입니다.

| 항목 | 표시 내용 및 기능 |
|---|---|
| ● 상태 | 상태 인디케이터 신호등. 상태 단어 자체가 스타일 클래스로 바인딩되어 일관된 색상을 표시합니다 |
| 빌드 버전 | 실행 중인 데몬의 빌드 판본 (`about`의 `version`) |
| 모델 · 백엔드 · 승인 | 현재 적용된 설정 확인 및 즉시 변경 인터랙션 제공 (데몬 제공 목록 연동) |
| fold context · restart · update | 컨텍스트 압축, 데몬 재기동, 바이너리 업데이트 액션 |

- ⚠ **`restart` 및 `update`는 사전 확인 대화상자를 거칩니다.** 실행 중인 턴이 즉시 종료되기 때문입니다. `shutdown` 명령은 제외되었습니다(프로세스 종료 후 복구 경로가 제한적이기 때문). 모든 명령은 로컬 워크스페이스 데몬에만 안전하게 적용됩니다.
- ⚠ **웹뷰 보안 원칙:** 웹뷰 내부에서 임의의 명령 식별자를 호출할 수 없도록, 카드가 요청 가능한 명령을 사전 정의된 화이트리스트 6종으로 엄격히 제한합니다.

## 4. 보조 사이드바 — 계획 및 계기판

우측 보조 사이드바의 magi 아이콘을 통해 진입하며, 7개 섹션 카드로 구성됩니다: **now · plan · context · jobs · scheduled · fleet · handed over**.

- ⚠ **fleet 상태 표기 원칙:** 데몬의 상태 열거형 중 비정상 중단(`abandoned`)과 정상 종료(`stopped`)는 명확히 구분된 개념입니다. 모르는 상태 코드는 가공 없이 원형 그대로 표기합니다.

| 섹션 | 표시 정보 |
|---|---|
| now | 현재 진행 중인 작업 요약 |
| plan | 에이전트의 TODO 항목 및 상태 (`✓` 완료 · `◐` 진행 중 · `☐` 대기). **대화 이벤트 스트림에서 복원**하므로 창을 재기동해도 최종 계획을 유지합니다 |
| context | 컨텍스트 창 점유율(`35103 / 200000 (18%)`) 및 **토큰 구성 비율**(전체 합계 대비 각 요소의 백분율 몫). **컨텍스트 압축(Fold) 후 잔여 내역**도 함께 명시합니다 |
| jobs | 실행 중인 백그라운드 프로세스, 서브에이전트 및 대기 큐 작업 목록 |
| scheduled | 주기적 예약 작업(cron). **실행 불가 상태인 예약은 ⚠ 마크와 사유를 함께 표기**합니다 |
| fleet | 동일 머신에서 구동 중인 타 컴패니언 현황. 상태 구절, 도달 가능 여부(`elsewhere`, `no answer`), 담당 역할 요약을 함께 표기합니다 |
| handed over | 타 컴패니언에게 인계한 작업 및 실시간 진행 상태(§7.1.5) |

- ⚠ **엔드포인트 미지원과 데이터 부재의 구분:** 구버전 데몬과의 통신 시 엔드포인트 미제공 상태를 「데이터 없음」으로 잘못 렌더링하지 않도록 분리 처리합니다.
- 보조 사이드바가 보이지 않을 경우 `보기 > 모양 > 보조 사이드바`(⌥⌘B)로 활성화할 수 있습니다.

## 5. 상태 표시줄

상태 표시줄 좌측 끝 단일 위젯으로 상시 노출되며, 패널을 최소화한 상태에서도 컴패니언의 상태를 파악할 수 있습니다.

| 표시 레이블 | 의미 |
|---|---|
| `magi: attached` | 데몬에 정상 연결되었으나 추가 상태가 전달되지 않은 상태 (정상 턴 실행 중 포함) |
| `$(loading~spin) magi: working · …` | 턴이 활발히 작업 중인 상태 |
| `magi: waiting on you · …` | **사람의 답을 기다린다** (사용자의 승인 또는 응답 대기) |
| `magi: not running` | 워크스페이스에 구동 중인 컴패니언이 없는 상태 |
| `magi: cannot say` | 데몬에 질의하였으나 상태 응답을 수신하지 못한 상태 |
| `magi: attached · gpt-oss:20b` | 활성 대화 세션에 할당된 **모델 식별자 표기** |

- ⚠ **`attached` 레이블의 의미:** `status` 질의 응답에 `waiting`이나 `doing` 필드가 없을 때 표출됩니다. 장시간 소요되는 도구(`read`, `bash`, `edit`) 실행 중에도 이 상태로 표시될 수 있으며, 결코 유휴(idle) 상태가 아닙니다.
- ⚠ 승인 대기 상태에서도 눈을 피로하게 만드는 경고성 배경색을 남용하지 않고 정갈한 텍스트로 알립니다.
- ⚠ 모델명은 활성 대화 세션이 존재하는 경우에만 결합되어 표시됩니다.

### 5.1 런타임 설정 퀵픽 — 상태 표시줄 클릭 시

상태 표시줄을 클릭하면 핵심 런타임 환경을 즉시 조회하고 변경할 수 있는 메뉴가 열립니다.

| 메뉴 항목 | 기능 및 세부 동작 |
|---|---|
| Open the conversation | 대화 패널 포커스 |
| Model: … | 현재 데몬이 제공하는 모델 목록 중 선택 (`models` → `set-model`) |
| Backend: … | 프로파일 선택 또는 **기본 백엔드로 복귀** (`profiles` → `use-backend`) |
| Approval: … | 승인 모드 전환 (ask · auto · allow · deny) |
| magi's own settings | 데몬 고유 설정 변경 (`config-get` → `config-set`). 파싱 실패한 설정 파일이 존재할 경우 선택 전 경고 및 사유를 우선 출력합니다 |
| Completion said nothing: … | 자동완성 제안이 비어 있을 때 그 원인(데몬 열거형 사유)을 문장으로 설명합니다 |

- ⚠ 사용자 탈출구 보장: 백엔드 프로파일 변경 후 언제든 원래의 기본 백엔드로 돌아올 수 있도록 「기본 백엔드」 선택지가 상단에 기본 제공됩니다.

## 6. 에디터 버퍼 내 기능

| 기능 | 에디터 표출 위치 | 활성화 방법 |
|---|---|---|
| **인라인 완성** | 커서 위치 회색 고스트 텍스트 | `magi.complete` 설정 (기본값 꺼짐) |
| **타이핑 중 훑어보기** | 타이핑 멈춤 시 버퍼 분석 | `magi.lookWhileTyping` 설정 (기본값 꺼짐). 지적은 그 줄 끝에 붙고, **파일에 없는 줄을 가리킨 지적은 버리지 않고** 번호를 붙인 채 위쪽 띠로 돌려준다 — 지적은 최대 셋이라 하나를 잃으면 화면이 「할 말 없음」과 똑같아진다 |
| **훑어본 말** | 해당 라인 끝 회색 인레이 힌트 | 상동 |
| **파일 전체에 대한 말** | 첫 줄 상단 데코레이션 띠 | 상동 (검토 의견이 있을 때만 표출) |
| **열린 버퍼 자동 동봉** | 백그라운드 자동 동기화 | 상시 동작 (미저장 버퍼 내용 실시간 전달) |
| **컴패니언이 고친 줄** | 라인 배경 하이라이트 및 에디터 눈금 | `magi.showEditMarks` 설정 (기본값 켜짐). 실제 삽입된 텍스트 위치를 검색하여 정확히 강조하며 턴 완료 시 소거 |

**Look over this file now** 명령은 자동 검토 설정이 비활성화되어 있어도 수동 실행이 가능합니다. 검토 결과 의견이 없을 경우 상태 표시줄을 통해 피드백을 제공합니다.

## 7.1.5 타 컴패니언 작업 인계 (`hand_off`)

계획판 제목줄의 **일 넘기기** 버튼 또는 커맨드 팔레트의 `magi: Ask another companion to do something`을 통해 진입합니다.

동일 머신 상의 다른 컴패니언에게 작업을 위임하며, 확장이 타 워크스페이스 소켓과 통신하는 유일한 경로입니다.

| 단계 | 수행 작업 |
|---|---|
| 1단계 | `roster`를 통해 연결 가능한 로컬 컴패니언 목록을 조회합니다 |
| 2단계 | 수행할 작업 내용을 기술합니다 |
| 3단계 | **단순 질의(`looking`)인지 작업 요청인지**를 지정합니다 |
| 4단계 | 접수증을 수신하여 계획판의 「handed over」 섹션에 등록하고 3초 간격으로 `hand-state`를 폴링합니다 |

- ⚠ **라벨 서명 규약:** `fleet.go`에 정의된 라벨 포맷을 엄격히 준수하여 체이닝 방지 및 출처 추적 무결성을 보장합니다.
- ⚠ **비동기 상태 수신:** 확장은 응답을 직접 대기하지 않고 상태를 지속 조회하므로, 상대 컴패니언에 상태 기록을 명확히 요청합니다.
- ⚠ **거절과 연결 단절의 구분:** 작업 거절(만료 또는 재기동)과 일시적 통신 단절을 구분하여 불필요한 무한 폴링을 차단합니다.

## 7.2 백그라운드 작업 및 예약 관리

계획판 제목줄의 전용 아이콘을 통해 관리합니다.

| 커맨드 | 호출 엔드포인트 | 동작 사양 |
|---|---|---|
| Stop a background job | `jobs` → `job-kill` | 데몬이 보고한 유효 작업 목록에서 선택하여 중단합니다. 이미 종료된 작업인 경우와 성공적으로 중단된 경우를 구분하여 사용자에게 알립니다 |
| Scheduled work | `cron` → `cron-set` · `cron-remove` · `reload-cron` | **`$`로 시작하는 항목은 셸 명령어로 자동 실행**되며 모델 질의를 거치지 않습니다. 비활성화된 항목은 「off」로 표기되며, 예약 시각은 최상위 `schedule` 필드로 전송됩니다 |

- ⚠ **「세웠다」와 「이미 끝나 있었다」는 다른 말로 답한다.** `job-kill`은 이미 완료된 작업에 대해 실패를 반환하지 않고 성공(`ok: true`)하되 `removed` 필드로 세부 상태를 구분합니다.

### 7.3 편집기 제어 도구 서버 (MCP HandServer)

확장이 로컬 루프백 인터페이스에 경량 MCP 서버를 구동하고 그 주소를 데몬에 등록(`mcp-attach`)합니다. 보안 권한 관리를 위해 서버 식별자는 **`vscode`로 고정**됩니다.

| 제공 도구 | 역할 | 권한 속성 |
|---|---|---|
| `mcp__vscode__show` | 파일 열기 및 지정 라인 커서 이동 | 읽기 전용 (안전) |
| `mcp__vscode__apply_edit` | 에디터 버퍼를 통한 코드 변경 적용 | 수정 작업 (승인 대상) |
| `mcp__vscode__problems` | 언어 서버 및 린터가 보고한 진단 내역 수집 | 읽기 전용 (안전) |

- ⚠ **읽기 전용 힌트 명시:** 도구 등록 시 `readOnlyHint`를 명확히 선언하여, 단순 조회 작업이 코어 기록상에 파일 수정으로 오인 기록되는 것을 방지합니다.
- ⚠ **워크스페이스 밖은 거절합니다.** 세 도구 모두 컴패니언이 대는 경로를 워크스페이스 안으로 한정합니다 — 절대 경로든 `..` 로 걸어 나가는 경로든 「이 워크스페이스 밖입니다」로 거절합니다. 데몬도 컴패니언을 프로젝트에 가두지만, 편집기 손은 같은 기계로 난 둘째 문이므로 여기서도 지킵니다. 심링크는 따라가지 않습니다(안에서 밖을 가리키는 링크는 통과합니다).
- ⚠ **루프백 보안 토큰 인증:** 로컬 타 프로세스의 무단 접근을 방지하기 위해 모든 HTTP 요청의 헤더 토큰을 선행 검증합니다 (미인증 시 HTTP 403).
- ⚠ **단일 창 우선 바인딩:** 동일 워크스페이스를 여러 창으로 열 경우 최초 연결된 창이 제어권을 가지며, 후속 창은 안전하게 거절 처리됩니다.

## 9. 운영 시 참고 사항

- **에디터 재시작 후 세션 보존:** 세션 데이터의 원천이 데몬에 영속화되어 있으므로 창을 재기동해도 대화가 유지됩니다.
- **타임아웃 마감 관리:** 데몬 응답 지연 시 마감 시간이 도달하면 연결을 안전하게 종료하고 사용자에게 알립니다.
- **수정 파일 자동 리로드 및 더티 버퍼 보호:** 컴패니언이 수정한 파일은 에디터에 자동 반영되나, 사용자가 편집 중인 미저장 버퍼는 덮어쓰지 않고 보호합니다.
- **다중 창 독립 대화창 지원:** 동일 폴더를 2개 창으로 열 경우 단일 데몬을 공유하되 창마다 독립적인 입력 상호작용이 가능합니다.
- **중단된 질의의 시각 표식:** 사용자가 중단한 프롬프트는 취소 표식(취소선)으로 정리되어 진행 바가 무한 대기하지 않도록 처리합니다.
- **스트리밍 델타 청크의 확정 치환:** 조각 데이터(`part.delta`)를 누적 렌더링하고 스트림 완료 시 확정된 본문으로 완벽히 치환합니다.
- **스크롤 고정 지원:** 사용자가 이전 대화를 스크롤하여 읽고 있을 때는 새 응답이 도착해도 스크롤을 강제로 하단으로 끌어내리지 않습니다.
- **연결 단절 시 복구 버튼 제공:** 컴패니언 연결이 끊어졌을 때 대화 패널에 즉시 「Start one」 버튼을 제공하여 빠른 복구를 돕습니다.
- **비활성 시 폴링 간격 자동 조정:** 컴패니언 미실행 시에는 소켓 폴링 주기를 10초로 완화하여 리소스 낭비를 방지합니다(실행 중에는 2초 주기).
