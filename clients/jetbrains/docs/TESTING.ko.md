# 무엇을 어디서 재나

[↑ 클라이언트 개요](../README.md) · [사용자 매뉴얼](./MANUAL.ko.md) · [플랫폼 규약 대조표](./PLATFORM.ko.md) · [화면 설계](./UI.ko.md)

> **왜 이 문서가 있나.** 이 레인의 시험은 층이 다섯이고, 층마다 **도는 조건이 다르다.** 어떤
> 것은 push 마다 돌고, 어떤 것은 데몬이 살아 있어야 돌고, 하나는 릴리스 태그를 밀 때만 돈다.
> 그 조건을 모르면 「초록이니까 됐다」가 「그 층은 애초에 안 돌았다」와 같아 보인다 — 이 저장소는
> 그 착각으로 하루 넘게 CI 가 빨간 줄 몰랐고, 같은 날 `:core:test` 가 입력 선언 누락으로 통째로
> 안 돌던 것도 찾았다.

**마지막 실측: 2026-09-01 — 212개, 실패 0, 건너뜀 6**(라이브 데몬 1, 모델 적합성 5 — 둘 다
청해야 도는 것들이다). 이 줄은 커밋마다 갱신한다. 「초록이었다」는 기억이 아니라 날짜와 수로
남아야, 다음 사람이 무엇을 근거로 믿는지 안다.

## 층 다섯

| 층 | 어디 | 언제 도나 | 무엇을 아나 |
|---|---|---|---|
| 1. 단위 | `plugin/core/src/test` | push 마다 | 셰이퍼·전송·파서의 규칙 |
| 2. 소스 글자 | `SourceTextTest` (16) | push 마다 | 컴파일러가 안 잡는 규칙 |
| 3. 유도 가드 | `ManualTest`·`ArchitectureTest`·`PaletteTest` | push 마다 | 광고면과 문서·구조가 갈렸나 |
| 4. 헤드리스 IDE | `plugin/intellij/src/test` (10) | push 마다 | 진짜 IDE 안에서 우리 것이 서나 |
| 5. 라이브 | `live/`·`LiveDaemonTest` (6) | 청해야 | 진짜 데몬·진짜 모델과 맞나 |

릴리스 태그(`jetbrains-v*`)를 밀면 여기에 **여섯째**가 붙는다 — `verifyPlugin` 이 세 IDE
(IU-261·IU-262·PY-261)의 바이트코드에 대고 검증한다. 1.7GB 를 받고 6분이 걸려 push 레인에는
없다. **태그를 밀기 전에 로컬에서 한 번 돌릴 것** — 2026-08-31 에 그것으로 첫 릴리스가 죽을
뻔했다(내부 API 사용 여섯).

## 1. 단위 — 규칙이 사는 자리

`plugin/core` 는 IntelliJ SDK 를 안 당긴다. 순수 JVM 이라 몇 초에 돌고, 그래서 **규칙은 되도록
이쪽으로 옮긴다.**

- **셰이퍼**(`RowsTest` 13, `TranscriptTest` 16) — 데몬의 사건을 화면 행으로 바꾸는 규칙.
  사실과 전이의 갈림, 타자기(부분 조각), 재부상, 접힘.
- **전송**(`SocketPathTest` 11, `SocketReachTest` 5, `CompanionTest` 17) — 소켓 이름이 코어의
  Go 와 같은가, 붙어 보고 만난 것을 어느 갈래로 가르는가, 문마다 무엇을 싣는가.
- **파서**(`LookNotesTest` 4, `MarkdownTest` 5, `RowTextTest` 6) — 모델이 준 글자에서 줄번호를
  뽑고, 마크다운을 펴고, 행의 글자를 정한다.
- **규칙 층**(`DaemonLifecycleTest` 11) — 소켓 없이 「살았나·죽었나·나갔나」 판정만.

`RowTextTest` 는 최근에 생겼다. 그 여섯 규칙은 1500줄짜리 창 클래스 안에 사설 함수로 있어서
**화면을 눈으로 봐야만** 확인됐는데, 하는 일은 문자열 계산이라 이쪽으로 옮기니 그대로 재진다.

## 2. 소스 글자 — 컴파일러가 안 잡는 것

`SourceTextTest` 는 클래스가 아니라 **소스 글자**를 읽는다. 여기 있는 규칙은 전부 「돌긴 도는데
딴것을 한다」 부류라, 타입도 맞고 빌드도 초록이고 다른 시험도 다 통과하는데 사람이 보는 것이
틀린다. 잡을 자리가 여기밖에 없다.

지금 재는 것 중 몇 가지:

- 달러를 글자로 박아 두면 화면에 템플릿 원문이 찍힌다.
- 라벨에 붙는 남의 글자는 거르는 함수를 거쳐야 한다.
- **창을 거두는 자리는 클래스를 처음 로드하지 않는다** — IDE 가 나갈 때 우리 클래스로더는 이미
  닫혀 있을 수 있고, 터진 `dispose` 는 그 아래 정리를 통째로 거른다(라이브에서 실제로 났다).
- **설정 디렉토리를 정하는 자리는 하나다** — 두 곳이 각자 정하고 있었고, 셸에서
  `MAGI_CONFIG_DIR` 을 쓰는 기계에서 창과 열린 버퍼가 다른 소켓을 봤다.

## 3. 유도 가드 — 두 벌이 갈리는 것을 막는다

목록을 두 벌 적으면 안 재지는 쪽이 갈린다. 그래서 이 셋은 **원천에서 유도**한다.

- `ManualTest` — `META-INF/*.xml` 전부에서 액션·그룹의 글자를 뽑아, 번들 양쪽에 있는지와
  매뉴얼에 적혔는지 본다. 디스크립터에 `text=`/`description=`/`displayName=` 을 직접 적으면
  거기서 운다. 번들 값이 MessageFormat 으로 서는지, 홑따옴표가 짝인지, **값이 비지 않았는지**도
  같이 잰다(여러 줄 문구에 진짜 줄바꿈을 적으면 값이 끊기는데 파일은 겉보기에 멀쩡하다).
- `ArchitectureTest` — 계층 방향과 `usecase/` 의 파일 목록. 목록을 못박은 이유는 그 시험이
  **빈 목록을 보고 조용히 초록**이 되는 것을 막기 위해서다.
- `PaletteTest` — 화면 색이 TUI 의 원본(`internal/adapter/tui/styles.go`)과 같은가.

## 4. 헤드리스 IDE — 창 없이 진짜 IDE

`plugin/intellij/src/test` 는 최근에 생겼다. **그전에는 이 모듈에 시험이 하나도 없었다.** 그래서
액션이 언제 보이나, 인텐션이 언제 서나, 번들이 어느 글자를 주나 같은 규칙은 전부 사람이 IDE 를
띄워 눈으로 봐야만 확인됐고, 실제로 그 값을 여러 번 치렀다 — 안 뜨는 액션, 안 닫히는 탭, 판을
가로로 벌리는 라벨.

`TestFrameworkType.Platform` 이 창 없이 `Project`·`Editor`·액션 시스템을 프로세스 안에 세운다.
우리는 사람이 쓰는 것과 같은 입구로 들어간다.

지금 아홉을 잰다. 그중 다섯은 **사람이 IDE 를 띄워 눈으로 보던 점검표 항목**을 옮겨 온 것이다 —
우클릭이 하위 메뉴 하나인가, 그 안에서만 접두를 벗기는가, 설명문 라벨이 판을 가로로 안 벌리는가
(사람이 「가로로 쭉 늘어남」으로 잡았던 자리다. 재는 것은 선호 폭이 아니라 **최소 폭**이다 —
그것이 글자 길이만큼이면 판은 그 아래로 못 좁혀진다), 도구창 아이콘이 로드되는가, 스위치 기본값.

눈으로 본 것은 다음 판에서 다시 봐야 하지만, 여기 적힌 것은 매 push 마다 돈다.

이 모듈만 JUnit 4 다. `BasePlatformTestCase` 가 JUnit 3 계보라서고, `core` 는 JUnit 5 그대로다.

## 5. 라이브 — 진짜 데몬, 진짜 모델

두 가지가 있고 둘 다 **청해야** 돈다. 아무 데서나 돌면 남의 데몬을 건드리고, 하나는 모델을
실제로 불러 돈과 시간을 쓴다.

### 5.1 데몬에 붙는다

```sh
MAGI_IDE_PROBE_SOCK=/tmp/mw1/daemon-ws1-b1lp9vc8.sock ./gradlew :core:test
```

부르는 것은 `about` 과 `models` 뿐이다. 둘 다 읽기이고 턴을 안 건드린다. 골든 해시가 맞아도
전송이 틀리면 소용없으므로 한 번은 실물을 봐야 한다.

### 5.2 모델을 갈아 끼웠을 때 — 적합성 배터리

```sh
MAGI_IDE_CONFORMANCE=1 ./gradlew :core:test --tests '*ModelConformance*' --rerun-tasks
```

**코어의 E2E 가 못 보는 자리를 잰다.** 코어(`internal/app/e2e_test.go`)는 에이전트 루프를 본다 —
툴을 부르고 파일이 생겼나. 그런데 이 플러그인이 쓰는 문 셋(`complete`·`suggest`·`look-over`)과
커밋 초안은 **그 루프를 안 탄다.** 한 번 왕복하고 글자 하나를 돌려줄 뿐이고, 그 글자를 우리가
파싱해서 화면에 꽂는다. 그래서 모델이 바뀌면 코어 시험은 전부 초록인데 IDE 만 이상해진다:

- 완성을 ``` ``` ``` 으로 감싸 보내면 그대로 커서 자리에 백틱이 꽂힌다.
- 완성이 접두를 되풀이하면 같은 줄이 두 번 써진다.
- 「다음은 완성입니다:」 같은 머리말도 코드로 들어간다.
- 훑어보기가 줄번호를 계약과 다른 모양으로 붙이면 지적이 **줄에서 떨어져** 전부 띠로 밀린다.
  화면에서는 「할 말이 없다」와 구분이 안 간다.

재는 것은 **답의 내용이 아니라 모양**이다. 모델마다 문장이 다른 것은 결함이 아니다. 꽂을 수 있는
모양인가, 우리 파서가 짚어내는가, 그리고 거들기 문을 부른 뒤 워크스페이스가 안 바뀌었는가만 본다.
마지막 것은 부른 전후로 `git status --porcelain` 을 견준다 — 완성 한 번이 파일을 바꾸면 사람은
자기가 안 한 변경을 보게 된다.

끝에 성적표가 찍힌다. **통과한 것까지 적는다** — 초록이 「안 재고 지나감」과 같아 보이면 안 된다.

판정 자체는 라이브 밖에 있다. `Shapes` 는 순수 함수이고 `ShapesTest`(9)가 **실제로 겪은 나쁜
모양들**을 먹여 판정이 우는지 확인한다. 인라인으로 두면 모델이 있어야만 도는 코드가 되어, 정작
모델을 갈아 끼운 날 판정이 고장나 있어도 「전부 통과」로 보인다. 재는 기계도 재야 한다.

## 여기서 안 재는 것

**사람의 눈이 아직 필요한 것.** 점검표에서 아직 못 옮긴 자리들이고, 못 옮긴 사유가 각각 있다.

| 항목 | 왜 아직 사람인가 |
|---|---|
| 탭의 ✕(주 탭엔 없고 연 탭엔 있다) | 탭을 세우려면 데몬에 붙는 뷰가 서야 한다 — 2026-09-01 사람 확인 |
| 상태 표시줄 클릭·툴팁 | 위젯이 상태 표시줄에 붙은 뒤라야 의미가 있다 |
| 터미널 우클릭 항목 | 새 터미널 엔진의 편집기가 있어야 한다 |
| 대화 목록이 열리는가 | 데몬과 대화가 필요하다 |
| 데몬 자동 실행·내려받기 | 프로세스를 띄우고 네트워크를 탄다 — 그래서 시험 안에서는 **아예 안 띄운다**(`StartDaemon.enabled`) — 2026-09-01 사람 확인 |
| 다크 테마에서 아이콘이 보이는가 | 색 패칭은 실제 테마가 서야 확인된다 |

- **진짜 창을 클릭하는 것.** 4층은 창을 안 띄운다. 마우스로 눌러 보는 것은
  `runIdeForUiTests` + Remote-Robot 의 몫이고, 디스플레이가 필요하며 잘 흔들린다. 지금 층으로
  못 재는 것이 나오면 그때 얹는다.
- **데몬의 에이전트 루프.** 툴 호출·계획·카운슬은 코어(Go)의 E2E 와 `internal/eval` 이 잰다.
  이쪽은 그 결과를 **받아서 그리는** 부분만 본다.
- **창을 여럿 띄운 상태의 행동.** 손이 하나뿐이라는 계약, 고정 탭의 스트림 수명 같은 것은
  주석과 사람의 손에 남아 있다.
- **자동 기동이 실제로 붙는 것.** 규칙(`Restarts` 6·`StartDaemon` 갈래)은 재지만, 프로젝트를
  열어 상태 표시줄이 실제로 `Connected` 가 되는 자리는 사람이 본다. 2026-09-01 에 확인했다 —
  이 경로가 **끝까지 돈 것은 이날이 처음**이다. 그 전에는 `magi: Not running` 에서 안 바뀌었고,
  원인은 JVM 이 띄운 데몬이 IDE 의 프로세스 그룹에 묶여 죽는 것이었다. 코어가 `--detach` 를
  내주면서 닫혔다(CLI 실측 1.6초·`PPID 1`·자기 PGID, IDE 실측 같은 날).
- **수준이 탭 제목으로 새지 않는 것.** 「수준이 글자가 되는 자리가 없다」는 `SourceTextTest` 가
  소스로 막지만, 그것은 **우리가 아는 자리**만 막는다. 2026-09-01 에 사람이 영문 IDE 에서
  확인했다 — 탭은 `Chat`·`Findings` 이고, 첫 탭을 드래그해 놓아도 둘째 탭 제목이 안 번진다.
  이 두 번째 절이 중요하다: 원래 결함이 **드래그했을 때만** 둘째 탭까지 물들이는 모양이었다.

- **받아온 코어 바이너리의 실행.** 받는 규칙(`CoreReleaseTest` 6)은 재지만, 실제로 내려받아
  돌려 보는 자리는 없다. 2026-08-31 에 사람이 손으로 한 번 확인했다(체크섬 일치, macOS 검역
  딱지 안 붙음, `--version` 응답).

## 가드를 새로 세울 때 묻는 셋

하루에 같은 실패를 네 번 만나고 정리한 것이다. **전부 「초록인데 안 재고 있다」의 변형**이었다.

1. **훑는 범위가 규칙이 사는 범위와 같은가.** `ManualTest` 가 디스크립터 하나만 보고 있었고,
   dispose 가드가 셋 중 하나만 보고 있었고, 경로 치환이 백틱 붙은 것만 보고 있었다.
2. **그 작업이 실제로 도는가.** `:core:test` 가 `UP-TO-DATE` 로 건너뛰고 있었다 — 시험이 읽는
   `.xml`·`.properties`·`docs/` 가 `inputs.files` 에 없었다. 일부러 결함을 넣어도 초록이었다.
3. **픽스처가 이름이 말하는 그것인가.** 「크래시 잔여물」을 보통 파일로 흉내 내면 크래시를 안
   재게 되고, 그 갈래를 가르는 판정이 들어오는 순간 **시험이 결함 쪽을 지킨다.**

셋 다 **일부러 실패시켜 빨간 것을 봐야만** 확인된다. 이 문서에 적힌 가드는 전부 그렇게 확인했다.
