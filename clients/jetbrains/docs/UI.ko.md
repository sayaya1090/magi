# JetBrains 플러그인 — 화면 설계

[↑ clients/jetbrains](../README.md)

> **무엇을 정하는 문서인가.** magi 의 화면은 지금 셋이다 — 웹 콘솔(`cmd/magi-web`), 터미널
> (`internal/adapter/tui`), 그리고 이 플러그인. 이 문서는 **이 플러그인이** 그 대화를 IDE 의 어느
> 자리에 어떻게 그리는가를 정한다. 구현 전에 쓴다 — §1 은 실측한 현재이고, §3 부터가 결정이다.
>
> **다른 IDE 클라이언트(VS Code, Visual Studio)를 만드는 사람에게.** 구현은 각자 다르고 문서도
> 각자 갖는다. 다만 여기서 **§0 불변식, §2 의 판정(행을 짓는 규칙은 어디 사는가), §5 의
> 슬래시→설정 분류, §7 안 하는 것**은 클라이언트가 바뀌어도 다시 판정할 일이 아니라 옮겨 적을
> 것이다. 자리 배치(§4)만이 각 IDE 의 어휘로 다시 정할 일이다 — VS Code 의 Panel/Sidebar/
> StatusBarItem, Visual Studio 의 ToolWindow/도킹이 JetBrains 의 그것과 이름만 다른지 성질까지
> 다른지(게으른가, 폭이 있는가, 액션 슬롯이 있는가)를 §4 의 각 행마다 확인하고 갈리는 것만 적으라.

---

## 0. 불변식

0-1. **한 대화의 행을 짓는 규칙은 한 벌이다.** 규칙을 두 벌 적으면 안 재지는 쪽이 갈라진다. 이
저장소가 이미 그 값을 치렀다 — `Activity.of` 가 생기기 전 상태 표시줄은 데몬이 안 말한 것을
"쉬는 중"으로, 우측 판은 같은 자리를 "도는 것 없음"으로 그렸다. 한 규칙, 두 벌, 갈라짐.

0-2. **화면은 얕게 그린다.** 무엇을 적을지는 데몬이 정한다. 화면이 이벤트 페이로드를 파서 문장을
지으면 그 문장은 화면 수만큼 생긴다 — IDE 클라이언트가 셋이 되면 세 벌이 된다.

0-3. **모름과 없음을 갈라 그린다.** "안 왔다"와 "없다"와 "이 빌드에 문이 없다"는 셋 다 다른
사실이다. 빈 자리로 셋을 뭉치면 화면이 모르는 것을 아는 척한다.

0-4. **보고와 수준은 다른 자리에 쓴다.** "안 갔다: 사유"는 한 번 일어난 사건이고 "붙어 있다"는
지금 계속 참인 상태다. 한 자리에 쓰면 뒤엣것이 앞엣것을 지운다 — 이겨도 앞엣것이 거짓이 되지는
않고, 사유만 사라진다. 이 플러그인은 이것을 타입으로 박았다(`Level` — 사건은 라벨에 들어올
이름이 없다). 다른 클라이언트도 셈(자리 수 시험)이 아니라 타입으로 박기를 권한다.

0-5. **IDE 에 이미 있는 것은 만들지 않는다.** 상태는 상태 표시줄에, 지금 무엇인지는 그 창의
제목이 서는 자리에, 흘러가는 글은 스크롤이 원래 사는 독에, 붙박이 사실은 옆에 서는 독에.
가운데는 고치는 파일의 자리다 — 어느 IDE 에서든.

0-6. **워크스페이스는 신뢰 경계다.** 전사는 로컬 소켓 전용이다. ssh 문(`cmd/magi/door.go` 의 `doorMethods`)에는 어떤 클라이언트도 전사를 올리지 않는다 — 그 문은 남의 키가 지나는 좁은
자리이고, 거기 전사를 실으면 낯선 사람이 남의 대화를 읽는다.

## 1. 지금 있는 것 — 실측 (2026-08-29)

### 1.1 터미널 (TUI) — 이 플러그인이 준하려는 기준

`internal/adapter/tui/model_view.go` 의 `View` 가 한 프레임을 조립한다. 세로로:

| 자리 | 무엇 |
|---|---|
| 머리 2줄 | `✦ magi` · `model <이름>` · 승인 칩 · `◈ plan: <모드>` · `◐ <스텝> d/t` · `⚖ council rN: 이름` · `⛐ N: <에이전트>` · 오른끝 스크롤 미터, 그 아래 실선 |
| 가운데 | 전사 뷰포트 + 서브에이전트 타일 |
| 겹쳐서 | 우측 위 **포스트잇 판** — 레이아웃 폭을 안 뺏고(`panelCols()`=0) 위에 떠 있다 |
| 사이 | 모달 — resume · subagents · cron · route · search · 커맨드 팔레트 · 승인 · 물음 |
| 입력 | 입력 상자 + 컴포저 제안 한 줄(`Tab`) |
| 발치 | 스피너 + `working…` + 턴 미터(경과 · ↑토큰 · ctx% · 쓴/전체) + `esc interrupt`, 놀 때는 키 힌트 |

포스트잇 판(`internal/adapter/tui/panel.go` 의 `statusPanel`)이 그리는 것은 정확히 다섯이다 — **Context** 막대,
**Plan d/t** 와 스텝들, **Background**(도는 판과 끝난 명단, 시작 차례 유지), **Waiting N**
(이 턴이 끝나기를 기다리는 것), **Scheduled**(곧 돌 것과 영영 못 돌 것). 그리고 **그릴 것이
없으면 판째로 숨는다**(`hasPanel`).

전사 행은 이벤트에서 **증분으로** 선다: `applyEvent` → `m.blocks` → `renderBlock` → lipgloss 로
칠한 고정폭 문자열. 그 문자열은 터미널 격자에 붙어 있다 — 클릭 히트테스트가 행의 화면 Y 를
기억하고, 폭이 바뀌면 전부 다시 짠다.

### 1.2 웹 콘솔 — 행이 데이터로 오는 유일한 화면

> ⚠ `cmd/magi-web` 은 없어질 예정이다(새 콘솔은 `web/ui`). 그래서 아래 실측의 값은 코드의
> 위치가 아니라 **어휘**다 — 집은 헐려도 `line` 의 필드 목록과 그 주석이 실측으로 산 규칙들은
> 이 문서가 물려받아(§2.1) 계약으로 남는다.

`cmd/magi-web/main.go` 의 `events` 가 SSE 한 연결에 세 종류를 흘린다: **전사 행 전체 배열**,
`turn` 프레임(`{open, forSec}` — 턴이 열렸나, 몇 초째인가), 명단 프레임. 행은 브라우저가 아니라
**서버가 짓는다** — `renderMessages` 가 세션 로그를 재구성한 `[]session.Message` 를 `[]line`
으로 편다. `line` 은 순수 데이터다:

`who` `text` `tool` `args` `ok` `note` `out` `pending` `round` `decision` `member` `lens`
`confidence` `why` `feedback` `keep` `cite` `at` `diff` `abandoned` `by`

그 구조체의 주석이 규칙을 이미 계약으로 적어 뒀다 — **필드로 보내고, 렌더된 문장에서 도로
파내지 않는다.** "두 화면이 갈라지는 것은 정확히 그 파내기에서 시작한다." 특기할 것 둘:

- `Ok`/`Note` — 툴 호출과 그 결과는 **한 행**이다. 갈라 그리면 "됐나"를 아래 행을 찾아 열어야
  안다. `Note` 는 **되고 나서 읽을 것이 남은** 호출(사후 훅, 린트)이다 — 와이어에선 에러로
  오지만 실패가 아니다.
- `Diff` — 편집 호출은 **그 호출의 인자만으로** diff 를 서버가 지어 보낸다. 거절된 편집은 안
  짓는다(일어나지 않은 변화를 그리게 된다).

### 1.3 이 플러그인 — 지금

세 자리가 서 있다(`plugin/intellij/src/main/resources/META-INF/plugin.xml`):

- `toolWindow id="magi" anchor="bottom"` — 전사·문제 두 판, 입력, 보내기·세우기 단추,
  컴포저 제안(`Tab`).
- ~~`toolWindow id="magi.facts"`~~ — 있었다가 접혔다(§4.2): 사실·플릿은 설정 화면 안으로.
- `statusBarWidgetFactory id="magi.status"` — 3초 폴, `magi: 도는 중 · <승인모드>` 꼴.

전사는 데몬의 `transcript` 문에서 **날 이벤트**로 온다 — 웹처럼 모양 잡힌 행이 아니다. 규칙
층(`Wire.kt` 의 `LogEvent`)은 페이로드(`data`)를 일부러 안 읽고("타입마다 모양이 다르다. 이
층은 안 읽는다"), 읽기로 되어 있던 화면 쪽 독자가 **안 쓰였다**: `MagiToolWindow.entry` 는
`#seq type (actor)` 만 적는다. **사람이 친 글도 컴패니언의 답도 화면에 없다.** 살아 있는
샌드박스에서 실측했다 — 「하이」를 보내면 `#13 prompt.submitted (user)` 가 서고, 답은
`part.appended (agent)` 로 **도착하는데** 몸통이 영영 안 보인다.

경로가 없어서가 아니다. 같은 트리의 `Problems.of` 는 `data.part.toolResult` 를 파고 들어가
`content` 를 문자열로 꺼내 파일:줄을 짚는다. 문은 뚫려 있고 전사만 안 쓴다.

## 2. 판정 — 행을 짓는 규칙이 어디 사는가

세 화면의 입력부터 다르다:

| | 입력 | 짓는 자리 | 결과물 |
|---|---|---|---|
| TUI | `event.Event` (증분) | `applyEvent`→`blocks`→`renderBlock` | 칠해진 고정폭 문자열 |
| 웹 | `[]session.Message` (전량 재구성) | `cmd/magi-web/main.go` `renderMessages` — 집째 헐릴 예정 | `[]line` — **데이터** |
| IDE | `LogEvent` (증분) | 없음 | `#seq type (actor)` |

이 문서의 첫 판은 「웹의 셰이퍼를 코어로 옮기고 데몬에 행 문을 하나 낸다」였다. `cmd/magi-web`
이 없어질 예정이라는 사실이 서면서 **행 짓기는 클라이언트가 각자 구현한다**로 정해졌다
(2026-08-29). 데몬이 책임지는 것은 날 이벤트 문(`transcript`)까지고, 그 위는 화면의 일이다.

그 판에서도 변하지 않는 것 둘:

1. **TUI 의 결과물은 못 가져온다.** 문자열이 아니라 터미널 격자에 붙은 문자열이다 — lipgloss
   폭 계산·ANSI 절단·행 Y 클릭 히트테스트가 한 덩어리라 Swing/DOM/WPF 판에 옮길 수 있는 것이
   아니다.
2. **웹 `line` 의 어휘는 그대로 계약이다.** "필드로 보내고, 렌더된 문장에서 도로 파내지
   마라"는 구현이 어디 살든 참이고, 그 필드 목록(§1.2)이 세 화면이 같은 대화를 같게 읽는
   기준이다.

§0-1(규칙은 한 벌)과는 이렇게 산다: **코드는 여러 벌이어도 계약은 한 벌이다.** 계약은 이
문서의 어휘 표와 규칙 목록(§2.1)이고, 각 클라이언트는 자기 셰이퍼를 자기 골든으로 붙든다(§6).
규칙이 여러 벌인 것을 알고 두는 것과 모르고 두는 것은 다르다 — 이 절이 그 "알고"다.

### 2.1 행은 이 클라이언트가 짓는다

> 구현 수준은 [전사 셰이퍼](./TRANSCRIPT.ko.md) — 행 모델, 이벤트→행 매핑, 골든.

셰이퍼는 `plugin/core` 의 usecase 층에 산다. `Transcript.kt` 가 이미 그 자리의 절반이다 —
무엇이 행이 되는가를 이미 안다(`echoesFact` 가 델타를 거른다: 같은 말이 `part.appended` 팩트로
다시 오고, 리플레이되는 것은 팩트뿐이다). 페이로드를 파는 것도 그 층의 일이다 — `Problems.of`
가 이미 `data.part.toolResult` 를 판다. `Wire.kt` 의 "이 층은 안 읽는다"는 전송·규칙 경계에
하는 말이지 usecase 가 못 읽는다는 말이 아니다.

입력 = `LogEvent` 증분 스트림. 출력 = 웹 `line` 어휘를 옮긴 행 모델. 그리고 웹이 실측으로 산
규칙들은 구현이 달라도 그대로 산다:

- **툴 호출과 그 결과는 한 행이다.** call id 로 짝을 맞춘다 — 병렬 호출은 순서 밖으로
  완료된다. 갈라 그리면 "됐나"를 아래 행을 찾아 열어야 안다.
- **note ≠ 실패.** 되고 나서 읽을 것이 남은 호출(사후 훅, 린트)은 와이어에선 에러로 오지만
  실패로 그리면 화면이 거짓말한다.
- **diff 는 착지한 편집만.** 거절된 편집의 인자는 일어나지 않은 변화를 그린다.
- **턴 경과는 세션 수준 사실이다.** 마지막 행에 걸면 그 행이 무엇이냐에 따라 뜻이 달라진다.
  초 단위로 세고 IDE 시계로 이어 센다 — 타임스탬프 비교는 두 기계의 시계가 갈릴 때 틀린다.
- **전사는 append-only 가 아니다.** 재부상한 인터젝션이 앞의 프롬프트를 지우고, 컴팩션이
  로그를 통째로 다시 쓴다. 증분으로 짓되, 지우는 사건이 오면 **통짜로 다시 짓는 것**을
  두려워하지 않는다 — 웹은 아예 매번 통짜로 지었고 4천 이벤트 세션에서 12ms 였다.

로그 파일을 재유도하지 않는다 — 문은 스트림이다(door, not subcommand). 스트림이 안 싣는 것은
§8 에 적고, 데몬에 요청하는 것은 그때 그 항목으로 한다.

### 2.2 다른 두 화면도 각자 짓는다

TUI 는 격자 제약이 진짜라 접을 수 없고, 새 콘솔(`web/ui`)도 자기 것을 갖는다. 붙드는 것은
공유 코드가 아니라 **문서화된 계약 + 클라이언트마다의 골든**이다(§6-2·§6-3).

## 3. 결정 — 이 플러그인의 자리 배치 원칙

TUI 는 한 격자에 넷을 다 쌓는다 — 터미널엔 자리가 하나뿐이라서다. IDE 에는 그 넷이 각자 갈
자리가 이미 있다. **옮기는 것이지 새로 만드는 것이 아니다.** 배치는 한 문장이다:

> **하단 독은 전사와 입력만. TUI 의 머리와 발치는 상태 표시줄과 툴윈도 제목표시줄로. TUI 의
> 우측 포스트잇은 우측 독으로.**

| TUI 자리 | 무엇 | JetBrains 자리 |
|---|---|---|
| 머리 — `model <이름>`, 승인 칩 | 무엇으로 도는가 | **하단 툴윈도 제목표시줄** (`ToolWindow.setTitle` — "magi — gpt-oss:120b · auto" 꼴) |
| 머리 — `◐ 스텝 d/t`, `⚖ council`, `⛐ N` | 지금 무엇을 하는가 | **상태 표시줄** — 폭이 없어 「무엇을」은 안 적고, 「무엇을」은 설정 화면의 「지금」 장이 그린다 |
| 뷰포트 | 전사 | **하단 툴윈도 가운데** (§4.1) |
| 발치 — 턴 미터(경과·토큰·ctx%) | 이 턴이 얼마나 갔나 | **상태 표시줄** — 열렸는지·몇 초째인지는 셰이퍼(§2.1)가 이벤트에서 세고, IDE 시계로 이어 센다 |
| 발치 — `esc interrupt` | 세우는 손 | 이미 있다 — 「세우기」 단추 |
| 발치 — 키 힌트 | 배우는 자리 | 안 옮긴다 — IDE 는 단추가 보이는 화면이라 힌트 줄이 하는 일이 없다 |
| 우측 포스트잇 다섯 장 | 붙박이 사실 | **설정 화면의 정보 장** (§4.2 — 처음엔 우측 독이었다가 사용자 결정으로 접혔다) |
| 모달 — 승인·물음 | 답하는 손 | 이미 있다 — 하단 독의 프롬프트+단추 |
| 모달 — resume·route·cron·subagents | 설정과 행동 | **설정 화면과 제목표시줄 액션** (§5) |
| 커맨드 팔레트 | 한 타로 아무 데나 | IDE 의 것을 쓴다 — 액션을 등록하면 Search Everywhere 가 공짜로 줍는다. 자체 팔레트는 §0-5 위반 |
| 입력 + 컴포저 제안 | 손 | 이미 있다 |

### 3.1 왜 하단 머리의 `state` 라벨이 없어지나

지금 하단 독 머리에는 `Level` 라벨이 서 있다 — 「컴패니언이 붙어 있다」가 거의 항상이다.
**거의 안 변하는 큰 한 줄이 전사 위 판 하나를 차지하고 있다** (사용자 실측 그대로: "왜 이렇게
커? 변하는 데이터도 없네"). 수준은 §0-5 대로 상태 표시줄(이미 그린다)과 제목표시줄로 가고,
하단 독에서 그 판을 거둔다. `Level.Waiting` 만은 할 일이 있는 수준이라 눈에 띄어야 하는데,
그것은 이미 프롬프트+단추가 서는 것으로 보인다 — 라벨이 겹말이었다.

`Level` 타입과 「라벨에 글자를 넣는 문은 하나」 규칙은 그대로 산다. 문이 서는 자리만 바뀐다.

## 4. 화면별 결정

### 4.1 하단 독 — 전사

셰이퍼(§2.1)가 지은 행을 그린다. 어휘는 웹 콘솔의 `line` 과 같다 — 같은 계약의 다른 붓이다:

- **누가.** `who` 별로 갈라 그린다: 사람의 행은 그대로, 컴패니언의 답은 본문색, `thinking` 은
  접힌 채 흐리게, `tool` 은 이름+요약 한 줄에 `args`/`out` 은 접어서. 카운슬 행은 `member` 의
  자리 색(`Look.seat` — melchior·balthasar·casper 셋 말고는 아무도 색을 못 받는다).
- **툴 호출은 한 행.** `ok` 가 오면 그 행에 ✓/✗ 를 얹는다. `note` 는 실패가 아니라 "됐고 읽을
  것이 있음"으로 — 지금 문제 판이 이미 이 구분을 그린다.
- **`pending` 행과 턴 경과.** 답 없는 프롬프트에 왼쪽 막대(`Look.pending()` — 콘솔의
  `.row.pending .txt` 를 옮긴 것), 턴이 열려 있으면 발치에 경과 초.
- **`diff` 는 IDE 답게.** 서버가 지은 diff 문자열을 그대로 접이식으로 그리되, 행이 파일을
  짚으면 클릭이 그 파일을 연다 — 문제 판이 이미 하는 그 일이다.
- **전사는 덧붙이기만.** 창이 하는 말(`— 전사에 붙었다.` 류)은 지금처럼 `—` 앞머리로 전사에
  실린다 — 보고는 전사로, 수준은 라벨로(§0-4)의 그 절반이다.
- **Enter 는 보낸다.** 지금은 「보내기」 단추만 `say()` 를 부르고 Enter 는 줄바꿈이다. Enter=
  보내기, Shift+Enter=줄바꿈으로 — 웹도 터미널도 그렇다.

전사·문제 두 판 구조는 유지한다. 왼쪽은 데몬이 보낸 것 전부, 오른쪽은 그중 사람이 손대야
하는 것만 — 출처가 다른 두 글이다.

### 4.2 사실과 플릿 — 설정 화면의 정보 장 (옛 우측 독)

처음 판은 우측 독(`magi.facts`)이었다. **사용자 결정(2026-08-29)으로 접었다**: 그 판이 거의
항상 하는 말이 「붙어 있다」였고, 하루 한 번 볼 사실이 독 한 칸의 집세를 내고 있었다. 상시로
알아야 하는 **수준**은 상태 표시줄이 이미 하고, 자세히 보는 사실은 **열 때 읽으면 된다** —
설정 화면은 열림이 곧 `reset()` 이라 「펴는 순간 다시 묻기」가 구조로 공짜다.

지금 설정 화면(Settings › Tools › magi)의 장 셋:

- **지금** — 하는 일·승인·대화 id, 그리고 못 만지는 컨텐트 루트 경고(데몬 없이도 선다).
- **설정** — §5 의 표 그대로.
- **플릿** — `roster` 문의 행들: 사람 기다리는 행은 강조, 목격담은 나이와 함께 흐림, 문 없는
  데몬엔 그 사실을 말로.

TUI 포스트잇의 나머지(계획·건넨 일·받은 지시)는 데몬 읽기 문이 생기면 이 장들 옆에 선다 —
「없으면 숨긴다」와 「못 읽었다」를 가르는 규칙(§0-3)째로.

### 4.3 상태 표시줄

지금 꼴(`magi: 도는 중 · auto · 못 만지는 루트 N`)에 둘을 더한다: 턴이 열려 있으면 경과
(`턴 3m12s`), 카운슬이 열려 있으면 `⚖ rN`. 폭이 없는 자리라는 원칙은 그대로 — 「무엇을」은 안
적는다.

## 5. 설정 — 슬래시 커맨드를 IDE 설정 화면으로

지금 이 플러그인에는 설정 화면이 없다 — `plugin.xml` 에 `projectConfigurable` 이 없다. 모델·
승인·크론·자동완성을 바꾸려면 터미널을 따로 열거나 `config.toml` 을 손으로 고쳐야 한다.

터미널의 단일 원천은 `internal/adapter/tui/model.go` 의 `slashCommands` 다. **설정**(남는
상태)과 **행동**(한 번 하고 끝)과 **읽기**를 가른다 — 설정 화면은 남는 상태의 자리다. 한 번
하고 마는 것을 거기 두면 사람이 「적용」을 눌러야 도는 것으로 읽는다.

| 갈래 | 슬래시 | 이 플러그인의 자리 | 데몬 문 |
|---|---|---|---|
| 설정 | `/route` (`/model`) | Settings › Tools › magi › 모델·라우팅 | `models` · `set-model` · `use-backend` |
| 설정 | `/permission` | 같은 화면 › 승인 모드 | `set-permission` |
| 설정 | `/cron` | 같은 화면 › 예약 | `jobs` · `reload-cron` |
| 설정 | (자동완성) | 같은 화면 › 거들기 — `[autocomplete]` 프로필과 이 IDE 의 켬끔 | `complete` · `suggest` |
| 설정 | `/providers` | 같은 화면, **읽기 전용** | 쓰기 문이 **없다** |
| 설정 | `/subagents` | 같은 화면, **읽기 전용** | 쓰기 문이 **없다** |
| 설정 | `/context <n>` | 같은 화면, **읽기 전용** | 쓰기 문이 **없다** |
| 행동 | `/compact` `/clear` `/rewind` `/resume` | 하단 툴윈도 **제목표시줄 액션**(기어 메뉴) | `compact` · `rewind` · `resume` |
| 행동 | `/fork` `/replay` `/init` `/ultra` | 안 만든다 — 감독 화면이 아니라 운전 화면의 동사다. 필요해지면 그때 |
| 읽기 | `/cost` `/loop` `/tools` `/sessions` | 설정 화면 정보 장 또는 제목표시줄 메뉴 | `status` · `tools` · `about` |
| 읽기 | `/diff` | 안 만든다 — IDE 의 Git 창이 그 자리다(§0-5) | |

**「없다」는 그대로 그린다.** 쓰기 문이 없는 항목을 편집 가능하게 그리면 사람이 바꾸고 안
바뀐다. 문이 생기기 전까지 값만 보이고 왜 못 바꾸는지 한 줄 적는다(§0-3).

### 5.1 설정은 어디 저장되나

이 화면이 고치는 것은 IDE 설정이 아니라 **워크스페이스 컴패니언의 설정**이다.
`PersistentStateComponent` 에 한 벌 더 두지 않는다 — 두면 IDE 가 아는 값과 데몬이 아는 값이
갈라지고, 갈라지면 화면이 거짓말한다. **화면은 데몬에 묻고 데몬에 쓴다.** 열 때 읽고, 적용이
쓰고, 다시 읽어 확인한다.

예외는 IDE 만 아는 것뿐이다 — 인라인 완성을 이 IDE 에서 끌 것인가 같은. 그것만 IDE 설정이다.

## 6. 무엇으로 붙드나

6-1. **전사가 몸통을 그린다.** 행 배열을 넣으면 사람이 친 글과 컴패니언의 답이 판에 있어야
한다. 지금 화면은 `#seq type` 만 적어도 초록이다 — 그 시험이 없다. 이것부터 건다.

6-2. **셰이퍼는 골든으로 붙든다.** 이벤트 JSONL 을 넣으면 행 모델이 나오는 순수 함수로 두고
(usecase 층 — SDK 없이 돈다), 몸통·짝맞춤·pending 이 기대와 갈리면 우는 골든을 건다. 칠은 안
잰다 — 갈라도 되는 것과 갈리면 안 되는 것을 구분해서.

6-3. **어휘가 갈리면 문서가 같이 움직인다.** 행 모델의 필드는 §2.1 의 어휘(=웹 `line` 의 필드
목록)와 이름이 맞아야 하고, 새 필드가 필요하면 이 문서에 먼저 적는다. 절반은 기계가 본다 —
citecheck 가 이 문서의 심볼 손가락을 원본에 맞춰 보므로, 원본이 이름을 바꾸면 여기가 운다.

6-4. **자리 계약.** 라벨 문이 `Level` 만 받는 규칙(`SourceTextTest`)을 새 자리에도 편다 —
제목표시줄·상태 표시줄은 수준만, 전사는 사건만.

6-5. **없으면 숨는다 ≠ 못 읽었다.** 정보 장(플릿 등) 각각에서 둘을 갈라 시험한다.

6-6. **설정 왕복.** 설정 화면의 각 항목은 데몬에서 읽은 값을 보이고, 적용 후 다시 읽은 값이
화면과 같다. 쓰기 문 없는 항목은 편집 불가가 **타입/UI 로** 박혀 있다.
